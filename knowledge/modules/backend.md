# 后端模块职责

归属：[模块设计](../modularization-design.md)。本文件只定义后端 owner；数据与事务约束见[设计契约](../design-contracts.md)。具体路径、公开入口以[模块登记](../module-boundaries.json)为准。

## 分层

| 区域 | 职责 | 边界 |
| --- | --- | --- |
| 启动与组合入口 | 构造依赖、注册路由/调度、启动和关闭 | 不承载领域计算、数据修复或测试控制逻辑 |
| 应用工作流 | 经公开接口编排跨领域命令和事务 | 不复制领域校验；与启动装配分文件维护 |
| `src/config/` | 运行配置解析、校验与快照 | 应用代码不散落读取 `process.env`；独立 CLI 参数另属入口 |
| `src/http/` | 请求解析、身份绑定、Cookie、SSE、响应与错误映射 | 不直接改业务存储，不维护第二套业务流程 |
| `src/modules/` | 稳定业务能力、领域规则与实体 | 通过注入接口访问仓储和供应商 |
| `src/infrastructure/` | 外部协议、SDK、传输与存储适配 | 不决定业务场景、用户事实或业务重试策略 |

## 领域所有权

| 模块 | 拥有的主要能力 |
| --- | --- |
| `auth` | 注册、登录、会话、密码、账户身份 |
| `checkins` | 此刻状态、自定义量表与发生时间 |
| `health` | 睡眠、心率、体重、运动记录 |
| `captures` | 捕念、标签与展开关系 |
| `journals` | 日记、草稿、写作辅助与回望 |
| `thoughts` | 问题、内容块、追问、用户留痕与批注锚定 |
| `annotations` | 跨内容类型的批注、回复、可见文本锚点和漂流；资源解析由应用编排 |
| `library` | 书目、阅读日期和读书笔记 |
| `keepsakes` | 小物元数据、原图、轮廓图和分割流程 |
| `quotes` | 善言、标签与回顾抽样 |
| `reviews` | 趋势、实验、指标和认知复盘 |
| `ai` | 场景配置、模型调用、用量、费用和 AI 审计 |
| `tasks` | 持久后台任务、重试、过期和恢复 |
| `notifications` | 通知状态、未读数和目标定位 |
| `trash` | 软删除、恢复、永久清理计划 |
| `onboarding` | 问卷、资料、初始理解和版本 |
| `commercialization` | 商业参数、模型和核算 |
| `admin-snapshot` | 中台所需的只读脱敏聚合 |

表中是职责划分，不代表这些能力已全部按目标重构。新增文件按实际复杂度拆分 schema、service、repository 等，不创建空层或强制目录套件。

## 共享能力

| 能力 | 责任 |
| --- | --- |
| persistence | 仓储、事务、关系映射与迁移/恢复适配；普通在线访问遵循精准实体契约 |
| attachments | 账户内附件引用、配额、清单、存储适配及清理 |
| observability | 请求上下文、系统/操作日志和安全投影；AI 审计结构归 AI 领域 |
| security / validation / errors | 安全原语、无业务含义的校验与稳定错误类型 |
| time | 自然日、时间戳与发生时间解析；业务迁移规则不进入通用时间库 |
| content | Markdown 可见纯文本等共享解析，不代管领域内容 |
| prompts | 不可变模板快照与严格渲染；模板版本、参数与审计见[Prompt 架构](../prompt-architecture.md) |

共享能力应有真实复用方且不携带某调用方的私有业务规则；避免万能 `utils` 或以共享命名掩盖领域耦合。

## 跨领域资源流程

- 回收站拥有回收条目、期限与清理计划；应用工作流协调被删实体、批注及回收记录。恢复推进必要版本，保留原文、ID、发生时间和附件关系；迟到任务必须核对目标版本。
- 附件清理先持久登记，再删实物，再提交结果。第一步失败不得删除；结果提交失败保留可幂等恢复的清理任务。清理同时考虑现存实体和回收记录的有效引用。
- 持久上传先预留清单，再写实物并核验。失败先登记清理；权限、哈希或存储异常不能被误记为实物不存在。临时文件与持久附件有不同回收边界。
- 任务模块拥有领取、幂等、重试后继、终态及重启恢复；通知拥有通知状态及目标定位。目标业务结果、任务终态与必要通知按业务事务原子提交，模型请求不占用该事务。
- AI 领域拥有场景参数、额度、用量与逐次调用审计；供应商适配只执行协议并返回标准结果/错误，不私自重试、落业务数据或修改费用。成本未知不能补成已知零费用。
- 个人上下文由应用工作流通过各领域公开查询装配；用户原文与模型派生分别标记，供应商不接收全量 store。冷启动规则见[冷启动策略](../onboarding-strategy.md)。
- 日志与业务提交不等同于同一事务；日志失败不应让成功模型回答再次调用。具体记录、隐私例外与失败边界见[日志审计](../observability.md)。
