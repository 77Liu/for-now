# PostgreSQL 隔离验证入口

返回[系统测试地图](../system-testing.md)。是否需要数据库专项及发布前快照门，只由[测试影响矩阵](../test-impact-matrix.md)决定。

## 工具与命令

- `npm run test:postgres:preflight`：在业务断言前检查实际工具路径和主版本。
- `npm run test:postgres:stable`：使用预检选定的工具链运行真实数据库专项。
- `npm run test:postgres`：数据库专项入口；具体场景以当前 package.json 及脚本为准。
- 已有工具可用 `PG_TEST_BIN` 显式指定；候选、Node、数据库二进制、schema 与必要配置都计入环境身份。

不能把“工具存在”“端口能监听”或映射单测通过写成数据库专项通过。预检失败先处理环境；实际消费者失败返回实现，不能通过修改期望、过滤异常数据或跳过数据库启动制造通过。

## 隔离与资源

测试自建临时数据库、随机密码与端口，使用被测运行角色验证权限；不以表 owner / superuser 运行角色替代 RLS 验证。运行目录、数据库、子进程和端口按执行隔离，成功或失败均清理本次资源，不清理其他任务的数据库。

不得意外读取生产连接或向生产写入。发布前快照门使用真实持久化与实际启动入口，禁用外部副作用；模型、通知等真实调用另按已授权的 live 验收执行，不能偷换快照门的无付费性质。

## 环境故障辨别

`listen EPERM`、数据库多线程启动保护、Node 原生模块签名/Team ID 问题分别定位，不混称业务回归失败或通过。历史已尝试路径、源码校验与兼容构建参数见[原始诊断](../history/postgres-test-diagnostics.md)。历史的 macOS 本机测试兼容构建不得进入生产制品；不删除数据库保护校验、不扫描现存实例跳过启动。

只有相关候选、工具和环境仍适用时才复用旧证据；环境变化记录实际结果。未知根因保持未知，不以曾经通过推断本次通过。
