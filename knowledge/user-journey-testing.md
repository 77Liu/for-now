# 基于真实用户行为的交互测试体系

## 目标

测试以“用户完成一件事”为最小闭环，不以按钮或接口数量代替可用性。
每条旅程按以下结构维护：

`用户角色 → 用户目标 → 正常路径 → 预期结果 → 异常中断 → 恢复路径`

覆盖矩阵的单一事实来源是
[`user-journey-matrix.json`](./user-journey-matrix.json)。脚本中的证据锚点失效时，
矩阵校验必须失败，避免文档声称已覆盖但测试已经删除或改名。

## 运行入口

何时运行、选择哪些测试及证据是否有效，仅由[测试影响矩阵](test-impact-matrix.md)决定。`smoke`、`daily`、`release` 是既有命令的覆盖档位，不是定时任务、授权或发布门；实际命令组合见 [runner](../scripts/user-journey-regression.mjs)。

```bash
npm run test:journeys:validate
npm run test:journeys:smoke
npm run test:journeys:daily
npm run test:journeys:release
```

每次运行在 `artifacts/user-journeys/` 写入机器可读摘要。目录不进入 Git；候选发布
时把摘要中的结论、耗时和失败证据引用到阶段报告。

## 五类证据

1. UI 交互：真实点击、输入、上传、滚动、键盘和触摸目标。
2. E2E：界面操作穿过 HTTP、领域逻辑和持久化后得到正确业务结果。
3. 视觉回归：桌面、390px、320px 和 iOS 截图，无溢出、遮挡、缺图或不可读状态。
4. 探索性测试：在正常旅程之外改变顺序、快速切换和中途返回。
5. 异常恢复：断网、超时、重复提交、权限失效、刷新、重启和账户切换。

截图只能证明视觉状态，不能单独证明保存成功。高风险旅程至少检查：

- 界面反馈；
- 业务记录；
- 刷新或重新登录后的持久化；
- 账户/权限边界；
- 重复记录、误删媒体、错误通知等副作用。

## 提交与外部动作

提交适用范围遵循[本地提交规则](commit-and-release-rules.md)，旅程证据不单独授予提交权限。外部动作按[发布自动授权策略](release-authorization-policy.md)核对已有条件持续授权和当前暂停／撤销状态；已覆盖的动作无需重复申请，超出范围才补授权。

## 技术初值

- 浏览器动作默认超时：25 秒。
- 小物陈列：首屏 12 件，距列表底部 160px 时加载下一页。
- 线上只读快照：单次 JSON 或附件请求 15 秒硬超时。
- UI 最小触控目标：44px。

这些是工程初值，可根据真实 P95、误报率和设备证据调整；商业价格、费用预算和
用户权益阈值不在 Agent 自主调整范围内。

## 真实服务 E2E

`npm run test:journeys:live -- <mode>` 使用独立 Chrome Profile 操作真实页面、
HTTP 服务、账户持久化与已配置的第三方服务。账号、密码、邀请码、样例文件和
证据目录只通过 `E2E_*` 环境变量传入，不得写入脚本、日志或 Git。

当前模式覆盖 UI 注册与登录、新用户引导、多账户并发隔离、核心文字记录、
图文和语音捕念、ASR/TTS、内容图片理解、健康 OCR、AI 回答、小物失败恢复
以及多供应商统计。所有写入模式先检查本轮标记或使用固定幂等键，重复执行不应
生成重复业务记录。运行证据写入 `E2E_ARTIFACT_DIR`，目录必须保持忽略状态。

真实供应商调用必须同时满足：

- 使用隔离测试账户；账号本身也从注册 UI 创建。
- 付费验收共用[每版本累计 ¥4 的持续授权](release-authorization-policy.md#上线前付费验收持续授权)，所有付费 API、失败、重试和在途预留合计；不按轮次重置，预计超额先报告申请。
- 执行前后读取账户用量账本；已知估算费用与待账单调用分开报告。
- 主账号附件只允许只读抽样，随后从测试账号 UI 上传；不得修改主账号。
- 生产写入、发布、迁移、push、tag 和 Release 不因 E2E 通过而自动授权。

执行真实环境旅程前还必须建立“用户动作 → 自动副作用”清单。保存、提交、
切换页面等动作若会自动排队 AI、上传媒体、执行 ASR/TTS/OCR/分割或触发其他
计费请求，应按真实供应商调用处理，不能因为测试者没有点击“生成”或“转写”
按钮就视为零调用。只授权无费用冒烟时，测试步骤必须避开这些动作，或使用已
验证不会向外部发请求的隔离配置。

若旅程意外产生外部调用，停止后续写操作，保留调用状态、费用/账单缺口与测试
数据标识；不能删除日志或只清理界面记录来掩盖副作用。
