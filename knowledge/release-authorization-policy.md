# 发布自动授权策略

版本：1.2；生效日期：2026-10-13。本文是自动 push、tag、Release、部署和生产写入的唯一风险分级正文。它只定义“什么条件下可以自动做”，具体动作和回执见 [`SOP/release-and-observation.md`](../SOP/release-and-observation.md)。

## 放权原则

Owner 授权的是可审计策略，不是把全部判断交给 Agent。策略必须绑定规则基线、允许的分支、环境、动作、预算、候选身份、观察指标、自动停止条件和有效期模式（固定到期或持续至撤销）。超出策略时自动停止并返回协调者，不得靠聊天中的“应该可以”继续。

三道边界始终存在，但由机器判定：

1. **候选身份边界**：范围、SHA/tree、依赖、配置和制品固定。
2. **质量安全边界**：代码审查、测试影响矩阵、构建、权限、数据、恢复和可观测性证据齐全。
3. **生产观察边界**：回滚对象已固定，canary、指标、费用和自动停止条件有效。

## 风险等级

| 等级 | 默认范围 | 自动动作 | 必须暂停的条件 |
| --- | --- | --- | --- |
| `L0` | 文档、测试、低风险内部工具、无生产数据变化 | 本地提交、功能分支 push、候选 tag/Release、预览部署；不含生产动作 | 规则文件、权限、依赖、生产配置或数据边界变化 |
| `L1` | 可回滚的普通产品功能，兼容契约不变 | 评审后自动合入、发布、canary、放量和异常回滚 | 共享 schema/API、认证、费用、外部供应商或数据迁移变化 |
| `L2` | 共享契约、持久化、认证、媒体、第三方、预算、生产配置 | 自动构建、候选、预览和证据收集 | 生产写入、迁移、真实 provider、权限模型或 SLO 风险 |
| `L3` | 破坏性迁移、删除、不可逆数据变化、重大权限/费用变化 | 只自动准备和核验，不自动执行生产写入 | 必须取得 Owner 针对本次动作的明确批准 |

`L0/L1` 不是无条件放行。它们仍必须通过候选身份、质量安全和生产观察三道边界。自动回滚只回到已核验的固定对象，不自动恢复业务数据；数据恢复必须按独立恢复证据执行。

## Owner 已确认的默认授权

2026-10-11，Owner 选择以下默认范围；具体候选仍必须在唯一控制面登记，未满足启动闸门时不产生外部生产副作用：

| 等级 | 已确认动作范围 | 关键限制 |
| --- | --- | --- |
| `L0` | 文档、测试和内部工具可本地提交；可推送功能分支、创建候选 tag/Release、执行预览部署 | 不直接推送 `develop`，不执行生产部署或生产写入 |
| `L1` | 普通可回滚功能通过门禁后，可自动合入、发布、canary、放量和异常回滚 | 共享契约、认证、费用、外部供应商和迁移变化不得套用 L1 |
| `L2` | 自动构建、候选、预览和证据收集 | 生产写入和迁移必须针对本次动作另行授权 |
| `L3` | 只自动准备和核验 | 每个生产动作必须取得 Owner 一次性明确批准 |

授权有效期选择为“持续有效，直到 Owner 撤销”。这不取消每次 attempt 的现场核验：每次外部动作仍必须读取当前控制面、检查候选身份、策略版本、环境、预算、暂停开关和停止条件；策略修订、候选变化、规则基线变化或 Owner 暂停都会立即使在途之外的新动作停止。

暂停采用双通道：Owner 的“暂停”指令触发停止，控制面字段保留可审计状态；恢复也必须由 Owner 明确指令触发。

## 上线前付费验收持续授权

生效：2026-10-13。每个版本上线前，所有真实付费 API 验收共用 **人民币 ¥4** 上限，包含模型、语音转写、语音合成及其他付费 API；不是每个供应商、需求或候选各 ¥4。在阈值内按任务需要调用，无需再次申请；预计超出 ¥4 时先报告累计费用、剩余验收及追加额度建议，取得 Owner 授权后继续。

按版本累计已发生费用和在途预留，失败、重试及降级调用一并计费；更换候选、再次验证、跨日或重启不得重置额度。调用前核对已有账本和可用额度，按供应商可用价格作保守预估，调用后保留可核对的用量与费用回执。费用未知时保留未知并占用预估额，不将缺回执当作零费用。不得同时派发可能合计越过余额的调用。当前控制面保存有效授权与费用证据引用，不复制每次调用正文。

该额度用于版本验收，不改变生产日压缩等常规业务的配置、预算和硬限制。上线后立即执行的版本验收调用仍计入该版本共同测试额度。生产测试须满足当前任务的环境授权与本地闭环前置条件；预算授权本身不授权上线或任意生产测试。执行要求不等于跨供应商技术硬拦截，未实现并验证前不得宣称已自动强制。

## 策略最小字段

```text
policyId / policyRevision / ruleBaseline
riskLevel / allowedBranches / allowedEnvironments / allowedActions
requiredReviewers / requiredChecks / impactDomains
migrationClass / budgetLimit / canaryWindow / rolloutLimit
rollbackTarget / haltConditions / ownerPauseSwitch
effectiveFrom / expiryMode / expiresAt / revokedAt
```

策略与候选、attempt、运行对象绑定。修改策略、候选、依赖、配置、测试桩或目标环境会生成新的 attempt；不得沿用旧授权假定继续。

## 质量控制

- 变更作者不能单独完成高风险变更的最终审查。
- 自动系统必须保留候选 SHA/tree、评审身份、测试证据、发布回执、运行 SHA 和回滚回执。
- canary 期间任何关键错误、跨账户读取、持久化失败、费用失控、健康检查失败或回滚失败都触发停止。
- Owner 可以随时暂停策略；暂停停止新的外部副作用，已在途动作先查询实际结果。
- 生产策略不允许通过修改断言、删除失败证据或重复执行把 `FAIL` 变成 `PASS`。

## 启动前条件

自动生产写入在以下条件全部满足前保持关闭：

1. Git 起点、分支职责、工作树和未提交差分完成交接；
2. `develop`、候选、运行版本和远程保护关系可核对；
3. 唯一协调控制面已初始化，且只有协调者可写；
4. 测试影响矩阵已绑定当前候选，发布和回滚脚本通过最小演练；
5. 生产凭据、预算、告警、canary 和 kill switch 已现场核验；
6. Owner 批准本策略的风险等级、动作范围及有效期模式；持续授权使用 expiresAt=null、expiryMode=until_revoked。

在条件未满足时，可以继续本地开发、测试和文档整理，但不得把“策略已批准”写成“自动生产已启用”。


## Partial 的授权边界

Owner 选择 16A：PARTIAL 可进入预览和候选；生产前必须有无 P0/P1 用户损害的依据，并在控制面记录未验收项、责任人与补验条件。未验证不能当作没有损害；需求排期标签不代替实际损害判断。权限、数据隔离、不可恢复数据故障仍按对应风险等级阻断受影响动作。

项目记录的对象标识遵循[完整哈希与展示简称约定](coordination-control-plane.md#项目记录的哈希与集合差量)，Git 与工具协议必需标识不截断。
