# v0.2.0 起：全量模块化重构设计

状态：G2 R4 本地验收通过；生产发布门待人工授权。
范围：后端模块化单体、前端页面/功能/通用能力模块化，以及防止跨模块修改遗漏的检查门禁。
约束：从 v0.2.0 开始渐进实施；逐项排期和状态只在 [`../README-TODO.md`](../README-TODO.md) 维护。

本文是模块边界、依赖方向、跨模块影响矩阵和迁移顺序的单一事实来源。新增、拆分、合并、重命名模块，或改变公开契约时，必须同步维护本文；README 和其他架构文档只保留入口或当前运行事实。

## 1. 目标与非目标

### 目标

1. 将 `server.mjs` 中混合的认证、HTTP、持久化、业务、AI、附件、统计和调度职责拆成可独立理解、测试和替换的模块。
2. 将 `public/app.js` 按页面、跨页面功能和通用能力拆分，使页面只组合功能，不直接承载全局业务规则。
3. 将 `public/styles.css` 拆为设计令牌、基础样式、通用组件和页面样式，并约束选择器作用域。
4. 为每个模块定义唯一公开入口、拥有的数据、依赖和测试，禁止跨模块读取内部实现。
5. 用可执行检查与人工影响矩阵共同防止“只改一个模块，遗漏其他调用方、数据、日志、权限或 UI”的问题。
6. 降低多个智能体并行开发时对 `server.mjs`、`public/app.js`、`public/index.html` 和 `public/styles.css` 的集中冲突。

### 非目标

- 不在本轮同时改用微服务、Kubernetes、Redis、消息队列或独立向量数据库。
- PostgreSQL 全领域映射与正式切换、模块化收口和 `/api/v1` 均为 v0.2.0 的 P0，按独立阶段串行验收；不绑成一次不可验证的大改，不顺带替换 TypeScript、前端框架或构建工具。
- 不借重构改变产品文案、交互、API 响应、数据结构、权限、AI Prompt、费用口径或部署方式。
- 不为了目录整齐创建只有转发作用的空层、万能 `utils` 或循环依赖的“共享”模块。

当前热点：

| 文件 | 当前职责 | 主要风险 |
| --- | --- | --- |
| `server.mjs` | 启动、HTTP、认证、数据、AI、附件、统计、任务和静态资源 | 任何后端 Feature 都可能修改同一文件 |
| `public/frontend/app/runtime.mjs` | 浏览器应用组合、页面 presenter 与 feature 事件绑定 | 剩余页面 presenter 后续按领域继续细分，入口文件不再承载实现 |
| `public/index.html` | 全部页面结构和弹层 | 页面结构变更容易误伤其他入口 |
| `public/frontend/styles/application.css` | 当前全站令牌、布局、组件、页面和响应式样式；根 CSS 仅作稳定入口 | 后续按页面维护时仍需防止选择器覆盖 |
| `scripts/regression.mjs` / `scripts/ui-regression.mjs` | 多领域集中测试 | 模块迁移后容易漏接测试入口 |

重构成功必须同时满足：

- 用户可见行为和生产契约保持不变，除非另有独立 Feature 明确批准。
- 启动入口保持薄：只负责配置、依赖装配、路由注册、生命周期和关闭。
- 每个模块只有一个公开入口；外部代码不深层导入模块内部文件。
- 业务模块不直接依赖浏览器 DOM、Node HTTP 对象、具体 JSON 文件或第三方 SDK。
- 共享模块不包含任何具体 Feature 的业务判断。
- 迁移过程中旧、新实现不得长期双写；每一步都可独立验证和回退代码。
- 完整系统测试、跨模块契约测试和模块边界检查全部通过。

## 3. 后端目标边界

保持 Node.js 模块化单体。一个进程可以装配全部模块，但代码依赖必须受控。

### 3.1 应用层

| 区域 | 职责 | 不负责 |
| --- | --- | --- |
| `src/app/` | 启动、关闭、依赖装配、路由汇总、定时任务注册 | 业务判断和数据修复 |
| `src/config/` | 环境变量解析、默认值、启动校验 | 在运行中读取散落的 `process.env` |
| `src/http/` | 请求解析、响应、Cookie、SSE、静态资源、统一错误映射 | 直接修改业务存储 |

### 3.2 领域模块

领域模块按稳定业务能力划分，而不是按单个接口划分：

| 模块 | 拥有的主要能力 |
| --- | --- |
| `auth` | 注册、登录、会话、密码、账户身份 |
| `checkins` | 此刻状态、自定义量表与发生时间 |
| `health` | 睡眠、心率、体重、运动记录 |
| `captures` | 捕念、标签与展开关系 |
| `journals` | 日记、草稿、写作辅助与回望 |
| `thoughts` | 问题、内容块、追问、用户留痕与批注锚定 |
| `annotations` | 跨内容类型的批注、回复、可见文本锚点和漂流；资源解析由应用编排 |
| `library` | 书目、阅读日期和读书笔记 |
| `keepsakes` | 小物元数据、原图、轮廓图和分割流程 |
| `quotes` | 善言、标签与回顾抽样 |
| `reviews` | 趋势、实验、指标和认知复盘 |
| `ai` | 场景配置、模型调用、用量、费用和 AI 审计 |
| `tasks` | 持久后台任务、重试、过期和恢复 |
| `notifications` | 通知状态、未读数和目标定位 |

每个模块按实际复杂度选择 `routes.mjs`、`service.mjs`、`repository.mjs`、`schema.mjs` 等文件；不强制为了形式创建空文件。模块根 `index.mjs` 是唯一公开入口。

### 3.3 基础设施与共享能力

| 模块 | 职责 |
| --- | --- |
| `shared/persistence` | JSON repository、PostgreSQL 关系映射/重建/整批迁移；运行事务适配继续在此模块实现 |
| `shared/attachments` | 附件引用、配额、存储适配和清理 |
| `shared/observability` | 请求上下文、系统日志、操作审计和追踪 ID |
| `shared/security` | 哈希、常量时间比较、CSRF、输入大小和路径安全 |
| `shared/time` | 本地自然日、UTC 时间戳和发生时间规范化 |
| `shared/validation` | 无业务含义的基础校验原语 |
| `shared/content` | Markdown 可见纯文本；供批注校验和跨领域内容解析使用 |
| `shared/errors` | 稳定错误类型与 HTTP 映射所需元数据 |
| `infrastructure/ai-providers` | 供应商 HTTP/SSE 与图片编码；不决定业务场景、重试或费用 |

禁止建立无边界的 `shared/utils`。一个能力只有被至少两个模块复用，且抽出后不携带任一调用方业务规则，才能进入 `shared/`。

### S3 删除、恢复与附件清理边界

本段由 S3 集成负责人串行实施，命中影响矩阵的删除/恢复、附件、版本/迁移、后台任务和审计行；HTTP 路径、二次确认文案、清单哈希及回收载荷保持兼容。

- `trash` 只拥有回收条目、保留期限、幂等查找、父子清理范围与计划哈希，不接收全量 store，也不直接访问任何业务集合。
- `app/trash` 负责解析删除/恢复位置并在账户 repository 事务中协调业务集合、批注与回收条目；批注附属对象的拆离/回附归 `annotations`。恢复推进根记录版本，原正文、ID、时间和附件引用保留。批注后台任务也绑定根记录版本，防止内容相同的恢复快照重新接受旧回答；旧版未绑定版本的排队任务保守过期，可手动重试。
- `shared/attachments` 负责识别附件引用、清理任务去重与删除尝试；只接收引用集合和存储回调，不了解领域字段。`app` 从可见记录和剩余回收条目生成引用集合，在移除回收条目的同一次提交中登记清理任务，随后删实物并再次提交结果。第一提交失败不得删除，第二提交失败保留已持久的任务供幂等恢复。
- 定时重试的账户上下文和生命周期由 `app` 管理；目录、存储后端和附件清单由启动装配注入。`http/trash` 只处理输入、响应和审计，业务变更通过应用服务。
- 验证覆盖：各类删除/恢复、父记录缺失和重复 ID、批注及漂流回附、恢复后迟到任务拒写、父子清单变化、共享附件保留、两次提交失败、重启清理及账户隔离。JSON 和真实 PostgreSQL 均须通过；全段验收前不记为完成。

### S3 附件上传与存储边界

- `shared/attachments/storage` 只实现 local/mock/OSS 的读写、核验、删除与用量。删除必须同时覆盖云端对象和迁移遗留本地副本，任一实物删除失败都向清理队列传递失败，重复删除安全。
- `shared/attachments/images` 拥有路径归一化、图片格式/大小校验和尺寸读取；`uploads` 拥有账户配额串行化、上传批次和临时文件生命周期。账户路径、配额、数据库清单锁/预留/确认/恢复及持久失败清理均为注入接口，不读取业务 store、HTTP 对象或 PostgreSQL 实现。
- 持久上传先预留清单，再写实物并核对哈希。失败先登记清理，不能在清理提交失败后把持久本地附件当临时文件直接删除；未持久临时文件在成功消费或失败后回收。启动核验只将确定不存在的实物记为缺失，权限、哈希或存储故障必须保留清单并报错。
- `http/attachments` 保持 `/api/images/upload`、`/attachments/:name` 的响应、大小限制、HEAD、私有缓存与路径校验；认证仍先于处理器执行。图片识别场景和模型解析规则不属于附件模块。
- 所有迁移/导出/OSS 冒烟脚本只能引用共享模块公开入口；部署语法检查遍历 `src` 和 `public/frontend`，部署回归复制相同目录并核对检查入口。专项覆盖两账户配额竞态、批量部分失败、清单提交故障、本地旧副本清理及重试；真实 PG 锁与恢复仍由数据库专项验收。

### S3 配置与日志边界

- `config` 是应用环境变量的唯一读取入口，提供启动时配置快照；保留现有默认值、上下限、旧美元额度换算及本地测试/数据库/OSS 互斥检查。附件迁移、导出和冒烟脚本显式读取附件配置后注入存储适配器，共享模块不自行读取环境。
- `shared/observability` 拥有异步上下文、脱敏、错误元数据、私有 NDJSON 队列、保留期和提交后变更摘要；只接收目录、版本及提交前后数据，不认识 HTTP 对象、AI 场景或 repository。上下文在并发账户和后台任务间隔离；日志写失败不撤销已提交业务，也不触发模型重试。
- `http/request` 拥有追踪 ID 校验、base path 归一化、安全响应头、异常映射和请求完成审计；数据库错误判断通过装配注入。系统日志只包含摘要，SSE 应用失败与 HTTP 状态分别保存，不记录查询参数或正文。
- AI 的消息裁剪、图片摘要、调用开始/终态和费用归 AI 领域；共享日志只负责写入与脱敏。本段不将 AI 规则迁入共享目录，也不把通用日志拆分描述为完整 AI 链路收口。
- 验证覆盖配置兼容、测试模式隔离、并发账户与后台上下文、有效/无效追踪 ID、base path、SSE/断连结果、日志权限/脱敏和写入失败后的业务保存；部署与系统测试同步迁移公开入口。

### S3 AI 设置、用量与审计边界

- `ai` 拥有模型档位、场景与风格设置、旧版本归一化、公开设置脱敏、供应商用量归一化与价格快照、账户调用额度、调用开始/终态及审计内容裁剪。设置、用量和成本模拟互不覆盖，未知 usage 不估算费用。
- 账户文档读写、JSON 串行队列与迁移备份归 `shared/persistence`；目录、运行后端、提交后审计与归一化策略由启动装配注入。领域不读文件、不接收 HTTP 对象。JSON 与 PostgreSQL 均在提交成功后记变更摘要，失败保留旧数据。
- 设置 HTTP 适配统一在 `http/ai-settings`，保留原 GET/POST、测试档位、密钥保留/清除和公开投影；测试连接仍走同一调用、额度与审计链路。JSON 设置更新在队列内读取最新值，避免并发局部修改互相覆盖。
- 私有审计写入与脱敏复用 `shared/observability`，AI 领域负责记录结构和失败处理。用量和审计可独立失败，不能触发模型重试或改变已经成功的回答；并发账户、后台任务仍继承各自上下文。
- 设置、账本和审计验证覆盖旧配置、设置并发、费用快照、未知用量、配额预留释放、敏感内容裁剪及写入失败。成本/通用 Prompt/供应商边界见下文；业务上下文仍属 `server.mjs` 显式例外。

### S3 AI 成本与供应商边界

- `ai` 拥有成本方案归一化、账本统计、场景输出契约、模型参数、空正文关闭思考的一次重试、额度预留及逐次审计。成本方案仍是独立账户文档，PATCH 保留整份替换语义；不修改真实设置或账本。
- `infrastructure/ai-providers` 负责 DeepSeek HTTP/SSE 传输、响应契约校验与本地图片编码；只返回结果或带私有诊断字段的错误，不决定重试、费用、记录保存或用户场景。端点与传输由装配注入，领域只调用供应商接口，不导入适配器。
- 通用 SP、场景输出约束与风格组合在 `ai`；跨领域个人语境和各业务任务的 Prompt 随所属领域继续迁移，不把全量 store 交给供应商。保持原提示词、参数、图片模型选择及响应结构。
- 本地日期和跨日计算归 `shared/time`，数字边界原语归 `shared/validation`；账本配额的既有 UTC 日口径保持不变。统计继续使用每次请求固化的价格，未知用量不补估。
- 验证须覆盖 JSON/SSE 一致性、拆包/断流/截断/过滤、空正文重试边界、重试额度耗尽、并发账户与图片审计、成本独立持久化和自然日边界；无真实供应商调用。

### P00 提示词目录边界

- `prompts/` 是模型可见稳定文本和模板的单一事实来源，版本文件不可原地修改；manifest 选择默认版本并登记 SHA-256、必需 ID 和占位符契约。`PROMPT_CATALOG_VERSION` 可在不改变应用版本的情况下固定已随发布包交付的历史目录。
- `infrastructure/prompt-catalog` 只负责读取、解析和验证文件；`shared/prompts` 只保存启动时安装的不可变快照并执行严格占位符渲染。领域模块不得读取文件，启动入口必须在构造任何 AI 流程前安装目录。
- AI 审计记录目录版本和摘要，并继续保存实际 SP/UP。版本缺失、哈希不符、必需提示缺失、占位符残缺或声明漂移均阻止启动；不得静默回退到代码内默认文案。
- 部署候选包含完整 `prompts/`，并在切换前运行提示词目录专项。业务代码只保留数据筛选、结构化投影和结果归一化，不保存系统提示、场景约束或业务任务正文。

### S3 小物分割边界

- `infrastructure/ai-providers` 接管阿里云凭据/SDK、同步结果与异步轮询、PNG 下载校验和供应商错误投影；SDK 保持 `autoretry: false / maxAttempts: 1`，不调用其他分割接口。测试替身、传输、时钟与逐次审计接口可注入，真实冒烟复用公开入口。
- `keepsakes` 拥有单图分割流程，通过注入的附件接口创建并清理临时文件，不读文件、不导入 SDK。限流覆盖准备图片至清理结束的整个请求；HTTP 只接收输入、附加异步绑定和映射既有状态码，保存边界见下文。
- 图片字节/格式/尺寸/哈希读取归 `shared/attachments`，DeepSeek 编码与阿里云审计共同复用；无业务含义的 QPS/在途队列归 `shared/concurrency`，AI 和分割仍使用两个独立实例，默认分别为 20/20、5/5。
- 提交、每次轮询与下载共用调用组、各有调用 ID，审计继续由 `ai` 负责；非 Token API 不进入 DeepSeek 账本。上传失败、供应商失败、下载超时/非 PNG/超限、审计写失败、账户并发和临时文件清理均需本地模拟验证。

### S3 小物保存与发生时间边界

- `keepsakes` 接管小物载荷校验、旧记录归一化和创建/编辑；仓储接口只提供小物集合，不把全量 store 交给领域。跨领域删除仍通过应用层回收事务完成，HTTP 保持既有响应与状态码。
- `shared/time` 提供严格日期校验、本地日期与时分合成、发生时间输入解析；版本相关的历史日期修正仍留在 store 迁移处，不把业务迁移规则放入共享层。创建审计时间和发生时间继续独立。
- 这一段保留既有局部更新语义：未传原图、轮廓、标签则保留，标题仍必填；未传备注/外扩仍按旧接口清空/归零。严格日期与旧发生日期兼容解析不借迁移改变，v1 另行明确契约。
- 验证覆盖旧记录/未知字段、无效图片引用标记、部分编辑、发生时间/时区/跨日、事务提交失败、账户隔离、删除恢复/永久清理，以及 JSON 和真实 PostgreSQL 路由运行；PG 启动故障期间不得将接口桩计为数据库验收。

### S3 冷启动资料与个人上下文边界

- `onboarding` 拥有问卷、资料归一化、必答校验、初始理解与个人资料投影；只接收自己的单例文档，持久保存通过注入的文档更新接口完成。三个 HTTP 接口保持旧响应与 PATCH 整份替换语义，历史账户豁免仍归 store 版本迁移。
- `thoughts` 拥有用户原文投影、完整追问链、回答/草稿/引子任务文本；`journals` 拥有写作辅助与回望提示、输出标记；`annotations` 拥有神鸡提示与局部问答拼接；健康记录摘要归 `health`。领域只接收自己的记录或已准备好的文字材料。
- `app` 负责跨领域个人语境、日记当天/前一天材料、思绪引子时间筛选和通用 UP 组合；全量 store 不进入领域、共享层或供应商。前台和后台思绪回答共用任务提示，保持文本、顺序、条数和长度上限。
- 用户原文与初始推断分别呈现，AI 回答不能进入用户观点投影；完整当前链保留全部追问及回答，模型思考永不进入提示词。验证覆盖差分等价、空账户、详细/快速问卷、原文/推断隔离、长链、日期截断、失败提交与跨账户保存；真实 PG 另行补齐。

## 4. 前端目标边界

先采用浏览器原生 ES Modules，是否引入 Vite、TypeScript 或框架由独立 ADR 决定。模块化不以重写 UI 为前提。

### 4.1 页面模块

| 页面模块 | 组合范围 |
| --- | --- |
| `pages/today` | 此刻、共参、每日 |
| `pages/seen` | 念起、书间、拾句、小物 |
| `pages/thinking` | 思绪、日记、回顾 |
| `pages/me` | 账户、统计、通知、回收站、AI 成本、架构、设置、商业化和关于 |

页面模块负责挂载、卸载、页面级路由和组合，不拥有可跨页面复用的业务规则。

### 4.2 功能模块

`features/` 承载可在一个或多个页面使用的完整交互，例如：

- `thought-timeline`
- `annotations`
- `background-ai`
- `notifications`
- `trash`
- `image-input`
- `onboarding`
- `commercialization`

每个功能模块公开 `mount`、`unmount`、必要命令和事件；不得让其他模块操作其私有 DOM、计时器或局部状态。

### 4.3 通用模块

| 区域 | 职责 |
| --- | --- |
| `frontend/app` | 启动、会话切换、一级导航、页面生命周期 |
| `frontend/api` | base path、请求、SSE、错误和取消 |
| `frontend/state` | 账户级状态、数据域更新和订阅 |
| `frontend/ui` | 无业务含义的按钮、弹层、toast、空状态等 |
| `frontend/content` | Markdown、LaTeX、纯文本预览和安全转义 |
| `frontend/media` | 图片选择、粘贴、拖放、预览和文件校验 |
| `frontend/time` | 日期格式化、本地自然日和跨午夜更新 |

CSS 稳定入口为根 `styles.css`，实现文件位于 `frontend/styles/`；后续增长时按 `tokens.css`、`base.css`、`components/`、`features/`、`pages/` 分层。页面和功能选择器必须有稳定作用域；禁止用无作用域标签选择器修复单页问题。

S3-12 当前实现采用原生模块且保持静态 HTML 可直接加载：`public/app.js` 只调用 `frontend/app` 的启动函数；`frontend/pages/index.mjs` 是 20 个现有视图与组别关系的唯一登记，统一切换 ARIA/可见状态；`frontend/features/index.mjs` 只组合进入或离开页面时的按需加载、溢出测量和动画清理；`public/styles.css` 只导入 `frontend/styles/application.css`。页面 presenter 与事件绑定封装在 `frontend/app/runtime.mjs` 的模块作用域，不再暴露根级可变变量或直接网络调用。

## 5. 依赖方向与公开契约

允许的依赖方向：

```text
启动入口
  -> 页面 / HTTP 适配层
  -> 领域或功能模块公开入口
  -> 共享能力接口
  -> 基础设施适配器
```

强制规则：

1. 模块外部只能导入该模块根 `index.mjs` 的公开符号。
2. 领域模块之间不得读取对方内部存储或修改对方对象；跨领域流程放在显式应用服务中。
3. `shared/` 不得反向导入 `modules/`、`features/` 或 `pages/`。
4. 前端页面不得直接调用 `fetch`；统一经过 `frontend/api`。
5. 前端功能不得通过全局 CSS 选择器、全局可变变量或任意 DOM 查询控制其他功能。
6. 路由、事件、数据对象和错误码属于契约；改变契约必须列出所有生产者与消费者。
7. 为迁移保留的兼容入口必须有删除条件、负责人和测试，不允许形成永久双实现。
8. 出现循环依赖时优先重新划分职责或提取最小契约，不通过延迟导入掩盖。

### 5.1 可执行模块登记

P0M-01 开始时建立 `knowledge/module-boundaries.json`，由 `check:modules` 直接读取。该 JSON 是模块路径和依赖事实的机器可读来源，本文继续负责设计原则、影响矩阵和维护规则，二者不重复保存说明性内容。

每个模块至少登记：

- 稳定模块 ID、类型（应用/领域/页面/功能/共享/基础设施）和当前状态。
- 模块根路径、唯一公开入口和允许依赖的模块 ID。
- 拥有的 API 路由、数据域、DOM 根节点或 CSS 作用域。
- 对应契约测试、行为测试和跨模块集成测试入口。
- 临时迁移例外、负责人、删除条件和最晚清理阶段。

检查脚本不得依赖人工维护的文件行号，也不得把所有历史依赖列入永久白名单。模块移动时先修改登记和测试，再移动实现；检查通过后才能删除旧入口。

## 6. 跨模块修改影响矩阵

任何改动先匹配下表。命中一行时，相关检查全部适用；不能因为代码只改了一个文件就跳过消费者。

| 变更类型 | 必查模块或资产 | 必测边界 |

## 8. 渐进迁移顺序

1. **冻结基线**：固定生产行为样本、API 响应、关键 DOM、截图、数据快照和性能基线。
2. **建立边界门禁**：建立模块登记、公开入口和 `check:modules`，先允许现有单文件作为明确记录的迁移例外。
3. **先拆无状态共享能力**：时间、校验、错误、内容渲染和 HTTP 辅助；每次只移动一个规则族。
4. **拆后端基础设施适配器**：配置、持久化、日志、附件和供应商调用，不改变业务数据结构。
5. **按领域拆后端**：优先低耦合模块，再处理 thoughts/AI/tasks/trash 等高耦合链路。
6. **拆前端通用能力**：API、会话、状态、内容和媒体输入。
7. **按页面和功能拆前端**：每次迁移一个页面或跨页面功能，并保留原交互和局部刷新行为。
8. **拆 CSS 与 HTML shell**：在 DOM 契约稳定后迁移样式，避免结构和样式同时大改。
9. **清除迁移例外**：删除旧实现、兼容转发、孤儿 CSS、未使用导出和临时允许规则。
10. **冻结候选并双轮审计**：完整系统测试、桌面/移动截图、生产快照兼容和回滚演练通过后，才进入发布。

高耦合链路不得由多个智能体同时拆分：

- `thoughts -> annotations -> ai -> tasks -> notifications`
- `trash -> attachment refs -> cleanup -> restore`
- `auth -> account storage -> API/SSE/attachments -> frontend session`
- `time -> sorting -> metrics -> page display`

## 12. G1 冻结契约

G1 于 2026-09-29 在当前工作区完成技术冻结，契约版本为 `API v1 1.0.0`。运行定义以 `src/http/openapi-v1.mjs`、`src/http/api-v1.mjs`、`src/modules/thoughts/index.mjs`、`src/app/thought-workflows.mjs` 和 `knowledge/module-boundaries.json` 为准。

- 成功响应固定为 `{ data, error: null, meta: { traceId, ... } }`；失败响应固定为 `{ data: null, error: { code, message, details? }, meta: { traceId } }`。
- 每个 HTTP 响应继续返回 `X-Request-Id`；合法客户端值透传，不合法或缺失时由服务端生成。
- 列表使用不透明 `cursor` 和有上限的 `limit`，下一页游标只出现在 `meta.nextCursor`；客户端不得解析游标内容。
- 单资源读取返回表示正整数版本的 `ETag`。条件更新/删除必须原样回传 `If-Match`；缺失为 `428 PRECONDITION_REQUIRED`，过期为 `412 PRECONDITION_FAILED`。
- 幂等创建和模型写操作必须提供 `Idempotency-Key`；同键同载荷复用结果，同键不同载荷返回 `409 IDEMPOTENCY_KEY_REUSED`。
- OpenAPI 根位于 `/api/v1/openapi.json`；G1 冻结思绪链列表、详情、创建、更新、删除和流式回答，S3-11 新增状态与健康记录的列表、详情、创建、更新和删除。旧 `/api/*` 与 v1 调用同一领域/应用服务，生产前端迁移完成前不得删除旧路由。
- v1 公共包络、错误码、游标格式、版本语义、幂等语义和根 OpenAPI 只能由集成负责人修改；支线只能提交领域分片和测试夹具。任何破坏性修改必须提升契约版本并重新经过 G1。

冻结的服务面：

- `createThoughtService`：`createChainInStore`、`updateChainInStore`、`saveGeneratedAnswerInStore`、`getChain`、`listChains`，以及既有块/备注/追问/状态命令。
- `createThoughtWorkflows`：`createChain`、`updateChain`、`removeChain`、`getChain`、`listChains`、`createDraft`、`createStarter`、`answerRoot`。

- `createThoughtHttp`：`handle` 保持旧 `/api/*` 兼容，`handleV1` 作为 v1 模块挂载点；后续领域沿用相同注册方式。

## 14. V0.3.0 串并行开发入口

V0.3.0 不复用上述 G2 的长期未提交工作树。当前调度、任务编号、`v0.2.x`
功能批次、最多两条实现线并行和串行合入规则统一见
[`reports/iteration-plan-v0.3.0-2026-09-30.md`](../reports/iteration-plan-v0.3.0-2026-09-30.md)。

本阶段继续遵守模块边界和影响矩阵，但工作树生命周期改为：

1. 从已提交的 `main` 基线创建一个任务分支。
2. 只有任务确需并行时才创建独立工作树。
3. 一个工作树只承载一个任务和一个明确所有权范围。
4. 每个可验收切片先形成本地提交，再进入串行集成。
5. 合并后记录提交和验证，确认工作树干净后用 `git worktree remove` 退出。

任何共享契约、schema、模块登记、根入口、全局样式或依赖锁仍由单一集成
负责人修改；支线发现公共缺口时返回串行主链，不在多个分支分别演化。
