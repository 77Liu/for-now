# 此刻 UI/UX 设计知识与 V0.4.0 规划

- 状态：**调研与规划基线，尚未进入设计实现**
- 形成日期：2026-10-01
- 适用版本：V0.4.0
- 适用终端：桌面 Web、移动 Web、iOS WebView / PWA

## 0. 文档职责

本文负责回答五个问题：

1. 当前界面为什么像“功能按钮罗列”，而不像一个完成度足够的产品。
2. 此刻应建立怎样的信息架构、交互模型和视觉系统。
3. 页面、组件、状态和多端适配必须遵守哪些明确约束。
4. V0.4.0 应按什么顺序完成 UI/UX 重构，以及如何判断真正完成。
5. 当前每个功能页还有哪些文案、布局、层级和可见范围需要继续审视。

本文是 V0.4.0 UI/UX 调研、设计约束和实施计划的单一事实来源，但不重复维护
其他领域已经确定的规则：

- 产品定位与数据边界以 [product-definition.md](product-definition.md) 为准。
- 文化表达与界面命名以
  [cultural-content-preferences.md](cultural-content-preferences.md) 为准。
- 浅色水墨、宋式气质、弱模块等长期设计哲学以
  [design-language.md](design-language.md) 为准。
- 首页已确认方向和接入约束以
  [home-v0.2-handoff.md](home-v0.2-handoff.md) 为准。

实现，也不构成发布证据。实施前仍需完成线框、视觉稿和交互原型评审。

## 1. 初步结论

当前问题不是“颜色不够漂亮”，而是产品层级尚未建立。

现有页面以功能和数据字段为中心：每增加一项能力，就新增一个标题、容器、按钮
或说明。功能虽然可见，却没有根据用户当下要完成的任务重新排序。结果是所有控件
都在争夺注意力，主要操作、辅助操作、系统状态和技术说明混在同一层级。

以当前“念起”录入页为例，移动端首屏同时展示：

- 正文标题和大文本框；
- 图片原文容器和添加按钮；
- 语音原件容器和上传按钮；
- 现场录音折叠入口；
- 标签输入；
- 发生时间选择；
- 保存按钮。

这些能力本身都有业务价值，但界面把它们表现为六组并列模块。用户真正的目标是
“把眼前这个念头留下来”，而不是先理解图片原文、语音原件、标签、时间和后台
处理之间的系统结构。

V0.4.0 的重构方向因此确定为：

> 从“把所有功能摆出来”转向“先帮助用户完成一个任务，再按需显露能力”。

设计质量按以下顺序判断：

1. 用户是否知道当前页面最重要的事情是什么。
2. 用户是否能低负担完成任务，并确认内容已经安全保存。
3. 用户是否能理解原始内容、系统状态和 AI 派生内容之间的关系。
4. 界面是否具有稳定、一致、可辨认的产品气质。
5. 功能数量是否在不同设备、异常状态和长期使用中仍然可控。

单纯更换配色、增大留白、统一圆角或增加动效，不能解决上述问题。

## 2. 现状诊断

### 2.1 信息架构

当前存在一级导航、组内导航、页面标题、卡片标题和功能区标题等多层入口，但各层
的职责没有完全分开：

- 一级导航表示生活场景；
- 组内导航混合内容类型与任务；
- 页面内部继续按后端对象或功能模块分组；
- 同一任务可能需要用户理解多个对象名称后才能完成。

这会产生三个问题：

1. **位置感弱。** 用户知道自己点了某个按钮，但不一定知道现在位于哪一层。
2. **入口竞争。** 多个功能拥有近似的视觉权重，无法形成明确的首要路径。
3. **扩展失控。** 每增加一个能力，就倾向于增加一个入口或容器，页面持续膨胀。

### 2.2 交互结构

当前许多页面使用“完整表单直接展开”的方式组织交互。该方式适合字段少、一次性
提交的后台表单，不适合高频、私人、需要保持思绪连续的记录工具。

具体表现为：

- 用户开始输入前就要扫描大量可选项；
- 图片、语音、标签、时间等辅助信息抢占主任务空间；
- 保存、上传、同步、转写和 AI 处理的完成边界不清；
- 长任务与短任务使用近似的表单结构；
- 编辑状态、查看状态和系统处理状态没有稳定的转换模型。

### 2.3 视觉系统

首页已经形成浅色宋式水墨方向，但功能页仍保留早期 demo 的组件语言：

- 厚卡片、虚线框、胶囊、文字按钮和字符图标并存；
- 同类按钮的尺寸、圆角、颜色和层级不一致；
- 容器用于分隔几乎所有功能，导致“卡片中再套卡片”；
- 页面之间缺少稳定的标题、正文、元信息和操作顺序；
- 控件比内容更醒目，阅读和回望被操作界面包围。

当前页面可以使用，但尚未形成完整的视觉语法。

### 2.4 内容设计

部分界面直接暴露内部概念，例如“原件”“分层保存”“后台转写”“服务尚未
配置”。这些词在异常解释和详情中有价值，但不应在正常主路径里成为第一层信息。

内容设计还存在以下风险：

- 同时解释功能、技术实现和用户动作；
- 辅助文字过长，反而增加理解成本；
- 保存成功、后台处理中和全部完成的文案区分不稳定；
- 用户原文、转写原文和 AI 整理稿虽有数据分层，但视觉标识不统一。

### 2.5 状态反馈

当前异步能力较多，包括附件上传、同步、ASR、OCR、图片理解、AI 回答和 TTS。
如果每个模块独立设计状态，用户会遇到多个不同的加载方式、成功文案和错误入口。

必须明确区分：

1. 内容是否已经留在本地。
2. 内容是否已经同步到服务端。
3. 附件是否已经上传。
4. AI 或识别任务是否仍在处理。
5. 哪一部分失败，原始内容是否仍然安全。

“保存成功”不能被用来代替上述所有状态。

### 2.6 多端体验

现有审计已证明 320px、390px 和桌面布局没有阻断级横向溢出，主要触控目标也已
进行修复。但“没有错位”只代表基本可用，不代表具有清楚的视觉层级和高质量体验。

V0.4.0 还需覆盖：

- 手机与桌面的任务顺序是否一致；
- 键盘打开后主操作是否仍可达；
- 系统字体放大后是否仍能阅读和操作；
- 横屏、WebView、安全区和前后台切换是否保持上下文；
- 加载、空数据、错误、恢复和权限拒绝是否都有设计；
- 视觉回归是否检查内容层级，而不只是页面非空。

## 3. 对标调研

调研只提取可迁移的设计原则，不复制产品外观、品牌资产或完整交互。

| 产品 | 值得借鉴 | 不直接照搬 |
| --- | --- | --- |
| Day One | 写作与内容回看优先；媒体作为同一条记录的组成部分；列表、日历、媒体等视图职责清楚；自动补充低负担元信息 | 不引入复杂富文本工具栏、重型日记管理和连续打卡压力 |
| stoic. | 先选择记录方式，再进入专注输入；辅助媒体通过加号按需展开；引导式任务有明确开始和完成反馈 | 不复制强引导、徽章、连续天数和心理训练包装 |
| flomo | 像聊天一样快速输入；无需先写标题、排版和分类；记录优先，整理与回顾后置 | 不把所有内容压成同一种卡片，也不放弃此刻已有的结构化记录 |
| mymind | 一键收集、自动整理、视觉内容优先；用户不必在输入时完成全部分类 | 不采用不可解释的全自动归类，不隐藏来源和 AI 推断边界 |
| DailyVox | 语音是一项明确主任务；录音、转写、完成和失败具有连续状态；操作靠近拇指热区 | 不把整款产品改为语音优先，也不使用过强的星空隐喻 |
| Voicenotes | 录音、转写、摘要和后续行动按时间顺序组织；用户离开录音页后仍可看到处理结果 | 不引入会议产品的信息密度和团队协作模型 |
| Bear | 编辑器保持安静，格式与附件工具退居次层；标签与正文关系自然；阅读和编辑状态清楚 | 不扩展为通用 Markdown 编辑器或复杂知识库 |
| Things | 功能深但首层安静；信息层级稳定；动效只用于保持空间和对象连续性；快捷输入不打断当前工作 | 不引入任务管理领域结构，也不以动画替代状态解释 |
| Apple HIG | 按相对重要性排序；最常用能力始终可见；复杂能力渐进披露；布局响应实际可用空间 | 不机械套用平台视觉皮肤，Web 与 WebView 仍保持此刻品牌 |
| NN/g 表单原则 | 逻辑分组、单列流程、清楚进度、简单语言和及时支持能降低认知负担 | 不把所有短任务改成多步骤向导 |

### 3.1 共同规律

优秀产品并不是功能少，而是让功能在正确时机出现：

- 高频动作处于首层；
- 当前任务只有一个视觉主角；
- 可选信息不会在任务开始前要求用户决策；
- 内容和状态先于管理工具；
- 复杂能力通过菜单、展开、详情或下一步出现；
- 系统在后台工作时持续说明“已经保住什么、还在处理什么”；
- 视觉品牌建立在稳定的排版、节奏和细节上，而不是装饰数量上。

### 3.2 对此刻的直接启示

1. 念起不是“多媒体表单”，而是一个可同时容纳文字、图片和声音的捕捉面。
2. 首页不是功能目录，而是进入记录、遇见旧内容和查看轻量状态的起点。
3. 内容列表不是操作面板，正文、时间、来源和媒体应先于编辑、删除和 AI 操作。
4. AI 不是独立装饰层，必须沿着原始内容之后出现，并持续标明来源和处理状态。
5. 视觉设计不能按页面逐个美化，必须先建立统一 token、组件和页面语法。

## 4. 目标用户与核心任务

### 4.1 使用情境

此刻服务同一个人在不同注意力状态下的使用：

| 情境 | 用户状态 | 界面责任 |
| --- | --- | --- |
| 突然想到一件事 | 时间短、容易被打断 | 立即输入，尽量不要求分类 |
| 走路或不方便打字 | 手被占用、注意力分散 | 一步开始录音，过程状态清楚 |
| 保存图片或截图 | 内容已有、解释可后补 | 先保留原图，再异步理解 |
| 每日记录状态 | 目标明确、字段有限 | 快速完成，解释与趋势后置 |
| 深入思考或写日记 | 注意力集中、内容较长 | 提供安静的编辑环境和可选引导 |
| 回看旧内容 | 以阅读、理解和关联为主 | 内容优先，操作退后，保留来源 |
| 查看系统处理 | 关注是否保存、同步和完成 | 用统一状态和可恢复动作降低不确定性 |

### 4.2 核心用户任务

V0.4.0 的页面与导航必须围绕以下任务，而不是围绕数据库对象组织：

1. 立即留下文字、图片或声音。
2. 记录今天的身体与心理状态。
3. 围绕一个问题继续思考或获得回答。
4. 阅读过去留下的内容并追溯来源。
5. 查看保存、同步和 AI 处理是否完成。
6. 修正系统对自己的理解。

功能若不能归入上述任务，默认不进入首层界面。

## 5. 体验原则

### 5.1 记录先于整理

用户开始记录前，不要求填写标题、标签、分类、说明或完整时间。系统可以提供当前
时间和默认归属，但必须允许用户看见并修改。

图片、语音和文字是同一条内容的不同输入方式，不应各自拥有一个默认展开的大型
模块。

### 5.2 内容先于控件

阅读页面首先展示正文、时间、来源和媒体。编辑、删除、重新理解、分享等操作根据
频率进入：

1. 直接可见的主操作；
2. 与对象相邻的上下文操作；
3. 更多菜单；
4. 详情或设置。

禁止把所有动作平铺在每条记录下方。

### 5.3 原始内容先于派生内容

视觉顺序固定为：

`用户原始内容 → 可核对的转写或识别原文 → AI 整理或回答 → 用户反馈`

任何 AI 结果都不能使用与用户原文相同的标题、字体层级和来源标识。没有可靠来源
时必须明确说明，不生成伪原文。

### 5.4 先确认安全，再说明处理

用户提交后，系统反馈顺序固定为：

1. 内容是否已在本地保住；
2. 是否已同步；
3. 附件是否已上传；
4. 后台任务是否仍在处理；
5. 是否需要用户处理异常。

用户不需要留在当前页面等待 AI 任务完成。

### 5.5 渐进披露

首层只展示大多数用户完成当前任务所需的能力。低频功能通过加号、更多菜单、展开
区或详情页进入。

渐进披露不是简单隐藏：

- 入口必须可发现；
- 标签必须说明会出现什么；
- 展开位置必须靠近被影响内容；
- 收起后保留用户输入；
- 再次进入时根据任务需要决定是否记忆上次状态。

### 5.6 一个页面，一个主要承诺

每个页面必须能用一句话说明“用户来这里做什么”。页面可以承载多个相关动作，但
只能有一个默认视觉主操作。

若两个动作同样重要，应先判断它们是否属于不同阶段或不同页面，而不是同时使用
两个主按钮。

### 5.7 安静而非消极

界面克制不等于低对比、不可发现或没有反馈。

- 正文和操作必须清楚；
- 背景、装饰和辅助曲线可以轻；
- 失败、危险和冲突必须明确；
- 不使用连续打卡、排名、红色警报或夸张庆祝制造压力；
- 不把低状态渲染成失败或退步。

### 5.8 可逆优先

关闭、返回、切换页面、断网和后台恢复不能轻易丢失草稿。删除、覆盖、放弃录音等
破坏性操作必须与普通操作分开，并提供撤销、回收或清楚确认。

### 5.9 哲学必须成为交互，不是装饰

“富含哲学”不等于在页面上增加古文、格言、山水意象或抽象概念。哲学只有转化为
用户能感受到的选择、节奏和权利，才属于产品设计。

| 哲学命题 | 界面表达 | 禁止做法 |
| --- | --- | --- |
| 人在变化中，不应被一次判断定义 | 所有个人理解带时间、来源、置信度和修正入口 | 用人格标签、综合分或单次问卷给用户下永久结论 |
| 未完成也是一种真实状态 | 念起允许一句话、一张图或一段声音独立保存 | 强迫用户补标题、标签、分类和完整解释 |
| 原文是本，系统是注 | 用户内容在前，AI 结果在后；来源可追溯 | 让 AI 摘要替代原文，或用同一视觉层级混合展示 |
| 时间提供上下文，不制造绩效 | 日期、变化和回望用于理解生活过程 | 用连续天数、排名、红色警报制造亏欠感 |
| 认识来自反复修正 | 编辑、否定、补充和新证据均可更新旧理解 | 把模型第一次输出包装为权威结论 |
| 克制是一种主动选择 | 首层只保留当前任务所需能力 | 把重要能力藏得不可发现，或用低对比伪装“高级感” |
| 留白意味着尊重注意力 | 通过节奏、对齐和空白建立层级 | 用无意义说明、装饰卡片和统计填满每一处空间 |
| 安静不等于冷漠 | 状态、失败和恢复反馈直接、及时、不过度庆祝 | 保存后撒花、弹跳，失败时只显示错误码 |
| 自主权高于系统聪明 | 用户决定是否调用 AI、是否保留派生结果 | 自动处理后直接写回原文或替用户做不可逆决定 |
| 相遇比推荐更温和 | 旧内容有限、可控地出现，用户可主动换一组 | 自动滚动、无限推送或用算法占据全部首页 |

每个设计评审必须指出本页面体现了哪些命题，以及这些命题具体落在什么交互上。
只写“东方”“宋式”“克制”“有温度”等形容词，不足以通过评审。

### 5.10 慢内容，快操作

此刻承载的是需要时间理解的私人内容，但记录、返回、保存和恢复必须迅速。设计应
形成“慢内容，快操作”的节奏：

- 用户可以慢慢读、慢慢想，系统不催促完成；
- 用户一旦决定记录，界面立即响应；
- 过场动效短而稳定，不延长任务；
- AI 可以慢，但原始内容必须先安全；
- 回望可以深，但默认入口不能复杂；
- 长解释进入详情，当前动作只保留必要文字。

## 6. 信息架构

### 6.1 一级导航

一级导航继续使用已经确认的四个名称：

| 一级导航 | 用户心智 | 首要任务 |
| --- | --- | --- |
| 今日 | 我今天怎么样，要做什么 | 记录当下、查看今日状态与内容 |
| 所见 | 我从外部收到了什么 | 捕念、书间、拾句、小物 |
| 所思 | 我怎样理解和表达 | 思绪、日记、回顾 |
| 我的 | 系统如何为我工作 | 个人信息、设置、同步、用量与隐私 |

V0.4.0 不重新命名一级导航。命名变化必须先更新
[cultural-content-preferences.md](cultural-content-preferences.md)。

### 6.2 导航层级

导航最多三层：

1. 一级导航：生活场景。
2. 组内页面：稳定内容类型或主要任务。
3. 页面内上下文：筛选、更多操作、详情。

禁止出现第四层常驻标签栏。更深信息应使用详情页、抽屉、表单或返回路径表达。

### 6.3 导航规则

- 任一时刻只显示一个明确选中的一级入口和一个当前页面。
- 移动端一级导航固定在底部安全区，桌面端使用侧栏。
- 组内导航在移动端允许横向滚动，但不得截断为无法理解的半个词。
- 同一内容的桌面和移动入口名称必须一致。
- 浏览器返回、系统返回和界面返回必须遵循同一历史栈。
- 打开详情再返回时，保留列表滚动位置、筛选和展开状态。
- 旧 URL 必须通过映射进入新页面，不直接失效。
- 主要任务在所属一级入口内不超过两次点击或轻触可达。

### 6.4 页面职责

| 页面 | 默认展示 | 按需展示 | 不应默认展示 |

| 共参 | 对话历史、当前输入 | 来源、模型说明、发生时间 | 全部模型设置、成本详情 |

| 念起 | 统一录入器、最近捕念 | 图片、语音、标签、时间、详情操作 | 独立图片框和独立语音大面板 |

## 7. 页面语法

所有页面使用同一结构顺序：

1. **位置层。** 当前页面名称和必要的返回关系。
2. **任务层。** 当前页面的一个主要动作或主要内容。
3. **内容层。** 用户记录、媒体、趋势或对话。
4. **上下文层。** 筛选、标签、时间和低频操作。
5. **系统层。** 保存、同步、处理、错误和恢复。

视觉权重从任务层和内容层向上下两端递减。系统状态需要清楚，但不应永久占据最大
空间。

### 7.1 页面标题

- 页面标题用于说明当前位置，不重复解释产品功能。
- 手机页面标题建议 24 至 28px，桌面 28 至 36px。
- 页面内部区块标题建议 16 至 20px。
- 紧凑面板和卡片标题不超过 18px。
- 不使用超大营销式标题占据业务工具首屏。
- 标题与下方内容间距大于同组内容内部间距，以建立分组。

### 7.2 主操作

- 每个页面默认最多一个填充色主按钮。
- 保存、发送、确认等完成当前任务的动作用文本按钮。
- 添加图片、录音、播放、关闭、更多等熟悉动作用图标按钮。
- 图标按钮必须提供 `aria-label` 和悬停提示。
- 取消使用低强调文字按钮；删除使用危险语义但不常驻高亮。
- 同一动作不能同时在标题栏、卡片底部和浮动按钮重复出现。

### 7.3 内容与容器

- 页面区段默认无外层卡片，通过留白、对齐和细分隔线组织。
- 卡片只用于独立、可重复的内容对象，以及模态编辑器和真正需要边界的工具。
- 禁止卡片嵌套卡片。
- 同一屏幕同时出现的实线外框不超过两个层级。
- 虚线只表示拖放或待添加区域，不用于普通内容分组。
- 阴影只用于浮层、拖动对象和需要与背景分离的临时表面。

## 8. 核心交互规格

### 8.1 统一录入器

统一录入器服务念起，也可复用于思绪根、日记、评论等轻量输入。不同内容类型可以
配置字段，但不重新发明交互。

#### 默认结构

默认状态只包含：

1. 内容输入区；
2. 图片按钮；
3. 录音按钮；
4. 更多按钮；
5. 当前发生时间；
6. 一个保存动作。

标签、手动时间、音频上传和其他低频选项通过“更多”或与媒体入口相邻的菜单出现。

#### 输入方式

- 文字、图片和语音均可独立构成有效内容。
- 添加图片后在正文附近形成缩略预览，不出现新的大型“图片原文”模块。
- 点击录音后，录音控制替换普通工具栏的中心区域，避免两套控件并存。
- 音频文件上传属于语音入口的第二选项，不默认占据整行。
- 已添加媒体显示数量、大小或时长，以及移除动作。
- 删除媒体前说明只移除草稿引用还是同时删除已上传对象。

#### 时间

- 默认时间以紧凑项显示为“现在”。
- 点击后可切换“现在”或“手动指定”。
- 选择“现在”时以提交时刻为准，不使用页面打开时刻。
- 手动时间显示完整日期与时间，不能只显示模糊相对时间。
- 编辑旧记录时保留原发生时间，除非用户明确修改。

#### 标签

- 标签不是保存前必填项。
- 默认不占用独立整行标题和说明。
- 输入 `#` 或点击标签入口时展示建议。
- 已有标签以紧凑标签呈现，可键盘删除和读屏识别。
- 自动建议不能在未确认时直接写入用户原始标签。

#### 保存

- 保存按钮名称使用直接动作，例如“收下”“保存”“发送”，由内容类型决定。
- 提交中按钮不改变宽度，不引发布局跳动。
- 首次点击后立即进入确定状态，阻止重复提交。
- 本地持久成功与服务端确认必须分别反馈。
- 后台 AI 处理不阻塞关闭编辑器。

#### 草稿

- 收起、切换页面、刷新和应用进入后台后保留草稿。
- 草稿按账户和内容类型隔离。
- 再次进入时说明恢复了哪一份草稿。
- 用户主动清空或提交成功后才清理草稿。
- 退出账户后不得向下一账户显示前一账户草稿。

### 8.2 录音状态机

| 状态 | 主界面 | 可用动作 | 禁止行为 |
| --- | --- | --- | --- |
| 未开始 | 麦克风入口 | 开始、选择音频文件 | 展示空播放器 |
| 请求权限 | 简短状态 | 取消 | 重复弹权限 |
| 录音中 | 计时、波形、明确录音标记 | 暂停、完成、取消 | 切换输入设备而无说明 |
| 已暂停 | 静止波形、暂停标记 | 继续、完成、取消 | 把暂停显示为已完成 |
| 本地保存 | 播放器、时长、文件信息 | 播放、移除、提交 | 宣称已经转写 |
| 已提交待转写 | 原音播放器、处理状态 | 离开、稍后查看 | 阻塞在当前页 |
| 转写完成 | 转写原文 | 查看、修正、整理 | 覆盖原音或用户文字 |
| 转写失败 | 原音仍可用、失败原因 | 重试、保留原音 | 暗示原音丢失 |

来电、前后台切换、权限撤回和页面关闭必须进入可解释状态。不能继续无声录音，也不能
丢弃已获得的音频。

### 8.3 内容列表

- 列表首层固定顺序：发生时间、来源或类型、正文摘要、关键媒体、必要状态。
- 正文默认最多显示约 3 至 5 行，具体按内容类型确定。
- 截断必须提供详情入口，不用渐隐覆盖最后一行文字。
- 列表项的编辑、删除和重新处理进入更多菜单。
- 高频的“继续思考”“查看原文”等与内容直接相关的动作可以保留一项直接入口。
- 多媒体列表先渲染稳定占位，再异步加载资源，不能引发行高反复跳动。
- 加载下一页时保留当前位置；到达末尾后明确结束，不无限显示加载。

### 8.4 内容详情

详情页使用阅读优先顺序：

1. 发生时间和来源；
2. 用户原文；
3. 原始图片或音频；
4. 转写或识别原文；
5. AI 派生内容；
6. 用户反馈、修正和后续行动；
7. 编辑、删除等管理操作。

详情返回后必须恢复列表上下文。图片查看器、音频播放器和长文阅读不能被放入另一个
装饰卡片。

### 8.5 首页

首页继续遵守已经确认的优先级：

`记录思考 → 用户已有内容 → 小物 → 轻量状态参考`

V0.4.0 不把首页重新改成功能面板。行动、习惯、完整状态表和完整思考表单继续按需
进入。

首页内容必须来自当前账户的真实可访问记录。无数据时展示一个具体下一步，不用假
内容填满版面。

### 8.6 思绪与日记

- 思绪编辑以“问题或主题”为主，初步想法、媒体和 AI 引导按需出现。
- 日记编辑默认是一张安静的写作面，不同时展开全部引导和 AI 工具。
- 写作引导通过横向建议、菜单或空白页入口出现，选择后进入正文，不持续占位。
- AI 只在用户明确触发后参与，不自动改写用户正文。
- 长文编辑离开前自动保存草稿，并提供明确的保存状态。
- 阅读态和编辑态在视觉上必须明显不同。

### 8.7 状态与健康

- 当次记录只突出当前选择的指标，不同时展开所有健康类型。
- 识别结果必须进入核对态，模型结果不得直接保存。
- 趋势图使用真实固定量表和时间，不通过缩放夸大变化。
- 缺失数据不补零，不跨缺失日期连接。
- 颜色表达类别和状态，不表达道德评价。
- 图表必须提供文本数值、时间范围和数据来源。

### 8.8 首次使用与空状态

冷启动不是把问卷从首页移到另一个页面，而是新用户第一次理解产品、建立信任并
完成首个真实动作的完整旅程。流程固定为：

`欢迎 → 产品介绍 → 选择答题深度 → 逐题作答 → 可选资料 → 初始理解 → 第一条记录`

#### 8.8.1 欢迎页

首次进入先显示独立欢迎页，不直接出现登录表单或整张问卷。

欢迎页只承担三件事：

1. 明确产品名称“此刻”；
2. 用一句话说明产品承诺；
3. 提供一个开始动作。

建议内容层级：

- 品牌：`此刻`；
- 主句：`留下真实的此刻，慢慢看见自己的变化。`；
- 补充：`记录、回望，也允许你随时纠正系统的理解。`；
- 主按钮：`开始`；
- 次入口：`已有账户，登录`。

欢迎页使用整屏但不把文字放进卡片。浅色山水或真实纸面材质作为全幅环境背景，
中心阅读区保持干净。首屏不得出现功能清单、价格、版本、供应商、权限说明或长篇
品牌故事。

#### 8.8.2 产品介绍

欢迎之后提供简短产品介绍。介绍不是可左右滑动十余页的功能轮播，也不是营销落地
页。最多三个连续画面，每个画面只表达一个承诺：

1. **先留下。** 文字、图片或声音，都可以先保存。
2. **再看见。** 时间会把零散记录连接成可以回望的线索。
3. **始终由你决定。** 系统可以理解和建议，但不能替你定义你。

每个画面包含：

- 一个短标题；
- 不超过两行的正文；
- 一个与真实产品状态有关的视觉对象；
- 固定位置的继续按钮；
- 始终可见的“跳过介绍”。

不得使用抽象功能图标矩阵、夸张数据、虚构用户记录或“AI 改变人生”等承诺。
介绍内容完成后仍可在“关于”中重新查看，但不应每次启动重复出现。

#### 8.8.3 开始答题前

答题前用一个短画面说明：

- 问题用于建立可修正的初始认识；
- 没有标准答案；
- 之后可以修改；
- 快速版约 2 分钟，详细版约 5 分钟；
- 题目内容和当前数据边界保持不变，除非另行进行内容研究。

模式选择使用两项大按钮，不使用紧凑分段控件：

| 模式 | 标题 | 辅助说明 |
| --- | --- | --- |
| 快速认识 | 8 题 | 先建立最小起点，之后再慢慢补充 |
| 更完整地认识 | 18 题 | 现在多回答一些，仍可随时修改 |

默认推荐快速版，但不能替用户自动开始，也不能用“推荐”制造详细版较差的暗示。

#### 8.8.4 逐题作答

问卷必须一题一页或一题一屏切换。不得在同一长页面列出 8 题或 18 题。

每题的视觉结构固定：

1. 顶部返回；
2. 细进度线与 `3 / 8` 形式的进度；
3. 低强调维度名称；
4. 放大的题目；
5. 纵向答案按钮；
6. 底部“稍后继续”。

阅读约束：

- 移动端题目 24 至 28px，行高 1.5；
- 桌面题目 28 至 32px，最大文本宽度 620px；
- 中文每行建议约 18 至 28 个字；
- 选项文字 16 至 18px，行高至少 1.5；
- 每个答案按钮最小高度 56px，文字长时自然增高；
- 题目、选项和进度之间使用稳定间距，不堆叠解释；
- “世界观、人生观与价值判断”等维度只作为小型上下文，不做大标题。

答案按钮不是装饰卡片。默认使用安静的整行选择项，包含清楚边界、按下反馈和选中
状态。四个选项在移动端单列，桌面可在文本都较短时使用 2×2，但同一轮问卷保持
一致，不随单题任意切换列数。

#### 8.8.5 答题切换与动画

选择答案后：

1. 当前答案在 120ms 内进入明确选中态；
2. 保留 180 至 240ms 确认时间；
3. 当前题轻微向左移出，下一题从右侧进入；
4. 返回上一题时方向相反；
5. 进度线与题目同步更新；
6. 焦点移动到新题标题，读屏播报新题和进度。

位移不超过 16px，同时使用透明度变化。禁止翻页、3D 旋转、弹跳、粒子和大幅视差。
开启减少动效后，取消位移，只做即时替换或 100ms 以内淡入。

选择后自动进入下一题，但必须满足：

- 已选答案立即保存；
- 顶部返回可修改上一题；
- 键盘用户按方向键移动、Enter 确认；
- 读屏用户选择后有明确状态通知；
- 最后一题不自动跳过总结，改为进入“看看初始理解”。

#### 8.8.6 控件位置稳定

题目切换时，以下位置不得漂移：

- 返回按钮；
- 进度条；
- 题目内容区顶部；
- 答案列表起点；
- 底部“稍后继续”。

题目和选项长度不同时允许内容自然增高，但共享框架、左右边距、按钮宽度、圆角、
描边、字号和间距必须相同。切换前后共享控件的几何差异不得超过 1px。

#### 8.8.7 可选资料

必答题完成后，单独询问是否补充资料。默认提供：

- `先到这里`；
- `再补充一些`。

选择补充后，按“基本资料、兴趣、自我介绍、已有材料”分步展示，不一次展开全部
字段。每一步都可跳过。导入文件只在“已有材料”步骤出现，不提前展示 Markdown
等格式术语。

#### 8.8.8 初始理解

系统生成初始理解前，先说明这是“根据当前回答形成的起点”，不是人格结论。

初始理解按以下顺序展示：

1. 用户明确选择；
2. 系统归纳出的暂时倾向；
3. 证据不足或存在矛盾的部分；
4. 修改或否定入口。

禁止生成固定人格类型、分数、标签徽章或“你就是怎样的人”式结论。

#### 8.8.9 首次真实动作

完成冷启动后不进入庆祝页或功能目录，而是提供一个低负担的首次动作：

- `留下一句话`；
- `记录现在的状态`；
- `先去看看`。

选择后直接进入真实页面和真实保存流程。产品介绍、问卷样例和完成动画不能制造
虚假记录。

#### 8.8.10 返回用户与异常

- 已完成冷启动的用户不再进入欢迎与问卷。
- 中途退出后，下次展示“继续认识”与“暂时跳过”，不强制重来。
- 网络中断时答案先保存在本地，恢复后继续。
- 提交失败时说明已保存到哪一步。
- 问卷版本升级不删除旧答案；新增问题单独提示。
- 登录、注册和冷启动之间的返回关系必须清楚。

#### 8.8.11 普通空状态

普通功能页的空状态只提供一个与当前页面相关的主操作。空状态不复用冷启动欢迎页，
也不展示完整产品介绍。

## 9. 系统状态语言

### 9.1 七类统一状态

| 状态 | 含义 | 推荐反馈 |
| --- | --- | --- |
| 编辑中 | 内容尚未持久化 | 不显示成功图标，可显示草稿状态 |
| 已保存 | 已在本地或服务端安全持久化 | “已保存”并说明保存位置 |
| 同步中 | 本地已安全，正在同步 | “已保存，正在同步” |
| 处理中 | 原始内容已安全，后台任务进行中 | “原音已保存，正在转写” |
| 已完成 | 当前任务全部完成 | 简短成功反馈，不持续占位 |
| 需要处理 | 存在冲突、权限或人工确认 | 说明影响和下一步 |
| 失败 | 当前步骤失败 | 说明未完成部分、已保住内容和恢复动作 |

### 9.2 反馈层级

- 与单个字段相关的问题放在字段附近。
- 与当前对象相关的保存或处理状态放在对象附近。
- 跨页面持续的任务进入统一任务入口。
- 全局、短暂且无需操作的成功消息可使用 toast。
- 需要用户决定的冲突不能只用 toast。
- 错误不能只写“失败”或错误码。

### 9.3 错误文案公式

错误文案按以下顺序书写：

`发生了什么 + 哪些内容仍然安全 + 用户下一步能做什么`

示例：

- “音频上传中断。文字草稿和本地录音仍在，可以重新上传。”
- “转写暂时失败。原音已经保存，稍后可再次转写。”
- “这条记录已在其他页面更新。你的修改仍保留，请选择重新加载或另存。”

内部错误码可进入诊断详情，不作为首层提示。

## 10. 视觉语言

### 10.1 视觉概念

V0.4.0 的视觉概念是：

> 宣纸承载内容，墨色建立秩序，留白提供呼吸，痕迹表达时间。

该概念不是复古装饰主题，而是界面决策方法：

- 宣纸：接近白色、低噪声的稳定内容表面；
- 墨色：高可读正文和清楚层级；
- 留白：通过空间建立关系，不依赖大量边框；
- 痕迹：日期、来源、版本和变化可追溯；
- 丹青：低饱和辅助色用于状态与重点，不覆盖内容。

### 10.2 颜色系统

以下为 V0.4.0 设计基线，实施时必须通过实际对比度测试：

| 语义 token | 建议基线 | 用途 |
| --- | --- | --- |
| `canvas` | `#F5F6F3` | 应用背景 |
| `paper` | `#FAF9F5` | 主要阅读与编辑表面 |
| `ink` | `#282F28` | 正文、主要标题 |
| `ink-secondary` | `#59615B` | 日期、来源、次级正文 |
| `moss` | `#40593B` | 主操作、选中态 |
| `moss-soft` | `#E6E9DE` | 轻选中、辅助底色 |
| `blue-gray` | `#536778` | 同步、系统信息 |
| `ochre` | `#8A642C` | 等待、需要注意 |
| `crimson` | `#914C52` | 错误、危险操作 |
| `success` | `#3F6D57` | 完成状态 |
| `hairline` | `#D8DDD7` | 分隔线、输入边界 |

约束：

- 页面不能由单一绿色家族主导，正文、系统、警告和危险使用不同语义色。
- 浅色只用于背景和装饰，正文不得低对比。
- 主操作同屏只使用一个主要强调色。
- 红色只用于错误和破坏性动作，不表示低情绪或低状态。
- AI 内容不使用梦幻紫色渐变作为默认身份标识。
- 不使用渐变球、光斑或模糊色团作为装饰背景。

### 10.3 字体

| 层级 | 字体 | 建议尺寸 | 字重 | 行高 |
| --- | --- | ---: | ---: | ---: |
| 品牌 | 宋体栈 | 28 至 36px | 600 | 1.2 |
| 页面标题 | 宋体栈或系统字体 | 24 至 32px | 600 | 1.25 |
| 内容原文 | 宋体栈 | 16 至 18px | 400 | 1.75 |
| 区块标题 | 系统字体 | 16 至 20px | 600 | 1.4 |
| 表单与按钮 | 系统字体 | 16px | 500 至 600 | 1.4 |
| 元信息 | 系统字体 | 13 至 14px | 400 至 500 | 1.5 |

规则：

- 品牌、主标题和用户原文可以使用宋体。
- 控件、标签、日期、状态和辅助说明使用系统无衬线字体。
- 字号不随视口宽度连续缩放，不使用 `vw` 控制文字。
- 字间距保持 `0`，不用负字距挤压标题。
- 手机输入控件字体不小于 16px。
- 元信息不能因追求“轻”而低于可读对比度。

### 10.4 间距

采用 4px 基础单位：

`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64`

使用规则：

- 同一控件内部：4 至 8px。
- 同组字段：8 至 12px。
- 同一区块元素：12 至 16px。
- 不同区块：24 至 32px。
- 页面主要章节：32 至 48px。
- 留白用于表示层级，不随意填入说明、图标或装饰。

### 10.5 圆角与边界

- 普通输入、按钮和工具表面：4 至 6px。
- 内容卡片和模态工具：最多 8px。
- 标签、状态点和头像可以使用全圆角。
- 图标按钮可以使用圆形。
- 不把所有文本按钮设计成胶囊。
- 普通内容默认无阴影。
- 输入聚焦使用清楚的边框和外圈，不通过尺寸变化表达。
- 虚线只用于可投放、可添加的空区域。

### 10.6 图标

- 统一使用 Lucide 或同等一致性的线性图标，不手绘多套 SVG。
- 默认尺寸 20px，紧凑工具 18px，主要媒体入口 24px。
- 默认描边建议 1.75px，并在实际屏幕检查清晰度。
- 常见操作只用图标：关闭、返回、更多、播放、暂停、删除、图片、麦克风。
- 不熟悉或有歧义的图标必须配文字或 tooltip。
- 不使用 `＋`、`×`、`↑` 等字符冒充所有图标。
- 同一动作在全产品使用同一图标和名称。

### 10.7 动效

动效只服务三件事：

1. 说明对象从哪里出现或回到哪里；
2. 保持列表、详情和编辑器之间的空间连续性；
3. 表达录音、上传和处理正在发生。

建议时长：

- 按钮与颜色反馈：120ms。
- 展开、收起和局部切换：180ms。
- 页面或模态层转换：240ms。

规则：

- 不使用持续漂浮、呼吸和背景粒子。
- 不通过弹跳强调普通保存成功。
- 加载动画不能替代文字状态。
- `prefers-reduced-motion` 下取消位移、缩放和循环动画。
- 动画过程中布局尺寸保持稳定，不能导致周围内容跳动。

## 11. 组件约束

### 11.1 按钮

| 类型 | 用途 | 数量约束 |
| --- | --- | --- |
| Primary | 完成当前主要任务 | 每个页面或模态层最多一个 |
| Secondary | 可逆的次要命令 | 与主按钮成组时最多两个 |
| Text | 取消、查看、低频跳转 | 不应形成整排按钮文字 |
| Icon | 熟悉的工具动作 | 必须有可访问名称 |
| Danger | 删除、放弃、不可逆动作 | 不与主按钮并列同色 |

按钮文本使用动词，避免“确定”“好的”等脱离上下文的词。

### 11.2 输入

- 标签始终存在，不能只依赖 placeholder。
- placeholder 只提供示例，不重复字段名。
- 必填、可选和格式要求在输入前可见。
- 校验优先在失焦或提交后出现，不在每次按键时制造噪声。
- 错误出现后输入高度尽量稳定。
- 多行文本自然增长到上限，超过后内部滚动。

### 11.3 分段控制

- 只用于 2 至 4 个互斥、同层级选项。
- 当前选项必须同时通过形状、文字或图标表达，不能只依赖颜色。
- 不用分段控制代替页面导航。
- 选项文本过长时改为列表或菜单，不能缩小字体硬塞。

### 11.4 标签

- 标签是元信息，不是主按钮。
- 标签颜色保持低饱和，正文对比度合格。
- 标签文本允许换行或截断后进入详情，不能撑破容器。
- 可删除标签提供明确可访问动作。

### 11.5 菜单

- 编辑、删除、重新处理、导出等低频对象操作进入上下文菜单。
- 菜单项使用清楚动词，并使用统一图标。
- 危险操作放在菜单末尾并分组。
- 菜单关闭后焦点返回触发按钮。

### 11.6 模态层与抽屉

- 单一、短小、需要保持父页面上下文的任务使用 sheet 或 dialog。
- 长文编辑、媒体查看和多步骤流程使用全屏或独立页面。
- 不连续打开多个模态层。
- 必须有明确关闭方式、Esc、焦点约束和焦点返回。
- 关闭未保存内容时先自动保存草稿；确有丢失风险才询问。

### 11.7 空状态

空状态由三部分构成：

1. 发生了什么；
2. 为什么这很正常；
3. 一个具体下一步。

禁止加入功能介绍清单、键盘快捷键教学或假数据。空状态不是营销页。

### 11.8 加载状态

- 已知结构使用稳定骨架，占位尺寸等于最终内容。
- 未知短操作使用按钮内状态或简短进度。
- 超过 1 秒显示正在执行的动作。
- 超过预期时间说明仍在继续，并允许用户离开。
- 不显示虚假百分比。

### 11.9 图表

- 图表先回答一个问题，不把多个指标塞入同一小图。
- 轴、范围、时间和单位在详情中完整可见。
- 颜色不是唯一编码，配合形状、线型或文字。
- 数据点可访问，至少提供等价文本或表格。
- 缺失值、推断值和用户确认值必须区分。

### 11.10 组件几何与无漂移契约

“同一种组件使用同一套设计”不仅指颜色相同，还包括结构、尺寸、点击区域、内容
对齐、状态变化和动效方式相同。

#### 基础尺寸

| 组件 | Compact | Medium / Wide | 固定约束 |
| --- | ---: | ---: | --- |
| 主按钮 | 高 48px | 高 44px | 同一流程宽度稳定 |
| 次按钮 | 高 44px | 高 40 至 44px | 不因 loading 改变高度 |
| 图标按钮 | 44×44px | 40×40px，关键操作仍为 44×44px | 图标居中，不随状态缩放 |
| 单行输入 | 最小高 48px | 最小高 44px | 边框、内边距和标签位置统一 |
| 分段控制 | 最小高 44px | 最小高 40px | 轨道宽高固定，选中态不改变外框 |
| 组内导航 | 高 44px | 高 40 至 44px | 切换时页面内容起点稳定 |
| 移动底栏 | 56px + 安全区 | 不适用 | 图标与文字基线固定 |
| 桌面侧栏 | 不适用 | 128 至 160px | 同一断点内不随页面变化 |
| 页面水平边距 | 16px | 32 至 48px | 同级页面一致 |
| 内容图片 | 固定宽高比 | 固定宽高比 | 加载前后不改变占位 |

数值是设计基线。若原型测试需要调整，必须整体更新 token 和所有实例，不能仅为
某个页面写例外尺寸。

#### 模板切换

睡眠、心率、体重、运动等同类模板切换时：

- 页面标题、标签栏、上传入口、表单起点和保存区的横向位置不变；
- 共享组件的宽、高、字号、圆角、描边和内边距不变；
- 选中态不能通过加粗后变宽导致其他标签移动；
- 按钮文案变化时使用全宽按钮或稳定 `min-width`；
- 加载图标、数量徽标和错误图标必须预留空间；
- 内容长度可以改变页面总高，但不能改变页面骨架和首个字段位置；
- 切换使用同一方向和时长的 180ms 以内过渡；
- 不能先折叠到 0 高度再展开，造成明显页面闪动。

#### 状态切换

同一组件从默认、加载、成功到错误时：

- 外框尺寸不变；
- 文字基线不跳动；
- 图标槽位不新增或移除导致文案位移；
- 成功和错误说明在预留的状态区域出现；
- 骨架与真实内容使用相同网格；
- 禁用态不降低到无法辨认；
- 焦点不能因重新渲染丢失。

#### 自动验收

组件级视觉测试至少记录：

- `getBoundingClientRect()`；
- 计算后字号、行高、内边距、圆角和边框；
- 默认、悬停、聚焦、按下、加载、成功、错误和禁用截图；
- 模板切换前后共享锚点位置；
- 320、390、768、1440px 的几何差异。

同一断点、同一组件、不同状态的非预期位置差异上限为 1px。文本自然换行和内容区
自然增高不算漂移，但共享控制区移动属于失败。

### 11.11 组件治理

- 每个组件有唯一名称、职责、变体和状态清单。
- 页面只能组合组件，不复制组件样式后自行修改。
- 新增变体必须说明现有组件为何不能满足。
- 视觉相同但行为不同的组件必须拆分语义，不能只靠 class 名区分。
- 行为相同但外观不同的组件应收敛为 token 变体。
- 每个组件变更必须检查所有使用页面。
- 废弃组件在迁移完成后删除，不能长期保留两套。

当前样式中按钮、动作、控制和标签相关类名较多，圆角从 2px 到 999px 并存。这些
数字只作为系统漂移的审计信号，V0.4.0 实施前仍需建立真实组件 inventory，确认
哪些是合理变体，哪些是历史重复。

## 12. 内容设计

### 12.1 语言原则

- 先说用户能做什么，再说系统如何工作。
- 使用常用、具体、短句。
- 一个句子只表达一个动作或状态。
- 正常路径不暴露 API、ASR、OCR、Worker、幂等等内部术语。
- 技术词只在设置、诊断或需要解释边界时出现，并配普通中文。
- 不用诗化名称代替清楚功能，不用功能说明破坏已经清楚的名称。

### 12.2 文案层级

| 层级 | 作用 | 示例 |
| --- | --- | --- |
| 页面名称 | 表示位置 | 念起 |
| 任务提示 | 帮助开始 | 写下一句话，或留下图片和声音 |
| 操作 | 明确命令 | 保存、录音、添加图片 |
| 状态 | 说明系统进度 | 原音已保存，正在转写 |
| 解释 | 说明边界 | 转写可修改，不会覆盖原音 |

同一信息不在标题、说明和按钮中重复三次。

### 12.3 AI 标识

以下来源信息必须可获得：

- 用户原文；
- 转写原文；
- 图片识别；
- AI 整理；
- AI 应答；
- 用户已确认；
- 用户已修正。

来源说明不评价质量。AI 结果必须能回到所依据的原始记录。

“可获得”不等于每张卡片都固定显示“用户原文”。当页面上下文已经明确内容来自
用户时，不重复贴标签；只有在用户内容与 AI 内容并列、来源可能混淆或进入审计
详情时显示。

### 12.4 用户可见文案治理

所有展示文字必须归入以下一种职责：

1. 表示当前位置；
2. 帮助用户开始任务；
3. 命名一个操作；
4. 说明状态和结果；
5. 解释必要边界；
6. 标明来源与不确定性。

不能归入上述职责的文字默认删除，而不是寻找空位保留。

#### 必须移出正常界面的内容

- 用于向 Owner 证明功能已实现的说明；
- API、ASR、OCR、Worker、Token、幂等等内部术语；
- “最新在前”“内容时间线”“用户原文”等模板结构说明；
- “原音频与转写分层保存”等数据模型说明；
- “需要时展开麦克风控制”等显而易见的操作解释；
- 供应商名称和模型档位，除非用户正在查看高级设置或费用；
- 测试模式、环境、版本、隔离和调试状态；
- 实现限制和研发备注。

这些信息若确有价值，应进入：

- 可访问名称；
- 详情中的来源说明；
- 高级设置；
- 管理员或开发者模式；
- 帮助文档；
- 错误诊断详情。

#### 页面标题规则

- 首选直接页面名或当前任务。
- 已有导航已说明位置时，不再叠加含义相近的眉题。
- 标语只在欢迎、关于或真正需要建立情绪的空状态出现。
- 同一句标语不作为每次进入页面都要阅读的固定障碍。
- 诗意文本必须能增强理解；只提供氛围而不提供方向时删除。

#### 文案审计状态

每条用户可见文案在设计稿中标记为：

| 状态 | 含义 |
| --- | --- |
| 保留 | 表达准确、必要且符合产品语气 |
| 重写 | 职责必要，但当前语言不清楚或不自然 |
| 删除 | 不提供用户价值，或重复表达 |
| 后移 | 放入更多、详情、帮助或高级设置 |
| 仅管理端 | 普通用户不应看见 |
| 待验证 | 需要通过用户理解测试决定 |

任何页面进入实现前，必须完成该页面所有静态文案、动态文案、空状态、错误、按钮、
tooltip、可访问名称和确认框的审计。

### 12.5 当前明确需要处理的文案

| 当前文字 | 初步判断 | 原因与方向 |
| --- | --- | --- |
| 碎片收集箱 | 删除或后移 | 是内部分类隐喻，导航“念起”已经说明位置 |
| 先捕捉，不急着想完整 | 重写或仅用于首次空状态 | 长期固定标语增加阅读，不直接说明动作 |
| 此刻冒出来的东西 | 重写 | 口语感较强但不够稳定，可改为直接输入提示 |
| 图片原文 | 删除或改为“图片” | 图片本身已经表明类型，“原文”用于图片不自然 |
| 语音原件 | 按上下文改为“录音”或“原音” | “原件”偏数据模型和档案术语 |
| 原音频与转写分层保存 | 后移 | 属于数据设计说明，正常录入无需阅读 |
| 需要时展开麦克风控制 | 删除 | 控件入口本身应可理解 |
| 用户原文 | 条件显示 | 只在与 AI 内容并列时有辨识价值 |
| 内容时间线 | 删除 | 是模板结构名称，用户已能看见内容按时间排列 |
| 最新在前 | 后移或通过排序控件表达 | 不应作为每次阅读的固定说明 |
| 日记助手 | 重写为“日记” | 页面不应默认把系统置于用户写作之前 |
| 把今天写清楚，不必写漂亮 | 待验证 | “写清楚”仍可能制造表现压力 |
| DeepSeek 长期对话 | 后移 | 供应商不是用户任务，详情中再显示模型来源 |
| ASR 服务尚未配置 | 重写 | 改为用户可理解的“暂时不能转成文字，录音已保存” |
| 模型思考 | 删除或仅内部诊断 | 不向用户展示模型内部推理过程 |
| 每周自动尝试，服务需运行 | 删除或仅管理端 | 是实现状态，不是产品语言 |
| 本地持久化、账户数据已隔离 | 后移 | 属于信任与技术说明，不应常驻导航 |
| 测试数据与模型配置 | 仅管理端 | 普通用户不应进入测试与供应商配置界面 |

表中给出的是初步方向，不代表最终替换文案。正式文案必须结合页面原型、上下文和
用户理解测试确定。

## 13. 响应式设计

### 13.1 尺寸区间

| 区间 | 宽度 | 布局原则 |
| --- | ---: | --- |
| Compact | `≤760px` | 单列、底部一级导航、任务优先 |
| Medium | `761–1100px` | 单列或有限双列，保留阅读宽度 |
| Wide | `≥1101px` | 侧栏导航、内容可双列，不拉宽正文 |

断点依据可用空间，不依据具体设备名称。

### 13.2 手机

- 一级导航固定底部并计入安全区。
- 主要操作靠近拇指可达区域，但不遮挡内容和键盘。
- 表单默认单列。
- 键盘打开后当前字段和完成动作仍可达。
- 横屏时不把内容压成窄长区域，可收起非必要导航。
- 不通过缩小字体把更多控件塞入首屏。

### 13.3 桌面

- 侧栏宽度稳定，内容区域有最大阅读宽度。
- 长文正文建议 640 至 760px。
- 双列只用于彼此独立、可同时阅读的内容。
- 不把手机底栏简单放大为桌面导航。
- 鼠标悬停可以补充信息，但任何核心功能不能只在悬停时出现。

### 13.4 尺寸稳定

工具栏、媒体格、图表、录音控制、底部导航和图标按钮必须有稳定尺寸。加载文案、
状态图标或标签变化不能推动周围关键控件跳动。

## 14. 可访问性

### 14.1 基础标准

- 普通正文对比度至少 4.5:1。
- 大字对比度至少 3:1。
- 非文本图标和必要边界至少 3:1。
- 主要触控目标不小于 44×44pt。
- 手机输入字号不小于 16px。
- 支持 200% 页面缩放和系统大字体。

### 14.2 键盘

- 焦点顺序遵循视觉阅读顺序。
- 所有功能可使用键盘完成。
- 焦点样式清楚，不能只改变颜色。
- 模态层打开后焦点进入层内，关闭后返回触发点。
- 不使用无法退出的焦点陷阱。
- 快捷键是效率补充，不是唯一入口。

### 14.3 读屏

- 图标按钮提供准确名称。
- 状态变化通过适当的 live region 宣告，但不重复播报。
- 当前导航使用语义选中状态。
- 图表提供文字摘要和可读取数据。
- 图片说明区分内容图、装饰图和用户原图。
- 装饰水墨背景必须 `aria-hidden` 且不接收指针事件。

### 14.4 动效与媒体

- 遵守减少动效偏好。
- 音频提供播放、暂停、进度和时长。
- 波形不是录音状态的唯一证据。
- 自动播放默认关闭。
- 转写失败不影响原音播放。

## 15. 感知性能

UI/UX 验收不仅检查接口耗时，也检查用户感知：

- 点击后 100ms 内出现视觉反馈。
- 可以立即落本地的操作先进入安全状态，再后台同步。
- 已有页面切换不重复请求和清空内容。
- 媒体使用稳定占位、懒加载和预取，避免布局跳动。
- 列表分页不阻塞已显示内容。
- AI 任务进入后台后允许离开页面。
- 长操作持续显示对象、阶段和恢复入口。

不得用过度动画掩盖真实等待，也不得为了“看起来快”提前显示尚未成立的成功状态。

## 16. V0.4.0 计划

需求池中的 UI/UX 类型已拆成以下八项。编号从 `P0-35` 开始，避开当前工作树已经
使用的 `P0-34` 真实服务 E2E。

### 16.1 P0-35｜全端信息架构与导航重构

**目标**
让用户按任务找到入口，不必先理解所有模块。

**主要交付**

- 当前页面与入口清单；
- 用户任务与页面职责映射；
- 新导航图和旧 URL 映射；
- 手机、平板和桌面线框；
- 返回、深链、刷新和上下文恢复规则。

**完成定义**

- 核心任务在所属一级入口内不超过两次操作可达；
- 任一时刻只有一个明确当前位置；
- 桌面与手机名称一致、布局独立；
- 旧链接有兼容策略；
- 不新增第四层常驻导航。

### 16.2 P0-36｜统一录入器：文字、图片、语音按需组合

**目标**
把功能清单重构为一个专注、可扩展、可恢复的捕捉面。

**主要交付**

- 默认、输入、附图、录音、上传、保存和失败状态原型；
- 媒体工具栏与更多菜单；
- 发生时间和标签的渐进披露；
- 草稿恢复与账户隔离说明；
- 念起、思绪根、日记和评论的复用边界。

**完成定义**

- 390px 首屏可见主输入、媒体入口和保存动作；
- 纯文字、纯图片、纯语音和混合输入均可完成；
- 标签和手动时间不再默认占据大型区块；
- 键盘、刷新、返回和上传失败不丢草稿；
- 录音和后台转写状态连续且可解释。

### 16.3 P0-37｜统一视觉语言与组件系统

**目标**
让所有页面形成同一个产品的视觉语法。

**主要交付**

- 语义颜色、字体、间距、圆角、边界、图标和动效 token；
- 页面、列表、详情、表单和浮层模板；
- 按钮、输入、菜单、标签、状态、媒体、空状态和图表组件；
- 手机与桌面关键页面视觉稿；
- 默认、交互、加载、错误和禁用状态矩阵。

**完成定义**

- 所有主要页面使用同一套语义 token；
- 同类控件没有多套尺寸、圆角和图标语言；
- 同一组件切换状态或模板后，共享几何位置的非预期差异不超过 1px；
- 页面区段不再普遍卡片化；
- 用户内容始终比管理控件更突出；
- 浅色水墨背景不影响可读性和触控。

### 16.4 P0-38｜保存、同步与 AI 后台任务状态反馈

**目标**
让用户始终知道内容是否安全，以及系统还在做什么。

**主要交付**

- 七类统一状态及转换图；
- 对象内状态、全局任务入口和冲突处理原型；
- 保存、上传、同步、转写、理解和回答的文案；
- 断网、过期、冲突、取消和重试路径；
- 重复点击与幂等反馈规则。

**完成定义**

- 明确区分本地已保存、服务端已同步和后台已完成；
- 超过 1 秒的操作说明正在做什么；
- 用户可离开页面后继续查看；
- 失败提示包含影响、已保住内容和恢复动作；
- 重试不重复创建对象或重复计费。

### 16.5 P1-09｜内容列表、详情与回望阅读体验

**目标**
让回看首先是一种阅读体验，而不是管理后台。

**主要交付**

- 跨内容类型的列表与详情骨架；
- 日期、来源、正文、媒体和操作层级；
- 长文、图片、音频和 AI 派生内容展示规则；
- 列表位置、筛选和播放状态恢复；
- 首页与回顾页的内容投影规范。

**完成定义**

- 念起、思绪、日记、书间、拾句和小物使用一致内容顺序；
- 低频操作进入上下文菜单；
- 长内容进入详情，返回后保持上下文；
- 原文、转写和 AI 内容始终可区分；
- 图片和音频在详情中可完整查看或播放。

### 16.6 P1-11｜首次使用、空状态与渐进引导

**目标**
让首次使用一次理解一件事，并随时退出和继续。

**主要交付**

- 独立欢迎页与产品介绍；
- 答题深度选择与时间预期；
- 8 题与 18 题共用的分步流程；
- 单题大字排版、答案按钮和切换动效；
- 进度、保存、返回、跳过和继续规则；
- 可选资料的条件展示；
- 关键页面空状态；
- 完成后进入真实任务的路径。

**完成定义**

- 新用户先理解产品承诺，再进入问卷；
- 一屏一个主题；
- 题目和选项达到本文的字号、行长和触控标准；
- 前进与返回动画方向一致，减少动效模式可用；
- 切题时返回、进度、题目起点和底部动作不漂移；
- 可选信息清楚标记并可跳过；
- 刷新和退出后可继续；
- 完成前可审阅保存内容；
- 空状态各自只有一个明确主操作。

### 16.7 P1-12｜全站内容设计与用户文案重审

**目标**
清除初版占位文案、实现说明和证明式文字，让每句话只服务位置、任务、状态、边界
或来源。

**主要交付**

- 全站静态与动态展示文案 inventory；
- 保留、重写、删除、后移、仅管理端和待验证分类；
- 页面标题、按钮、空状态、错误、来源和 AI 标识词表；
- 普通用户、专业用户与管理员的信息可见范围；
- 禁止词、内部术语和供应商名称检查；
- 关键路径文案理解测试。

**完成定义**

- 所有功能页完成逐条文案审计；
- “图片原文”“内容时间线”“最新在前”等结构性说明不再常驻；
- “原音频与转写分层保存”等实现说明移出正常流程；
- 普通用户不再看见测试模式、架构、商业化、API 密钥和模型档位；
- 用户内容与 AI 内容只在可能混淆时显示来源；
- 错误文案说明发生了什么、数据是否安全和下一步。

### 16.8 P0-39｜响应式、可访问性与视觉验收门

**目标**
把“没有错位”提升为可重复验证的全端设计质量。

**主要交付**

- 设备、页面、状态和主题截图矩阵；
- 视觉回归基线；
- 对比度、焦点、读屏、缩放和减少动效检查；
- 键盘、安全区、横屏和前后台恢复用例；
- 真实用户任务验收清单。

**完成定义**

- 覆盖 320、390、768、1440px；
- 覆盖紧凑、标准和大屏三档 iPhone 的竖屏与横屏；
- 满足对比度、44pt 触控和 200% 缩放要求；
- 键盘打开后输入与主操作可达；
- 核心任务同时通过业务、持久化、异常恢复和视觉检查。

- 保存、同步和后台任务反馈；

### 阶段 C：阅读与首次使用

- 列表与详情；
- 原文与 AI 派生层级；

- 首次认知分步流程；
- 空状态和恢复；

### 阶段 D：全端验收

最终由 `P0-39` 收口，并从阶段 A 开始持续维护：

- 自动视觉回归；
- 多端布局；
- 键盘、读屏与字体缩放；
- 异常状态截图；
- 完整用户任务。

该阶段是发布门，不应在实现结束后才临时补设计标准。截图矩阵和验收用例必须在
阶段 A 同步建立，在每个阶段持续更新。

## 20. 设计评审清单

### 20.1 结构

- 页面是否只有一个主要任务？
- 用户是否需要理解内部对象或技术名词才能开始？
- 常用动作是否在两次操作内可达？
- 低频动作是否按需出现？
- 返回后是否保留上下文？

### 20.2 视觉

- 第一眼是否先看到内容或主要任务？
- 是否存在无意义卡片、阴影、胶囊或重复标题？
- 同类控件是否使用同一尺寸和图标？
- 正文、元信息和操作是否有清楚层级？
- 水墨背景是否退到内容之后？

### 20.3 状态

- 空、加载、成功、失败和恢复是否都有设计？
- 是否明确哪些内容已经安全保存？
- 用户能否离开长任务？
- 错误是否给出下一步？
- 重试是否可能重复提交？

### 20.4 内容

- 文案是否先说用户结果？
- 是否使用简单、直接的中文？
- 是否重复解释已经清楚的界面？
- 用户原文与 AI 内容是否可区分？
- 是否误把推断写成用户事实？

### 20.5 多端与可访问性

- 320px 和大字体下是否仍可用？
- 键盘是否遮挡当前输入或提交？
- 触控目标是否至少 44pt？
- 焦点顺序是否符合阅读顺序？
- 减少动效时是否仍能理解状态？

## 21. 设计完成定义

某个 UI/UX 需求只有同时满足以下条件，才能标记为完成：

1. 设计稿覆盖正常与异常状态。
2. 手机和桌面均有明确布局。
3. 文案、图标和组件来自统一规范。
4. 真实数据、长文本、空数据和错误数据均已验证。
5. 用户任务可以从入口走到业务结果。
6. 刷新或重开后结果仍然存在。
7. 键盘、焦点、读屏、字体缩放和减少动效通过。
8. 没有把用户原文和 AI 派生内容混合。
9. 没有新增未经说明的导航层级和视觉语言。
10. 固定截图和自动化证据已保存。

“页面能打开”“没有横向滚动”“按钮可以点击”只属于基本可用，不等同于设计完成。

## 22. 非目标

V0.4.0 UI/UX 重构不包含：

- 重命名已确认的一级导航；
- 新增社交、社区或公开内容流；
- 引入连续打卡压力、排名、分数或成长游戏化；
- 为展示设计而伪造用户内容；
- 把产品改造成通用笔记、文档或项目管理工具；
- 为视觉重构修改业务数据含义；
- 将 AI 派生内容提升为用户事实；
- 未经必要性验证引入 3D、复杂插画或持续动画；
- 为追求统一强行让手机和桌面使用相同排版；
- 在本规划阶段修改生产代码或上线。

## 23. 变更控制

以下变化需要先更新本文并由 Owner 重新确认：

- 一级导航、核心内容类型或页面职责变化；
- 浅色宋式水墨方向变化；
- 用户原文与 AI 派生内容的层级变化；
- 保存、同步和后台任务完成语义变化；
- 发生时间默认规则变化；
- 低状态、习惯或成长指标的评价方式变化；
- 触控、对比度、字体缩放等验收标准降低；
- V0.4.0 UI/UX 需求的范围、优先级或编号变化。

局部尺寸可在不破坏原则和验收标准的前提下通过原型测试调整，但必须记录调整原因。

## 25. 全站待审视清单

本节是设计阶段的审计 backlog，不表示列出的文字已经决定最终替换方案。每项必须
在对应页面进入开发前完成设计评审。

### 25.1 全局外壳

**当前问题**

- 一级导航、组内导航、页面标题和眉题经常重复说明位置。
- 桌面侧栏显示“本地持久化”“账户数据已隔离”和版本号等系统信息。
- 大量按钮使用 `＋`、`×`、`↑`、`⌄`、`↻`、`Ⅱ`、`■` 等字符模拟图标。
- 页面新增功能时通常新增独立卡片或整行按钮，缺少统一收纳规则。
- 页面标题有的直接，有的像标语，有的像开发说明，语气不一致。

**待审视**

- 一级导航是否足以表达位置，哪些页面可以取消眉题。
- 组内导航在手机上是否应缩减为当前页面标题与菜单，而不是常驻全部入口。
- 系统、版本和数据隔离信息应进入“关于、隐私或同步详情”，不常驻主导航。
- 所有字符图标迁移到统一图标库，并保留可访问名称。
- 页面进入、返回、切换分组和打开详情是否使用同一过渡与焦点规则。

### 25.2 欢迎、登录与注册

**当前问题**

- 首次启动直接出现“此刻、进入你的个人成长记录”和登录/注册表单。
- 新用户在创建账户前不知道产品解决什么问题、如何使用、系统如何理解自己。
- 登录与注册只是通用表单，没有体现此刻的气质和信任边界。
- 内测码、密码规则和错误可能成为首次体验的主要内容。

**待审视**

- 新用户先进入独立欢迎页和产品介绍，再决定注册或体验。
- 返回用户可直接登录，不重复播放介绍。
- 欢迎与登录之间保持同一品牌背景、字体和过渡。
- 注册只请求完成账户创建所需信息，其他资料后置。
- 密码、内测码、网络失败和账号冲突状态单独设计。
- 登录成功进入未完成的冷启动步骤或上次真实页面，不固定跳首页。

### 25.3 冷启动问卷

**当前问题**

- 当前“初次相识、先建立一份可以持续修正的认识、世界观、人生观与价值判断”
  与 8/18 题、可选资料在同一长页面出现。
- 题目虽不改内容，但字号、行长、选项密度和页面长度带来明显阅读压力。
- “快速版、详细版”使用紧凑分段控件，无法清楚表达耗时与选择差异。
- 可选资料默认展开，用户容易误以为全部都要填写。
- 问卷、资料导入、样例、预览和提交同时出现，任务焦点分散。

**待审视**

- 完整采用 8.8 节的欢迎、介绍、模式选择和逐题状态机。
- 每题只显示一个问题和四个大按钮。
- 问题内容逐字复用当前题库，先只调整排版、节奏与交互。
- 题目文本进行可读性检查，但未经新的内容研究不改变价值取舍含义。
- 自动切题、返回修改、保存恢复和减少动效完整设计。
- 可选资料改为问卷之后的独立选择，不默认展开。
- “预览初始认知”改为问卷完成后的自然步骤，不与提交按钮并列。

### 25.4 首页“此刻”

**当前问题**

- 首页视觉方向相对完整，但“记录思考、换一组、小物、状态、行动与习惯”仍可能
  形成多个竞争入口。
- 首次用户、少量数据用户和长期用户需要的首页内容不同。
- “行动与习惯”作为大块折叠内容可能重新把首页变成功能容器。
- 日期入口、随机内容和状态趋势之间的优先级需在不同数据量下验证。

**待审视**

- 首次使用完成后，首页是否先邀请完成第一条真实记录。
- 有内容后，首页保留一个主记录入口，其他动作降低层级。
- “换一组”只影响内容区域，不改变页面位置和其他草稿。
- 小物与状态参考在 320px、大字体和无数据时是否仍自然。
- 行动与习惯是否进入独立页面或上下文入口，而不是长期占据首页。
- 首页背景、内容密度和留白在手机与宽屏分别调整，不使用同一缩放版式。

### 25.5 “每日”与健康记录

**当前问题**

- 睡眠表单一次展示十余个字段，体重和运动也包含大量专业指标。
- “优先上传 1–2 张睡眠截图”“识别并回填”等功能说明占据首层。
- 上传、识别、核对、手填和历史趋势同时出现在一个大卡片中。
- “校正暂定”“95% 估计区间”“未显示字段留空”等说明密度高。
- 睡眠、心率、体重、运动模板内容长度差异大，切换时页面骨架容易漂移。

**待审视**

- 首先选择“上传截图”或“手动记录”，再进入对应流程。
- OCR 路径按“选择图片、识别、核对关键字段、查看更多、保存”分步。
- 手动路径只展示最常用字段，专业指标进入“更多指标”。
- 识别来源、校正规则和不确定性在核对详情中说明，不占据默认表单。
- 四种模板共享稳定标题栏、上传入口、内容起点和保存区。
- 图表与历史列表移到保存完成后的阅读区，避免与录入争夺注意力。
- “综合状态分”和固定公式是否符合“不把生活变成绩单”的产品原则。

### 25.6 “共参”

**当前问题**

- “今天，一起看看”“共参”“DeepSeek 长期对话”三层文字重复说明同一页面。
- 供应商名称进入默认界面，用户任务反而不够突出。
- 发生时间控件和发送框的关系不自然。
- 对话、来源、模型思考、回答和删除操作可能形成较高信息密度。

**待审视**

- 页面标题保留“共参”，删除重复标语或只在空状态使用。
- 默认不显示供应商名称，模型来源进入回答详情。
- 输入框固定在可达区域，发生时间作为紧凑上下文项。
- 用户问题、系统回答、引用来源和后续操作使用稳定消息语法。
- 不展示模型内部思考；只展示必要的来源、生成状态与限制。
- 空状态用一个真实问题示例帮助开始，不介绍全部能力。

### 25.7 “念起”

**当前问题**

- “碎片收集箱”和“先捕捉，不急着想完整”属于初版概念表达，长期固定显示会
  增加阅读负担。
- “此刻冒出来的东西”语气不够稳定，且与导航“念起”重复建立隐喻。
- “图片原文”“语音原件”把数据模型名称直接放入界面。
- “原音频与转写分层保存”“需要时展开麦克风控制”属于实现说明。
- 文字、图片、语音、标签、时间和保存被设计成并列模块。
- 列表项同时显示标签、时间、展开思考、编辑、删除、图片理解、播放和转写状态。

**待审视**

- 采用统一录入器，默认只保留输入面、媒体工具栏、时间项和保存动作。
- “图片原文”改为无标题图片预览，必要时使用“图片”。
- “语音原件”在录入态改为“录音”，详情中需要区分时使用“原音”。
- 数据分层说明进入隐私或详情帮助。
- 录音入口直接可用，不显示“展开麦克风控制”。
- 标签和手动时间进入更多信息。
- 列表项以内容为主，只保留一个与内容生长有关的直接动作。
- 编辑、删除、理解和转写等动作进入上下文菜单或详情。

### 25.8 “日记”

**当前问题**

- “日记助手”把系统放在用户写作之前。
- “把今天写清楚，不必写漂亮”虽有安抚意图，但“写清楚”仍可能制造要求。
- 五个写作引导、三个 AI 工具、正文、标签、草稿和保存同时展开。
- 侧栏“写的时候，可以留意”长期占据空间，像写作课程。
- “支持 Markdown”等能力说明进入主编辑流程。

**待审视**

- 页面直接使用“日记”，默认是一张安静的写作面。
- 标题可空，日期和标签降低层级。
- 写作引导在空白时按需出现，选中后收起。
- AI 引子、结构和话题收进同一辅助入口。
- 手动保存草稿与自动草稿的关系需要重新定义，避免两个保存概念。
- 写作侧栏改为可选引导，不在每次写作时持续教育用户。
- 阅读态与编辑态分开，旧回望在原文修改后清楚标明依据版本。

### 25.9 “思绪”

**当前问题**

- “主题思考”“从问题、初步想法，到回答”与页面结构重复。
- 每条思绪展开后同时出现回答、记录、想法、批注、保留、舍弃、编辑、追问、
  备注和删除，操作数量过多。
- “用户原文”“内容时间线”“最新在前”“版本”等实现与模板说明直接显示。
- “没有你的痕迹”等文案带有系统评判感。
- “给我回答”与人工回答、模型回答、思考过程和来源层级复杂。

**待审视**

- 列表只呈现问题、最近进展、时间和一个继续入口。
- 进入详情后按问题、我的想法、应答、追问和备注组织。
- “用户原文”只在与 AI 内容并列时显示一次，不贴在每个块上。
- 删除“内容时间线”和“最新在前”，用自然布局表达。
- 版本号进入历史或诊断详情。
- 高频动作限定为“继续思考”或“追问”，其他动作进入菜单。
- “保留、舍弃”的语义、后果和视觉重量重新验证。
- AI 回答必须标明来源，但不展示内部模型思考。

### 25.10 “寻迹”

**当前问题**

- 搜索、体裁、内容类型、“只看未回访”和“任意门”全部在首层。
- “任意门”有文化感，但不一定能让新用户理解是随机回看。
- “待回访、已稍后、已读、原始记录、命中数、尚无后续痕迹”等状态偏系统化。
- 每条结果同时提供转行动、明天再看和查看原记录。

**待审视**

- 默认先提供搜索与一个可理解的随机回看入口。
- 高级筛选收进筛选面板，并显示当前筛选摘要。
- “任意门”保留前必须通过理解测试；必要时配“随机回看”。
- 结果项先显示内容与来源，匹配细节按需展开。
- “回访”状态应帮助用户决定下一步，不评价用户是否留下痕迹。
- 行动转换和稍后提醒放入上下文操作。

### 25.11 “回顾”

**当前问题**

- 趋势、延迟相关、聚类、实验、自定义指标和 AI 复盘同时进入一个页面。
- “别急着得出结论”与大段方法说明长期占据首层。
- 汇总条、卡片、图表和多种操作形成仪表盘感。
- 当前实现存在“最新综合分”和固定 0–100 公式，与轻量状态参考原则冲突。
- “每周自动尝试，服务需运行”等研发运行信息对普通用户无意义。

**待审视**

- 先回答用户最可能关心的一个问题，再按需进入趋势、关系和复盘。
- 默认不显示综合分、排名或红绿评价。
- 趋势、关联、实验和 AI 复盘分成清楚的子任务。
- 方法和样本边界放在图表信息入口，不占据主阅读区。
- “相关不等于因果”必须保留，但用更贴近当前结论的短句表达。
- AI 复盘按需触发，后台运行状态进入统一任务系统。

### 25.12 “书间”

**当前问题**

- 初始页同时出现封面、信息识别图、交换按钮、识别按钮和完整书目表单。
- “信息识别图”是实现语言，新用户难以理解为何要两张图。
- 新建书目、书架、随机笔记和详情使用多套视觉模板。
- 收藏使用星星和萌芽 emoji，与全局图标系统不一致。
- “随机精选”“偶遇旧笔记”“阅读时间线”等栏目名称较多。

**待审视**

- 新建书目先选择“拍封面、扫描信息、手动填写”之一。
- 图片角色在选择后解释，不默认展示两块上传区域。
- 书架、详情和记录编辑统一内容对象结构。
- 收藏状态使用统一图标和明确名称，不使用 emoji 表达唯一语义。
- 随机回看只保留一个稳定名称。
- “支持 Markdown 与 LaTeX”等能力移入编辑器帮助。

### 25.13 “拾句”

**当前问题**

- “善言收集”和导航“拾句”重复命名。
- 漂浮气泡、随机位置和持续动画可能打断阅读，并与产品的安静原则冲突。
- 随机展示、录入表单和时间线同时出现。
- 来源、内容、标签、时间全部作为完整表单展开。

**待审视**

- 以句子阅读为主，背景和动画不能抢夺注意力。
- 删除重复眉题，统一使用已确认名称“拾句”。
- 新增入口按需打开，不与回看内容长期并列。
- 来源是重要证据，应清楚但不压过正文。
- 随机换一组必须由用户触发，不自动漂浮或滚动。
- 长句、无来源和多来源情况单独设计。

### 25.14 “小物”

**当前问题**

- “小物收集、留下形状，放下实物、新建留存、轮廓陈列、数字留存”等多组概念
  同时存在。
- 批量上传、轮廓编辑、自动分割、边缘调整、预览和元信息形成专业编辑器。
- “主体清晰、环境淡显”“场景边缘”等实现或效果说明可能不易理解。
- 首次用户与高阶编辑用户看到近似复杂度。

**待审视**

- 默认先展示真实小物和一个添加入口。
- 添加流程按选择图片、确认主体、填写名称、保存分步。
- 自动识别优先，手动轮廓工具只在结果不理想时出现。
- 批量处理与单件编辑共享同一结构，不出现两套操作语言。
- 工具按钮统一图标、尺寸和 tooltip。
- 页面标题收敛为一套，诗意标题必须不妨碍任务理解。

### 25.15 “我的”、账户与设置

**当前问题**

- “我的”同时包含账户、统计、通知、回收站、导出、个人概要、治理中台、AI 成本、
  架构设计、设置、商业化、反馈和关于。
- 普通用户能力、个人透明度、开发测试和 Owner 管理工具混在同一层级。
- 菜单每项都有副标题，页面视觉像设置功能目录。
- 设置中直接展示本地测试模式、DeepSeek API、Lite/Mid/High/Ultra、模型和
  思考强度、API 密钥与测试连接。

**待审视**

- 普通用户默认只看到个人概要、数据与隐私、同步、通知、回收站、设置、反馈和关于。
- 架构、商业化、治理、本地测试、供应商密钥和模型档位进入独立管理端。
- AI 使用透明度可以保留，但不等于展示供应商调试面板。
- 菜单副标题只在名称无法说明后果时保留。
- 账户安全与普通偏好分组，不让测试配置成为“设置”首页。
- 生产环境通过角色和构建配置隐藏管理入口，而不是只用 CSS 隐藏。

### 25.16 统计、AI 成本、架构与商业化

**当前问题**

- “多供应商服务用量看板”、Token、缓存命中、输入未命中、推理费用等属于运营
  或工程信息。
- AI 成本页要求用户理解模型档位、计价时段和 Token。
- 架构页展示 ECS、RDS、Redis、MQ、WAF、ALB、RPO/RTO 等内部技术规划。
- 商业化页展示用户画像、CAC、流失、现金流、合同负债和调研预算。
- 这些页面目前从普通“我的”直接可达。

**待审视**

- 明确三种界面：个人使用界面、个人透明度界面、Owner 管理界面。
- 普通用户统计只回答“我留下了什么、哪些内容正在处理、是否接近个人用量限制”。
- 供应商、Token、成本拆分和调用明细进入 Owner 管理端。
- 架构和商业化页面不进入普通产品导航。
- 管理页面可以保持高信息密度，但仍使用统一组件、排版和可访问性标准。
- 管理端与普通端共享品牌 token，不共享相同的信息架构。

### 25.17 个人概要、来源与 AI 边界

**当前问题**

- “当前语境、有据可查、系统目前如何理解你、用户事实、用户观点、模型摘要”等
  概念同时出现。
- 来源、版本、Token 上界和生成时间可能让普通用户先看到系统结构，而不是理解。
- “只读”与用户可修正原则之间可能形成预期冲突。

**待审视**

- 默认先呈现简短、可理解、带不确定性的当前认识。
- 来源、时间和置信度通过“为什么这样理解”进入。
- Token、内部版本和生成预算只进入管理或诊断详情。
- 如果当前版本只读，必须提供明确的纠正路径，而不是只显示“只读”。
- 用户事实、用户观点和模型摘要的区别用普通中文解释一次。
- 删除来源后，界面要说明哪些理解随之失效。

### 25.18 通知、同步、导出与回收站

**当前问题**

- “通知”实际主要承载后台任务，名称与普通社交通知心智不一致。
- 同步状态包含 P95、毫秒、队列等潜在技术信息。
- 导出默认强调 JSON、Markdown、快照版本和模型内部推理排除。
- 回收站整体较清楚，但仍混入附件引用、保留期标记等实现说明。

**待审视**

- “通知”是否改为“处理进度”或与普通提醒分开。
- 同步首层只显示已同步、待同步、需要处理；性能数据进入诊断。
- 导出先让用户选择“完整备份”或“可阅读文档”，格式放到下一层。
- 回收站首层说明剩余保留时间和恢复动作，技术引用进入详情。
- 批量永久清理继续使用明确二次确认，不以颜色作为唯一警告。

### 25.19 评论、批注与文本选择

**当前问题**

- 选中文字后同时出现评论、善言、划线、加重，缺少主次。
- “评论漂流箱、失效评论、原文已变化、删除漂流记录”等概念需要学习。
- `@神鸡`、模型回答、回复、转换类型和更多菜单混在同一批注卡片。
- 插图仍使用“图片原文”。

**待审视**

- 文本选择工具控制在最常用的 2 至 3 项，其余进入更多。
- “评论”与“批注”的名称统一。
- 原文变化后的批注用普通中文解释“暂时找不到原位置”，不创造新术语负担。
- 助手入口是否需要独立名称，必须遵循命名单一事实来源。
- AI 回复与用户回复视觉分层，来源只在需要辨认时显示。
- 评论中的图片沿用统一媒体组件。

### 25.20 图片、音频与媒体查看

**当前问题**

- 图片在不同页面使用“图片原文、原图、截图、识别图、封面”等多套组件。
- 音频上传、录音、播放、转写、整理和朗读使用多组控件。
- 图片查看器和页面缩略图的标题、计数、错误状态可能不一致。
- 当前字符按钮与原生播放器在视觉上不属于同一体系。

**待审视**

- 建立统一媒体附件组件，按图片、录音、文件配置能力。
- 媒体名称根据任务使用“图片、截图、封面、录音”，不用数据层术语。
- 查看器统一加载、失败、前后切换、缩放、关闭和焦点恢复。
- 音频统一播放、暂停、时长、倍速和转写入口。
- 图片理解、OCR 和 ASR 是处理动作，不改变原始媒体身份。
- 媒体删除必须说明影响草稿、已上传对象还是整条记录。

### 25.21 动态状态、空状态与错误

**当前问题**

- 动态代码中存在大量独立状态文案和 toast，语气、信息顺序和恢复动作不一致。
- 部分错误直接暴露 ASR、API、供应商或接口概念。
- 空状态有的诗意、有的技术化、有的带教学段落。
- 同一“已保存”可能表示本地、服务端或后台任务完成。

**待审视**

- 将所有动态文案映射到第 9 节七类状态。
- 为每种异步链路建立状态转换表和文案表。
- 空状态统一为“现状、正常性、一个下一步”。
- toast 只承担无需决策的短反馈。
- 冲突、权限、删除和不可恢复失败使用持久界面。
- 禁止只显示“失败、异常、未知错误”。

### 25.22 视觉一致性与技术债

**当前问题**

- 当前样式存在大量页面专用按钮、动作和控制类。
- 圆角值、直接颜色、阴影、边框和卡片规格分散。
- 相似模板切换时，标题、按钮、字段和状态区可能因文案长度改变位置。
- 同一图标动作使用字符、emoji、文本和不同尺寸。

**待审视**

- 建立真实组件 inventory，逐个标记保留、合并、废弃和迁移页面。
- 建立语义 token，禁止页面新增未经登记的颜色、圆角和阴影。
- 对同类模板建立共享 DOM 结构和组件，不只复制 CSS。
- 为关键组件增加几何快照，切换状态差异上限为 1px。
- 统一图标、焦点、按下、禁用、加载和错误表现。
- 迁移完成后删除旧组件和兼容样式，避免永久双轨。

### 25.23 审计交付格式

每个页面需要一张审计表：

| 字段 | 内容 |
| --- | --- |
| 页面任务 | 用户来这里完成什么 |
| 当前首要内容 | 第一眼看到什么 |
| 当前首要操作 | 默认最突出动作 |
| 应保留 | 已经清楚且符合产品的内容 |
| 应删除 | 重复、无价值或实现证明文字 |
| 应重写 | 必要但表达不合适的文字 |
| 应后移 | 只在详情、更多或帮助中出现 |
| 仅管理端 | 普通用户不应访问 |
| 缺失状态 | 尚未设计的空、加载、失败或恢复状态 |
| 组件偏差 | 与统一组件不一致的尺寸和样式 |
| 多端风险 | 手机、桌面、键盘、横屏和大字体问题 |
| 验收任务 | 可以验证改进是否成立的用户行为 |

全站审计完成前，不以“文案以后再调”作为页面设计通过条件。

## 26. 当前结论

V0.4.0 不应继续以“补一个功能区、加一个按钮、再套一个容器”的方式演进。设计
工作应先建立信息架构和统一视觉语法，再重构高频录入、系统反馈、内容回看与首次
使用，最后通过全端可访问性和真实用户任务验收。

最终目标不是让页面“看起来做过设计”，而是让用户在每一个时刻都能回答：

1. 我现在在哪里；
2. 我在这里最主要能做什么；
3. 我的内容是否已经安全；
4. 系统还在处理什么；
5. 我怎样回到自己的原始内容并修正系统。

当这五个问题不需要用户思考，视觉语言又能稳定表达此刻的克制、安静和可信，
V0.4.0 的 UI/UX 才算真正完成。
