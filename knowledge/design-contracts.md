# 设计职责、领域边界与数据访问契约

修订：2026-10-17，Owner 已批准，接入 develop 后生效。本文是长期复用、领域协作、实体访问、事务、记录级同步和按需加载的唯一正文；其他入口只引用。现状实现不因本文更新自动视为达标。

## 复用与领域职责

可靠复用必须同时满足：模块职责清晰，实际输入、输出、副作用、错误、权限及生命周期行为与承诺一致。复用前核对真实消费者和既有实现，不仅比较函数名或类型。

按稳定业务能力划分领域。领域拥有自己的实体规则和公开查询／命令接口；跨域流程由应用服务组合这些接口，不穿透私有存储、不复制业务规则。共享能力只承载确有共同消费者的机制，不收纳多个领域的完整业务集合。

公共契约变更先核对生产者、存储／转换、读取和真实消费者，明确兼容及接入顺序。模块清单与依赖方向见[模块设计](modularization-design.md)；并行写集见[协作协议](../SOP/multi-agent-orchestration.md)。

## 身份、配置与附件

- 按会话令牌精准查询必要用户和会话信息，校验有效性及撤销状态；认证不能默认加载全部账户或会话。后续读写使用服务端确认的账户身份，不信任请求自报的归属。
- 业务入口通过专用配置装配服务取得本业务 schema；该服务复用底层配置查询，集中完成按需读取、装配、校验和过滤，并在同一次操作内合并重复读取，不将这些职责散落到各业务入口。仅在确需登记评分等任务时读取相应配置，不引入跨账户或无限期配置缓存。
- 无附件的命令跳过附件查询；有附件时仅查询本次路径／ID及必要归属、有效性，不扫描整个附件集合。

## 实体与读取边界

需要独立查询、关联、授权、更新或生命周期管理的数据，应有明确实体键和关联。单条记录的附属配置、模型结果可以使用 JSON；禁止的是账户级大文档读改写，不是 JSON 格式本身。

普通在线局部增删改禁止“全读账户／域、内存修改、清空后重写账户或无关集合”。全量导入、灾备恢复、迁移或派生重建必须走专用流程，明确覆盖范围、恢复点与验证，不得作为普通业务的静默回退。

按场景限制查询：

| 场景 | 必要约束 |
| --- | --- |
| 账户私有列表 | 账户、筛选条件、稳定排序、游标／分页上限；不要求单条 ID |
| 单条详情 | 账户与记录 ID，读取必要关联；版本仅在缓存核验等契约需要时使用 |
| 批量详情 | 账户与有上限的 ID 集合，逐项处理缺失或无权访问，不退回全域读取 |
| 条件更新 | 账户、目标键及所需版本条件／锁，检测冲突，不覆盖别人的新状态 |

可能大量返回的列表必须在数据库查询阶段分页；非数据库适配器须在拥有数据的索引层提供等价有界读取。稳定排序应有唯一键消除并列歧义，后端配置限制单页上限，前端实际使用分页。禁止先全读再内存切页；批处理／导出可以使用内部游标分批。

## 命令、事务与校验

一次命令只处理本次业务闭包：目标实体、必要子项、幂等结果、同步变化及确需登记的任务。不扫描或改写无关记录，不通过批量重写旧 position 变相清写集合。

前端编辑不持有数据库锁；请求确认落库后，在短事务内取得适合一致性边界的锁或使用版本条件更新。新记录通过唯一约束与幂等键处理竞争和重复请求，冲突须按身份／幂等契约处理，不能静默覆盖已有记录。

校验变化字段及受其影响的不变量。例如改结束时间仍需核对开始时间，新增追问仍需核对父思绪归属；不校验本次操作不会影响的无关历史。必要实体、幂等结果、同步变化和任务登记原子提交。

模型调用、完整上下文扫描及其他耗时操作不占据保存事务；其结果以来源 ID／版本和幂等约束另行短事务写回，防止迟到结果覆盖新内容。

## 记录级同步与缓存

同步返回变化记录的完整实体标识、版本、必要摘要、删除标记及游标／恢复信息。域名可以分类路由，不能据此传输、替换整个集合。任务、通知、统计和聚类各自提供必要变化或概览，不随一个业务变化附带其他业务的完整集合。

客户端使用实际唯一性范围内能完整标识实体的键维护唯一实体缓存：包含账户、实体 ID，以及区分实体所必需的实体类型／集合和父对象完整标识；不得假定不同体裁或不同父对象下的 ID 全局唯一。版本用于判断同一实体的新旧，不作为实体身份的一部分。更新可以采用不可变方式；不无限积累增量并每次渲染反复重放。重复消息幂等处理，旧响应不得覆盖新状态，删除需同步处理详情和列表成员关系。

账户切换、退出、会话失效后，清理或隔离相应缓存与订阅；进行中的异步响应必须核对账户／会话及页面生命周期，失效结果不得写入新账户或新页面。

游标失效时，先使受影响同步范围的旧缓存／分页成员关系失效，不再把未核验页面当最新；优先重取当前分页、指定详情或受控首屏，其他页面使用时再校验或重取。可保留的离线材料明确标为陈旧；不退回整账户快照，也不因此丢弃待提交草稿。

全量快照用于明确的初次离线数据导入、灾备恢复／迁移，以及经评估的旧客户端兼容回退；须限定账户、字段、体量／分批方式、触发条件和退出办法，保留待提交写入并核对版本。普通在线写后刷新和跨端更新优先使用记录增量；游标失效按上文有界恢复，不自动升级为整账户快照。快照是专用流程或明确兼容边界，不作为局部读写失败的通用回退。

## 列表、详情与首屏加载

列表只返回足够呈现的摘要，如标题／正文预览、时间、版本、媒体状态和必要计数。追问、批注、引用全文及大正文留给详情接口；用户展开后按 ID 获取。字段粒度以场景和载荷为依据，不为省几个小字段制造大量接口或请求。

后台各领域查询能力必须独立复用；网络层允许受控批量或首屏组合接口，只装配已有查询结果，限定页数、载荷和并发，不复制业务逻辑。新增接口前先核对已有能力，避免语义相同、各自维护的接口。

今日首屏优先；所见、所思及思绪／循迹／日记／回顾等入口的首屏摘要按近期使用、入口可见性分级预取，设并发与总载荷预算。约 20 条可作可调默认值，不要求所有页面固定相同数量。主动切换时立即提升目标页优先级，不等待无关预取完成。

分别验证刷新后的真实首屏、预取完成后的页面切换，以及开屏后立即切换而尚未完成预取的路径；时延从用户刷新／导航动作起算。骨架、隐藏 DOM 或重置计时不能代替可读内容。具体性能目标绑定需求及候选，不在通用规则重复硬编码。

## 交互状态与性能审查

局部保存、同步及后台更新不得重建无关页面或丢失草稿、焦点、光标／选区、滚动位置、展开状态、录音／播放及进行中的操作。导航、卸载和账户切换按真实生命周期取消或交接任务，并保存应保留的本账户状态；不要把“清理”解释为无差别重置。

高频业务先审实体和关联，再列最小必要查询、写入及事务，给具体场景设置预算。分别衡量 SQL 条数、网络往返、扫描／改写行数、锁等待、载荷和端到端时延；不统一规定所有业务的 SQL 次数，也不把多条无关操作塞进巨大语句当优化。单记录操作成本不应随无关账户历史线性增长。

## 迁移与验收边界

旧整域读写和全读后裁剪属于迁移现状，不冒称满足新契约。相关切片沿真实消费者逐步迁移；未满足本轮验收的部分如实记为失败、待验证或 partial，只有实际阻止下一动作时标为 blocked。

范围外存量债记录明确去向，不自动阻断所有版本；仍影响当前行动的缺口保留在控制面及候选回执。代码 partial 授权和标记仅见[源码规范](source-documentation-rules.md#partial-提交治理)。本契约不授权全仓 ORM、微服务迁移或无依据的接口拆分。
