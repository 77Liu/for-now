# 新功能开发上线自查清单

适用时机：功能开发和测试已经完成，准备提交、发布或部署前。

阶段顺序、授权核对、证据失效、部署后观察和关闭统一按 `SOP/release-and-observation.md` 执行；本文只负责详细检查项。

使用规则：

- 标记为 **阻断** 的项目未通过时不得上线。
- 不适用的项目填写 `N/A`，并写明理由，不能直接跳过。
- 每个结论应附测试结果、截图、日志样例、接口响应、文档或提交等可复核证据。
- 清单确认的是“可上线”，不能替代代码审查、测试和部署后的验证。
- `npm run commit:feat` 只允许门禁认可的低风险单域改动形成本地提交；自动提交不代表本清单通过，push、tag、Release、部署和生产写入必须同时满足发布自动授权策略与控制面记录。
- 夜间队列的动作仍受 `SOP/night-continuous-development.md` 和控制面限制；未记录有效自动授权策略时，只能执行其中明确允许的 Preview 动作。正式 tag、Gitee Release、`main` 和生产动作不得凭夜间队列自行推断授权。

## 0. 范围、复用与架构

- [ ] **阻断** 已搜索现有模块、公共组件、API、数据结构和工具，没有重复实现已有能力。
- [ ] **阻断** 同一业务概念只有一套权威实现，例如评论、上传、认证、模型调用、Markdown 渲染和时间处理没有形成平行系统。
- [ ] 新增抽象确实消除了复杂度或高风险重复，不是为了预想中的未来需求。
- [ ] 改动范围只覆盖当前需求及必要条件，没有夹带无关重构、格式化或元数据变更。
- [ ] 新功能遵循现有模块边界、命名、错误表达和状态更新方式。
- [ ] 已确认不会因一次局部操作重绘无关页面、清空输入、折叠内容或丢失滚动位置。

### 0.1 模块边界与跨模块影响

- [ ] **阻断** 已按 `knowledge/modularization-design.md` 确认主模块、公开契约和允许依赖，没有跨模块深层导入、私有状态修改或反向依赖。
- [ ] **阻断** 已逐行核对跨模块修改影响矩阵，所有命中的生产者、消费者、数据、权限、日志、测试和文档均已纳入改动或明确写明 `N/A` 理由。
- [ ] 新增、拆分、合并、重命名模块或改变职责时，模块登记、公开入口和设计文档已在同一任务中更新。
- [ ] 公共契约或共享模块只有一个明确负责人；并行任务没有同时修改同一模块内部实现。
- [ ] 兼容入口、迁移例外和重复实现均有负责人、删除条件与回归测试，不会成为永久双实现。
- [ ] 模块化提交只改变结构；如同时需要行为变化，已拆成独立可验证提交或明确说明无法拆分的原因。
- [ ] **阻断** `npm run check:modules` 已通过；如该命令尚处于 P0M 建设阶段，已记录对应迁移任务和当前人工检查证据。

## 1. 操作日志与系统日志

- [ ] **阻断** 所有关键写操作均有操作审计记录：操作者、时间、动作、资源类型与 ID、结果、失败原因、请求或追踪 ID。
- [ ] 涉及编辑、删除、权限或配置变化时，日志能识别变更前后差异；敏感正文只保存必要摘要或受控快照。
- [ ] **阻断** 服务端异常、外部依赖失败、超时、重试、后台任务失败和数据持久化失败均进入系统日志。
- [ ] 系统日志包含时间、级别、模块、请求或追踪 ID、状态码、耗时和可定位的错误栈。
- [ ] 前端关键失败对用户有可恢复提示，同时服务端保留足够诊断证据；没有静默吞错。
- [ ] 日志级别合理，正常流量不会大量输出错误级日志或造成明显 I/O 压力。
- [ ] **阻断** API Key、密码、Cookie、会话令牌、邀请码和其他凭据不会进入任何日志。
- [ ] 日志已定义访问权限、保存位置、保留期限、轮转、清理和备份策略。

## 2. AI 调用审计

- [ ] **阻断** 所有 AI 调用统一经过现有模型调用层，没有绕过公共日志、用量统计和错误处理。
- [ ] **阻断** 每次调用保存唯一调用 ID、追踪 ID、用户或账户、业务场景、开始与结束时间、状态和耗时。
- [ ] **阻断** AI 审计记录包含实际请求内容、SP、UP、历史消息或上下文、最终响应，以及存在时的 `reasoning_content`。
- [ ] **阻断** 记录供应商、模型及版本、档位、思考开关与强度、温度、最大 Token、响应格式、流式设置等实际生效参数。
- [ ] **阻断** 记录输入 Token、缓存命中与未命中 Token、推理 Token、回答 Token、总 Token、结束原因和官方原始 `usage`。
- [ ] 记录请求次数、重试次数、降级路径、取消或中断状态；发生重试时每次实际调用独立计数。
- [ ] 记录当次单价快照、币种、计费时段和费用拆分，后续调价不会改写历史费用。
- [ ] 流式响应在完成、断流、用户关闭界面和后台继续生成等路径下都能正确落账。
- [ ] 无可靠原始 `usage` 的历史调用不估算回填；缺失数据明确标记为未知。
- [ ] **阻断** 完整 SP、UP、用户上下文和响应存放在专用 AI 审计存储中，不混入普通系统 stdout。
- [ ] **阻断** AI 审计数据按用户隔离，并定义加密、访问授权、导出、删除、保留期限和脱敏策略。
- [ ] **阻断** API Key、认证令牌和不应发送给模型的私密数据未进入请求或 AI 日志。
- [ ] 失败、内容过滤、超时、长度截断和供应商异常能从日志中区分，费用与调用状态不会被误判。

## 3. UI、交互与可访问性

- [ ] **阻断** 新 UI 与现有颜色、排版、间距、圆角、控件、图标和信息密度一致。
- [ ] 桌面、窄屏和移动端均已实际检查，无横向溢出、文字截断、元素重叠或固定导航遮挡。
- [ ] 已覆盖加载、空数据、成功、失败、禁用、处理中、部分完成和重试状态。
- [ ] 动态内容不会引起不可控布局跳动；固定格式元素有稳定尺寸和响应式约束。
- [ ] 控件类型符合用途：模式用分段控件、布尔值用开关或复选框、数值用输入或滑杆、工具操作优先使用熟悉图标。
- [ ] 键盘可操作，焦点顺序合理，必要的标签、状态播报和对比度符合可访问性要求。
- [ ] 文案清楚且与真实能力一致，不夸大、不隐藏限制，也不把说明书堆在主界面。
- [ ] 页面更新保持输入、选择、展开状态和滚动位置，不因保存无关数据而重置。

## 4. 功能完整性与业务规则

- [ ] **阻断** 验收标准逐条满足，主流程已由真实操作验证。
- [ ] 输入校验覆盖空值、边界值、非法格式、超长内容、重复提交和不允许的状态转换。
- [ ] 创建、读取、编辑、删除及必要的撤销或恢复路径完整，操作结果与页面状态一致。
- [ ] 重复点击、刷新、网络重试和客户端重放不会生成不可接受的重复数据。
- [ ] 并发操作、后台任务和异步完成不会互相覆盖、锁死或写入错误账户。
- [ ] 时间、时区、日期归属、排序和跨午夜行为符合项目统一规则。
- [ ] 失败后用户可以安全重试，已成功保存的数据不会因后续步骤失败而丢失。
- [ ] 外部服务返回值经过结构和边界校验，不能把推断、空响应或异常字段直接当成用户事实。

## 5. 数据、迁移与兼容性

- [ ] **阻断** 新增或变更的数据结构已有明确版本、默认值和旧数据兼容策略。
- [ ] 数据迁移可重复执行、不会破坏原数据，并在必要时先生成备份。
- [ ] 已用真实旧版本样本验证迁移；不能只测试全新空库。
- [ ] 创建时间、发生时间、更新时间和审计时间语义清晰，不互相覆盖。
- [ ] 删除主记录时，附件、索引、批注、引用和派生数据的处理规则明确。
- [ ] 回滚代码后旧数据仍可读取，或已准备经过验证的数据回滚方案。
- [ ] 大数据量下已考虑查询范围、分页、聚合成本、文件增长和磁盘占用。
- [ ] 多用户环境中，数据文件、附件、缓存、队列和日志均按账户正确隔离。

## 6. API 与前后端契约

- [ ] **阻断** 请求参数、响应结构、状态码和错误码有稳定定义，前后端使用同一契约。
- [ ] 服务端不依赖前端校验，所有外部输入均再次验证。
- [ ] 老页面访问新服务端、新页面访问旧服务端的兼容或失败方式已经明确。
- [ ] 流式接口验证了正常结束、服务端报错、客户端断开、超时和半途取消。
- [ ] 写接口具有正确的认证、授权、账户隔离和跨站请求保护。
- [ ] 接口没有返回密钥、内部路径、错误栈、完整日志或不必要的个人数据。

## 7. 安全与隐私

- [ ] **阻断** 已验证未登录、越权、跨账户和直接猜测资源 ID 的访问会被拒绝。
- [ ] **阻断** 已检查 XSS、注入、路径穿越、SSRF、CSRF、开放重定向和不安全文件上传等适用风险。
- [ ] 富文本、Markdown、链接、文件名和模型输出在展示前经过安全处理。
- [ ] 文件上传校验 MIME、扩展名、大小、数量和存储路径，不能覆盖任意文件。
- [ ] 敏感配置只来自受控环境或权限受限的数据文件，不进入 Git、前端包或错误响应。
- [ ] 收集的数据是功能所必需的，并明确用户查看、导出和删除路径。
- [ ] 新增第三方服务时已核对传输内容、数据驻留、隐私条款、超时和故障影响。

## 8. 性能、容量与韧性

- [ ] 页面首屏、关键操作和大数据量列表的耗时在可接受范围内。
- [ ] 没有明显重复请求、N+1 查询、全量重绘、无限数组增长或无上限日志增长。
- [ ] 外部请求设置合理超时；重试有次数、退避和幂等边界，不会放大故障或费用。
- [ ] 后台任务失败不会阻塞前台记录，也不会产生无限重试。
- [ ] 服务重启、请求中断和磁盘写入失败后的状态保持一致。
- [ ] 已评估 CPU、内存、磁盘、附件和日志增长，必要时有告警阈值。

- [ ] **阻断｜自 V0.4.0 起** 每个功能切片在实现与提交时已运行受影响的

  验收，候选变化后已按证据失效范围重跑。

- [ ] **阻断** 已运行项目规定的语法检查和主回归，结果实际通过。
- [ ] 改动涉及认证、数据迁移、共享组件、页面主流程或模型调用时，已运行对应专项回归。
- [ ] 新增行为至少有一个成功路径和一个关键失败路径的自动化断言。
- [ ] Bug 修复有能在修复前失败、修复后通过的回归断言。
