# 一人产品与人—Agent 敏捷开发标准

- 标准编号：`STD-DEV-001`
- 版本：`1.0`
- 生效日期：`2026-10-04`
- 状态：生效
- 适用范围：产品需求、设计、开发、测试、审查、发布、热修与复盘

本文档是项目开发生命周期、阶段状态和门禁定义的单一事实来源。具体操作步骤
由 `SOP/` 承载；工程、测试、发布、设计和运维的专业规则继续维护在各自文件，
不得在本文重复形成第二套细则。

本标准以“一人产品与人—Agent 高效敏捷开发方法论”为基础完成项目化落地，
正文已包含执行所需的完整流程，不依赖仓库外文件。后续方法变化先更新本文及
变更记录，再调整各阶段 SOP。

## 1. 标准主流程

项目统一使用：

```text
需求收集
→ 本轮需求冻结
→ 开发规划与风险验证
→ 共享底座串行 / 独立功能按需并行
→ 集成审计与验收
→ 上线与观察
→ 复盘
→ 回流需求池与工程规则
```

持续测试、审查、证据维护和范围控制贯穿全程，不是开发结束后的附加步骤。生产
异常进入热修旁路：

```text
异常发现 → 判断影响 → 回滚或临时止损 → 最小修复
→ 针对性验证 → 发布观察 → 补回归与复盘
```

低风险小任务可以用一张任务卡承载多个阶段，但不得省略适用门禁的结论与证据。
高风险迁移、认证、权限、持久化、外部供应商和生产变更必须扩大验证，不能因
工期压缩门禁。

## 2. 核心原则

1. **一轮一个主要目标**：以一个可观察的用户结果组织本轮范围。
2. **小批、精准、高频**：每批解决清楚的问题，尽快形成反馈，再决定下一批。
3. **冻结承诺，不冻结证据驱动的方案**：本轮目标、范围和验收固定；实现方案
   可因新证据调整，调整后同步影响与验证。
4. **验收前移**：开工前写清成功、失败、中断、恢复、权限、持久化和体验结果。
5. **共享底座串行，独立功能按需并行**：并行度由契约、文件和测试资源隔离
   决定，不由可用 Agent 数量决定。
6. **证据先于状态**：没有绑定对象、环境和实际结果的证据，不得推进完成状态。
7. **候选、发布、观察分开**：本地通过、候选已验收、已发布、观察已关闭不能
   混写。
8. **人保留高风险决策，Agent 保持授权内连续执行**：目标、范围、不可逆操作、
   权限和发布由 Owner 决定；常规实现选择由 Agent 在契约内完成。
9. **只沉淀可复发、可行动的问题**：优先用代码、测试和工具消除问题，再增加
   必要规则。

## 3. 阶段与门禁

| 阶段 | 门禁 | 最小产出 | 通过条件 | 责任 |
| --- | --- | --- | --- | --- |
| 需求收集 | `G0 需求可进入` | 问题、场景、来源证据、候选价值、最小结果 | 能说明谁为什么需要，事实与解释已分开 | 产品责任 |
| 本轮冻结 | `G1 范围已冻结` | 主要目标、做/不做、验收、兼容约束 | 范围可控，完成与失败可判断 | Owner 决策 |
| 开发规划 | `G2 开发已就绪` | 方案、依赖、所有权、风险验证、测试与恢复路径 | 关键依赖可用，任务可执行，授权清楚 | 技术/执行责任 |
| 小批开发 | `G3 切片已完成` | 代码/文档、相关测试、审查结论、任务证据 | 满足切片验收，无未声明依赖或阻断 | 执行者 |
| 集成审计 | `G4 候选已验收` | 固定候选、完整路径、真实依赖、恢复证据 | 功能、兼容、权限、数据和恢复要求通过 | 集成与独立审查 |
| 上线准备 | `G5 最终 GO` | 影响矩阵命中验证、发布记录、备份、回滚、观察条件 | 阻断项关闭，授权范围和执行对象可核对 | Owner/协调者 |
| 上线观察 | `G6 发布已关闭` | 标签/Release、运行版本、冒烟、监控、观察结论 | 生产关键路径正常，达到观察退出条件 | 发布责任 |
| 复盘 | `G7 迭代已关闭` | 目标效果、过程事实、行动项、规则/需求回流 | 结论有证据，行动有归属和验收 | Owner |

门禁不通过时回到最近一个能消除问题的阶段。不得通过修改状态文字、降低断言、
删除失败测试或把阻断项改称“后续优化”推进。

## 4. 统一状态

需求、执行和发布是三个独立维度：

| 维度 | 标准状态 |
| --- | --- |
| 需求 | 待评估、待规划、待开始、进行中、待验收、已完成、暂缓、已取消、重复 |
| 执行 | 待排期、待开始、进行中、阻塞、待验收、已完成、已取消 |
| 发布 | 不适用、未发布、待发布、已发布、已回滚 |

状态必须描述实际对象。例如“代码已实现”不能写成“需求已发布”；Preview 通过
不能写成生产已观察；生产进程存活不能写成用户关键路径正常。

`G0-G7`、候选已验收、观察中和发布已关闭属于流程门禁或证据表达，不新增为
Base 单选值。需要表达这些阶段时写入计划、交付证据和发布记录。

## 5. 统一证据契约

每个门禁证据至少包含：

| 字段 | 要求 |
| --- | --- |
| 对象 | 需求 ID、任务 ID、完整提交 SHA、tree、标签或运行版本 |
| 基线 | 起点版本、分支/工作树状态及关联依赖 |
| 环境 | 本地/Preview/生产、系统版本、数据与身份类型 |
| 动作 | 实际命令、人工步骤或审查范围 |
| 结果 | 退出码、断言数量、观察值、截图或明确结论 |
| 时间 | 带时区的执行或观测时间 |
| 证据位置 | 报告、机器产物、日志、URL 或提交 |
| 未覆盖 | 未执行项、原因、风险、补验责任与条件 |
| 决策 | 通过 / 退回 / NO-GO，以及作出决定的责任角色 |

证据只证明所绑定的对象、环境和断言。代码、依赖、测试桩、配置、数据样本或
运行环境发生相关变化时，按影响范围失效并重跑；不得引用旧候选的全量通过证明
新候选。

## 6. 人—Agent 责任与授权

### Owner

- 提供或确认用户问题、主要目标、范围、验收和非目标。
- 决定商业数值、隐私承诺、不可逆数据操作、风险接受和发布窗口。
- 完成关键体验验收，明确 `G1` 与 `G5` 决策。
- 对复盘结论和下一轮优先级负责。

### 执行 Agent

- 读取规则、基线和已有改动，验证关键依赖。
- 在任务契约与授权范围内设计、实现、测试、修复并整理证据。
- 发现范围、公共契约、数据正确性、安全、费用或权限变化时立即升级。
- 不把建议写成用户事实，不把测试通过解释为发布授权。

### 审查与集成责任

- 核对目标、实际 diff、失败路径、公共影响和证据有效性。
- 高风险工作使用独立审查视角；审查结论必须引用具体对象与证据。
- 串行集成共享契约，维护固定候选和剩余风险。

同一人可以兼任多个角色，但必须分别留下决策、执行和审查证据。Agent 之间互相
声明“通过”不能代替可复核结果。

## 7. 任务契约

进入 `G2` 前，每个切片至少具备：

```markdown
任务 ID / 负责人 / 执行者：
目标与用户价值：
上下文入口与起始基线：
本轮做 / 不做：
允许修改的模块与文件：
共享契约、消费者与禁止越界范围：
用户旅程、成功/失败/恢复/副作用验收：
风险、预验证、测试环境与命令：
允许操作及必须升级报告的事项：
提交、集成、发布与恢复条件：
交付证据与未覆盖项：
```

任务按可验证用户路径拆分。预计超过项目规模阈值、跨共享热点文件或连续执行
超过规定时长时，按工程规则继续拆分并设置可恢复检查点。

## 8. 变更控制

开发中出现新信息时：

1. 不影响本轮目标、正确性、安全和兼容性：进入候选需求池，不扩当前范围。
2. 可在当前边界内解决：更新任务契约、验收和影响测试后继续。
3. 影响主要目标或门禁：暂停受影响任务，退回 `G1` 或 `G2` 重新决策。
4. 无法在本轮安全解决：缩小交付范围或重排迭代，由 Owner 记录取舍。

任何公共 schema、API、认证、配置、共享状态、依赖锁或部署接口变化，都视为
共享底座变化，由唯一负责人串行处理并通知消费者。

## 10. 例外

- **纯文档小改**：可以由一条任务记录承载 `G0` 至 `G3`；不涉及部署时发布
  状态为 `N/A`，仍需检查事实、链接、敏感信息和工作区范围。
- **探索原型**：按 `knowledge/exploration-release-track.md` 隔离，不能用
  探索通过替代生产 `G4` 至 `G6`。
- **热修**：按 `SOP/hotfix.md` 压缩路径，不免除生产授权、观察、补回归和复盘。
- **外部阻塞**：保留已完成证据，将状态标为阻塞并写明恢复条件；不得把无法
  验证写成通过。

## 11. 标准维护

- 修改阶段、门禁或状态模型时，先更新本文，再同步 `SOP/README.md` 和受影响
  SOP。
- 专业规则只在其单一事实来源维护；SOP 引用，不复制长期阈值和命令矩阵。
- 每次流程复盘只新增可复发、可执行的规则；可由自动检查替代后，应删除重复
  人工步骤。
- 标准变更记录到 `knowledge/iteration-history.md`，但历史记录不作为当前标准。
