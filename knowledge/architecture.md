# 本地应用架构

## 运行与数据

- `server.mjs`：无框架 Node HTTP 服务、JSON API、DeepSeek 调用、统计计算。
- `public/`：单页 HTML/CSS/JavaScript 界面。
- `data/store.json`：状态、每日健康记录、捕念、日记、思绪、对话、书目、小物、善言、实验与复盘的原始数据；当前结构版本为 v12。
- `data/llm-settings.json`：四档模型配置、逐场景档位映射与 API Key；当前结构版本为 v4，权限 0600，不返回页面明文。

应用本地运行于 `http://127.0.0.1:4173/`。所有模型能力走独立 DeepSeek API，不复用开发 Agent/Codex 线程。
日期归属使用运行设备的本地自然日，时间戳以 UTC ISO 格式持久化；页面显示时间固定采用 00–23 小时制。事件型记录同时保存不可变的创建审计时间 `createdAt`、可编辑的完整发生时间 `occurredAt`，以及从 `occurredAt` 按本地时区派生的日期索引 `occurredOn`。页面若跨过午夜且用户此前停留在“今天”，应自动切换到新的本地日期。

## 视觉设计语言

全站使用“雾白玻璃 + 石墨文字 + 低饱和功能色”。内容和记录是第一视觉层级，导航只提供稳定定位，不使用大面积深色背景与高饱和装饰。

- 基础色：页面为雾灰白，正文为石墨色，边框使用带少量绿色倾向的浅灰；卡片以 8px 圆角、细边框和轻阴影为主。
- 桌面导航：固定宽度 176px，使用半透明雾白、模糊和低对比边界形成毛玻璃质感；当前模块只通过浅色底、细指示条及模块强调色识别。
- 移动导航：同一导航在 920px 以下转为带安全区的浅色玻璃底栏；不得使用深色整栏，也不得遮挡页面、弹窗或批注面板。
- 模块色：今日青灰、捕念绿、日记陶土、思绪灰蓝、回顾冷青、读书橄榄、小物灰棕、善言赭金、设置石墨。模块色用于当前项、焦点、少量结构线，不大面积染色正文容器。
- 排版与密度：标题字距固定为 0；操作型界面保持紧凑，不使用营销式大卡片和过度留白。控件、时间线和固定格式元素须有稳定尺寸，桌面与移动端均不得产生横向溢出。

## 前端更新原则

首次启动可全量加载。写操作完成后重新获取状态，但只渲染受影响的数据域，不重绘整个页面：

- `thoughts`：只在思绪主体发生变化时刷新列表与标签，并保存根卡片和追问的展开状态。
- `captures`：只刷新捕念列表；正在编辑的捕念表单不得因其他数据域变化而清空。
- `journals`：只刷新日记列表并保留已展开日记；原文编辑表单和助手回望是两条独立操作。
- 评论与划线：选中文本后可创建需要文字内容的浅黄色评论，或无需填写内容的浅绿色划线。新增、回复和删除直接修补内存记录、对应锚点和右侧面板；不得调用 `refreshState("thoughts")`，也不得替换思绪卡片 DOM。
- 批注锚定：创建时同时保存选中文本、前后短上下文、原始位置和最多前后 1000 字原始上下文。编辑正文时先用“精确文本 + 邻近上下文 + 原位置距离”重定位；找到则平移，找不到则从有效批注移入根记录的 `annotationDrift`，完整保留评论、回复、神鸡对话与原始上下文。漂流项由用户显式删除。
- Markdown 正文统一使用“渲染后可见纯文本”作为批注坐标系；创建校验和编辑重定位都必须先去除 Markdown 结构标记，不得用源码字符位置直接匹配页面选区。
- 所有模型最终输出和声明支持 Markdown 的用户内容统一使用 `renderMarkdown` 后再执行 `renderLatex`，包括思考问题与初步想法、回答、追问问答、长期对话双方消息、神鸡问答、认知复盘、日记与回望、保存后的模型思考、捕念、书目简介和读书笔记。折叠摘要使用 `plainPreview`；编辑框保留源码；评论元数据、标签、来源和引用原文保持纯文本。
- `@神鸡`：评论和划线均可发起批注级 AI 对话，问答保存在对应 annotation 的 `shenji` 数组；返回后只更新当前侧栏卡片。上下文与人格规则见 `knowledge/prompt-architecture.md`。
- `checkins`：状态图表和滑块参考。
- `dailyRecords`：只刷新每日记录的当前类型历史与可视化；不得重绘“此刻”滑杆或清空其他表单。
- `chat`、`review`、`books`、`keepsakes`、`quotes`：各自独立刷新。

输入框、当前视图、滚动位置和无关区域不应因一次保存而重置。

图片输入共用格式校验、文件选择、剪贴板、拖放、预览、Data URL 转换、附件落盘和 Flash 图像调用链路，具体场景只替换识别提示词与 JSON Schema。书目录入包含两个独立图片槽位：封面图只用于书架展示并在保存时上传，信息识别图只回填可编辑元数据，不能自动成为封面；已有书目的元数据和封面可继续编辑。书目识别和心率接收 1 张，睡眠接收 1～2 张并合并解析；仅接受 PNG、JPEG、WebP，单张和单次合计均限制 8 MB，以确保 Base64 请求不超过服务端 12 MB 请求体上限。健康截图只回填可编辑表单，用户确认后才写入记录；截图缺少年份时，以用户当前所选日期推断最近年份，并在核验说明中显式标注。

书目保存独立的 `readingStartedOn` 与 `readingFinishedOn` 自然日字段：开始日期为新建必填项，结束日期允许为空且不得早于开始日期；旧书目兼容为空，不因增加字段升级存储版本。书籍详情页以笔记为主：轻微滚动后页面标题收拢至左上，随机精选笔记进入左侧，封面、标题、作者、简介及阅读日期缩为右侧摘要；该状态在当前书内保持稳定，返回书架后恢复展开标题。阅读时间线先于新增记录表单展示。

小物收集在 `keepsakes` 中同时保存原图路径 `originalPath` 与透明轮廓图路径 `cutoutPath`。DeepSeek Flash 只返回 0～1000 归一化多边形和非敏感名称，不转录票据正文；直接接触主体的少量手指可进入轮廓，但不得延伸至整手、手腕或手臂。浏览器 Canvas 将多边形栅格化并按 `edgeExpansion` 做小幅膨胀，随后允许用保留/擦除画笔修正；原图不参与蒙版破坏，放大查看默认展示原图。2C2G 服务端只负责视觉请求、文件和元数据持久化，不常驻图像分割模型。

异步 DOM 事件在第一个 `await` 前保存表单、按钮等节点引用，不得在异步恢复后继续读取可能已被清空的 `event.currentTarget`。时间线按 `occurredAt` 排序、按派生的 `occurredOn` 分组：同一日期只在组首显示一次左侧日期。善言的来源及思绪的标签放在内容卡片外上方左侧，时间和该层级的轻量操作放在同一行右侧；元信息不得占用正文卡片空间。编辑发生时间不得改写 `createdAt`。

## 模型交互

模型配置分为 Lite、Mid、High、Ultra 四档；每档分别保存 `model` 与 `effort`。思考草稿、思考回答、追问回答、长期对话、日记引子/结构/话题、日记回望、批注神鸡、认知复盘和书目识别分别保存所选档位，服务端按场景解析最终模型参数。旧的单模型设置首次启动时自动备份并迁移；书目图片因模型能力限制固定使用 Flash，但沿用该场景所选档位的思考强度。

“给我回答”统一使用回答弹窗和 SSE 流，依次显示整理上下文、模型思考、生成回答、回答完成四个阶段。DeepSeek 明确返回的 `reasoning_content` 在思考区流式展示；首个回答片段到达时自动折叠思考区，并在回答区继续流式渲染 Markdown/LaTeX。思考区仅在用户仍贴近底部时自动跟随；用户向上滚动后不得抢回滚动位置。

生成中的回答弹窗允许关闭。关闭只隐藏弹窗，不取消服务端请求；模型生成完成后仍须按原数据结构持久化、增量刷新对应区域并提示结果。`reasoning_content` 独立持久化为回答的 `reasoningContent`，仅供用户从回答旁的“思考”控件展开查看；不得混入最终回答正文，也不得进入完整追问链、长期个人语境、对话历史或认知复盘输入。

记录保存与自动回答是两条独立异步链：原始记录持久化成功后应立即清空并解锁录入表单，自动回答转入后台。每个后台任务只能禁用自己的触发控件，不得阻塞新的记录、追问或其他模型请求。

每次认知复盘均作为独立记录追加到 `store.analyses`，持久化 `id`、生成时间、触发方式、正文和模型思考，不覆盖历史结果。回顾页展示完整复盘历史及总数：最新记录默认展开，旧记录折叠但可随时回看。

回顾页顶部不展示单纯的内容总量，而展示可解释的行为信号：

- 近 7 日记录覆盖：状态、健康、捕念、日记、思考问题、长期对话、善言或读书笔记出现过任一种记录的自然日数，分母固定为 7 天。
- 近 30 日身心同日：同一自然日同时存在“此刻状态”和每日健康记录的天数。
- 近 30 日思考闭环率：期间创建的问题中，已有回答的问题数除以问题总数；没有问题时显示空值，不伪造 0%。
- 近 30 日主动校正：用户修改模型回答、追问、备注、批注及回复、主动触发日记回望或认知复盘的次数；自动生成内容不计入。
- 距上次认知复盘：最近一次复盘距今天的本地自然日天数，并同时显示累计复盘份数。

日记原文必须先独立持久化，AI 不自动改写原文。写作中的“引子 / 结构 / 话题”以当前编辑器全文和近期事件为输入，完成后只追加到当时编辑器的最新末尾，不覆盖用户文字；它们随日记保存后才进入持久化。用户可对已保存日记按需发起流式回望；每次回望作为带 `sourceUpdatedAt` 的独立版本保存在 `journals[].reflections`，日记后来被编辑时旧回望仍保留并明确标记为基于旧版本。回望的 `reasoningContent` 只供展开查看，不进入任何后续模型上下文。

捕念保存于独立的 `captures` 集合，不强制问题、答案或结构。当前“展开成思考”只把捕念正文带入思考表单的初步想法，由用户补充明确问题后再创建完整思考；不能静默改变原捕念或自动伪造问题。

每日健康记录保存于异构 `dailyRecords` 集合，类型为 `sleep / heartRate / weight / exercise`。睡眠与心率同时保留截图附件路径和结构化字段；运动当前只保存原始描述。体重必须同时保留秤上原值、衣物类型、扣减均值、校正值和 95% 估计区间，后续分析使用校正值及区间，不得覆写原始测量值。

善言记录保留原始换行并支持最多 8 个标签。时间线正文使用两端对齐，默认最多显示 5 行，确有溢出时才显示展开/收起控件。回顾气泡使用有边界的网格槽位，不能以绝对定位承载不定高正文；每轮优先从不同标签各取一条，再用其他记录补足。气泡只在善言页可见、页面未隐藏且鼠标未停留时自动换组，也提供手动刷新。所有可批注正文的选区工具均可打开“善言”确认框，用户编辑内容、来源、标签与时间后才入库。

## 云端运行

云端是正式数据的唯一来源，代码与数据分离：Gitee 保存代码，`/srv/for-now/data` 保存认证数据和逐用户运行数据，OSS 只保存一致性快照。不得用 Syncthing、网盘或 Git 双向同步运行中的数据目录。

设置 `INVITE_CODE_HASH` 后启用认证。密码使用独立盐值的 scrypt 哈希；会话令牌只以 SHA-256 摘要持久化，浏览器使用 HttpOnly、SameSite=Lax Cookie。首个邀请码注册账户自动接管迁移进根数据目录的既有记录；后续账户分别使用 `data/users/<user-id>/` 下的 store、模型设置和附件。未登录请求不得读取 API 或附件。

云服务器由 systemd 托管 Node，Nginx 保留现有根路径服务，并将 HTTP `/now/` 重定向到公网 IP HTTPS；443 上的 `/now/` 关闭响应缓冲以支持 SSE。Let's Encrypt 短期 IP 证书提供传输加密，应用账户提供身份与数据隔离。`/apps/` 可作为多应用入口。

本机默认使用隔离数据。设置 `UPSTREAM_ORIGIN=https://123.57.140.24/now` 时，本机 Node 只提供当前工作区前端，并流式代理认证、API、SSE 与附件到云端，以相同的云端数据验证本地修改。部署使用不可变发布目录和原子软链接切换，健康检查失败时恢复上一版本。备份短暂停止服务形成完整压缩快照，恢复服务后通过 ECS RAM 角色和北京内网 Endpoint 上传 OSS；不保存长期 AccessKey。

## 安全与验证

密钥只在“设置”页面输入，不写入聊天或 README。内测码只通过环境变量保存 SHA-256 摘要，不保存或输出明文。没有密钥时应显示清楚的可恢复错误。代码变更至少执行 Node 语法检查、服务健康检查和相关 API 回归；认证变更还应运行 `scripts/auth-regression.mjs`；涉及位置型数据的修改还必须验证“前方增删后重定位”和“标记正文破坏后进入漂流箱”。真实模型响应只有配置密钥后才能端到端验证。
