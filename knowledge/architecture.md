## 生产运行基线（v0.1.1）

- `server.mjs`：无框架 Node HTTP 服务、JSON API、DeepSeek 调用、阿里云图片分割与统计计算。
- `logging.mjs`：请求、持久化、操作和 AI 审计共用的脱敏、私有 NDJSON 队列、资源摘要与日文件清理。
- `attachment-storage.mjs`：本地或私有 OSS 附件后端；云端按账户使用对象前缀，读取统一经过应用认证代理。
- `public/`：单页 HTML/CSS/JavaScript 界面。
- `data/store.json`：状态、每日健康记录、捕念、日记、思绪、对话、书目、小物、善言、实验、复盘、回收站、待重试附件清理、后台任务、通知、冷启动资料与商业化估算参数；生产结构版本为 v14。

## v0.2.0 工作区候选（未发布）

模块边界和检查规则见 [`modularization-design.md`](modularization-design.md)；PostgreSQL、后台 worker、个人上下文与按指标扩容的目标方案见 [`scalable-architecture-design.md`](scalable-architecture-design.md)。

- `server.mjs`：保留无框架 Node HTTP 装配入口；G2 R4 候选已将目标领域规则迁入模块、应用与 HTTP 层，模块迁移例外清零。
- `src/shared/persistence/`：JSON/PostgreSQL repository、业务/身份/配置/用量映射、原子注册、附件状态、整批迁移与停写导出；业务模块不直接拥有数据库连接或 JSON 写队列。
- `src/modules/thoughts/`：接管思绪根链/内容块、保留状态、备注、追问、乐观版本和回答结果保存；`src/app/thought-workflows.mjs` 编排创建链/任务原子写、草稿/引子与前台回答，`src/http/thoughts.mjs` 同时适配旧 API 和 v1。
- `src/modules/annotations/`、`tasks/`、`notifications/`：分别拥有批注锚点/漂流/回复、任务幂等/重试/恢复、通知已读与计数。`src/app/` 解析跨领域资源，并在同一事务中校验输入、保存结果、更新任务与通知；`src/http/` 适配任务和两套兼容批注 URL。请求账户上下文由装配入口传入调度器。
- `src/modules/auth/`：账户、密码与会话生命周期；只通过注入的认证 repository 和初始化接口访问持久化。`src/http/` 负责 Cookie、身份绑定、认证路由、JSON 解析与 SSE 事件；注册事务提交后才向客户端发出 Cookie。
- `src/modules/trash/`：回收条目、保留期限、幂等查找和父子清理清单。`src/app/trash.mjs` 协调业务位置解析、版本推进和批注回附，`http/trash` 拥有响应适配。`shared/attachments` 负责引用识别和清理任务尝试，`app/attachment-cleanup` 在账户锁内登记持久任务、重试与重启恢复。批注后台任务同时绑定根记录版本，恢复相同正文也不能接受删除前回答。
- `src/config/`：统一环境解析、默认值、上下限与启动模式互斥检查；配置在启动时形成快照，存储适配器显式接收配置。
- `src/shared/observability/`：异步上下文、请求/持久化/AI 审计共用的脱敏、私有 NDJSON 队列、提交后资源摘要与日文件清理；`http/request` 拥有追踪 ID、base path、受控异常与请求完成审计。根 `logging.mjs` 已移除。
- `src/modules/discovery|exports|actions|feedback/`：分别拥有思绪检索/回访、跨体裁导出、行动/习惯及产品反馈/验证台账；均通过注入的账户仓储工作，不直接访问 HTTP、文件或数据库。
- `src/http/api-v1.mjs` 与 `src/http/openapi-v1.mjs`：冻结 v1 `1.0.0` 的 `data/error/meta` 包络、TraceID、游标、ETag/If-Match、Idempotency-Key、模块注册及 OpenAPI 根结构；G2 R4 候选共 60 条 OpenAPI 路径、104 个操作。
- `src/modules/ai/`：四档/场景设置、用量/费用快照、成本模拟/统计、额度、通用 SP/场景契约与逐次调用/重试审计；存储、日志和供应商接口由装配注入。JSON 设置修改串行读取最新值，写失败不提交摘要；账本/审计失败不重试模型。设置与成本路由归 HTTP，跨领域上下文和具体业务 Prompt 继续迁移。
- `src/infrastructure/ai-providers/`：DeepSeek HTTP/SSE、响应校验与图片编码，以及阿里云分割 SDK、轮询、PNG 下载和错误投影；不含业务重试、费用或记录保存策略。图片读取和摘要归共享附件模块。
- `src/modules/keepsakes/`：小物校验、归一化、创建/编辑和分割流程，只接收小物集合仓储或注入的供应商/临时文件接口；四条小物路由归 HTTP，删除调用应用回收事务。`shared/concurrency` 提供无业务含义的 QPS/在途队列，AI 与分割各自独立装配。
- `src/shared/time/`：本地日期、跨日计算、严格日期校验、本地日期/时分组合和发生时间解析；历史 store 版本的日期修正仍在迁移处。旧日期解析兼容与 v1 契约收口分阶段处理。浏览器侧无业务时间格式化由 `public/frontend/time/` 提供。
- `src/shared/time/` 与 `src/shared/validation/`：本地自然日/日期偏移、数字范围与通用校验；保持账本配额既有 UTC 日口径。
- `src/shared/attachments/`：本地、mock 与私有 OSS 附件适配，图片校验、配额锁、上传清单和临时文件生命周期；账户目录与数据库清单由装配入口注入。云端按账户使用对象前缀，HTTP 上传与 GET/HEAD 读取归 `src/http/attachments.mjs`，统一经过认证；清理同时覆盖云端与迁移遗留本地副本。根目录旧存储文件已移除。
- `public/`：单页 HTML/CSS/JavaScript 界面；根 `app.js` 只启动 `frontend/app`，根 `styles.css` 只加载模块样式。`frontend/pages` 登记 23 个视图并管理组别/页面生命周期，`frontend/features` 组合页面副作用及 discovery/export/actions/feedback 纯功能模块；`frontend/api/session/state/content/time/media` 分别承接传输、会话、状态和无业务共享能力。`index.html` 保持无内联业务逻辑的静态可访问性壳。
- `data/store.json`：状态、每日健康记录、捕念、日记、思绪、对话、书目、小物、善言、实验、复盘、行动、习惯/打卡、反馈、验证台账、回收站、待重试附件清理、后台任务、通知、冷启动资料与商业化估算参数；当前工作区结构版本为 v15。
- `data/llm-settings.json`：四档模型配置、逐场景档位、助手称呼、逐场景回答风格与 API Key；当前结构版本为 v5，权限 0600，不返回页面明文。
- `data/ai-usage.json`：从统计能力启用后开始追加的逐次 AI 用量、图片输入摘要、状态、耗时、当次峰谷单价快照和费用拆分；当前结构版本为 v2，不回填旧调用。
- `data/logs/ai-audit-YYYY-MM-DD.ndjson`：按账户和 UTC 自然日保存的完整 AI 调用审计；包含实际 SP、UP、历史、参数、回答与推理，不包含 API Key 或图片 Base64，默认保留 30 天。

应用本地运行于 `http://127.0.0.1:4173/`。所有模型能力走独立 DeepSeek API，不复用开发 Agent/Codex 线程。
首次启动先按锁文件执行 `npm ci`。持久化只在文件不存在时使用默认数据，损坏文件保留并拒绝继续写入；JSON 通过 `0600` 临时文件原子替换，结构迁移前留备份。数据、账户、附件和日志目录固定为 `0700`，其中的私有文件与迁移备份固定为 `0600`。
日期归属使用运行设备的本地自然日，时间戳以 UTC ISO 格式持久化；页面显示时间固定采用 00–23 小时制。事件型记录同时保存不可变的创建审计时间 `createdAt`、可编辑的完整发生时间 `occurredAt`，以及从 `occurredAt` 按本地时区派生的日期索引 `occurredOn`。页面若跨过午夜且用户此前停留在“今天”，应自动切换到新的本地日期。

### PostgreSQL 迁移阶段

- 生产及默认写源仍是 JSON；本地隔离验证可选 PostgreSQL 单写，不启用长期双写。
- `npm run migrate:postgres -- --dry-run --data-dir <path>` 只读校验全领域 JSON 和附件实物，输出账户、SHA-256 和数量，不输出正文或秘密。
- 建表通过 `--init-schema` 和独立 `PG_SCHEMA_DATABASE_URL`；完整导入使用非 owner 的 `DATABASE_URL`，所有账户和独立文件在同一事务中校验内容与源漂移。
- 业务集合、嵌套内容、认证/会话、模型设置/秘密、逐次用量及成本方案已接入关系行运行读写，并验证进程重启和第二数据库恢复。当前每数据库单应用实例，旧思绪投影已移除；生产切换仍需发布授权与演练。
- 所有租户表启用并强制 PostgreSQL RLS；真实 PostgreSQL 16.14 已验证隔离、重复导入、失败回滚和关系重建。表结构、覆盖保护、命令与剩余边界统一见 [`postgres-migration.md`](postgres-migration.md)。

## 视觉设计语言

全站使用“雾白玻璃 + 石墨文字 + 低饱和功能色”。内容和记录是第一视觉层级，导航只提供稳定定位，不使用大面积深色背景与高饱和装饰。

- 基础色：页面为雾灰白，正文为石墨色，边框使用带少量绿色倾向的浅灰；卡片以 8px 圆角、细边框和轻阴影为主。
- 一级导航固定为“今日｜所见｜所思｜我的”。今日包含“此刻｜共参｜每日”，并在此刻页承载行动/习惯；所见以“念起｜书间｜拾句｜小物”承载捕念、读书、善言和小物；所思包含思绪、寻迹、日记、回顾。“我的”采用设置页式分组列表，数据导出和产品反馈各自进入独立内容页。
- 文化表达与界面命名的选择原则、当前采用和保留候选统一见 `knowledge/cultural-content-preferences.md`。
- 桌面导航：固定宽度 176px，使用半透明雾白、模糊和低对比边界形成毛玻璃质感；当前一级入口只通过浅色底、细指示条及模块强调色识别。
- 移动导航：四个一级入口在 920px 以下转为带安全区的浅色玻璃底栏；不得使用深色整栏，也不得遮挡页面、弹窗或批注面板。
- 模块色：今日青灰、捕念绿、日记陶土、思绪灰蓝、回顾冷青、读书橄榄、小物灰棕、善言赭金、设置石墨。模块色用于当前项、焦点、少量结构线，不大面积染色正文容器。
- 排版与密度：标题字距固定为 0；操作型界面保持紧凑，不使用营销式大卡片和过度留白。控件、时间线和固定格式元素须有稳定尺寸，桌面与移动端均不得产生横向溢出。

## 前端更新原则

首次启动可全量加载。写操作完成后重新获取状态，但只渲染受影响的数据域，不重绘整个页面：

- `thoughts`：只在思绪主体发生变化时刷新列表与标签，并保存根卡片和追问的展开状态。
- `captures`：只刷新捕念列表；正在编辑的捕念表单不得因其他数据域变化而清空。
- `journals`：只刷新日记列表并保留已展开日记；原文编辑表单和助手回望是两条独立操作。
- 评论与划线：选中文本后可创建需要文字内容的浅黄色评论，或无需填写内容的浅绿色划线。新增、回复和删除直接修补内存记录、对应锚点和右侧面板；不得调用 `refreshState("thoughts")`，也不得替换思绪卡片 DOM。
- 批注锚定：创建时同时保存选中文本、前后短上下文、原始位置和最多前后 1000 字原始上下文。编辑正文时先用“精确文本 + 邻近上下文 + 原位置距离”重定位；找到则平移，找不到则从有效批注移入根记录的 `annotationDrift`，完整保留评论、回复、神鸡对话与原始上下文。漂流项由用户显式删除。
- Markdown 正文统一使用“渲染后可见纯文本”作为批注坐标系；创建校验和编辑重定位都必须先去除 Markdown 结构标记，不得用源码字符位置直接匹配页面选区。
- 所有模型最终输出和声明支持 Markdown 的用户内容统一使用 `renderMarkdown` 后再执行 `renderLatex`，包括思考问题与初步想法、回答、追问问答、长期对话双方消息、神鸡问答、认知复盘、日记与回望、保存后的模型思考、捕念、书目简介和读书笔记。折叠摘要使用 `plainPreview`；编辑框保留源码；评论元数据、标签、来源和引用原文保持纯文本。
- `@神鸡`：评论和划线均可发起批注级 AI 对话，问答保存在对应 annotation 的 `shenji` 数组；返回后只更新当前侧栏卡片。上下文与人格规则见 `knowledge/prompt-architecture.md`。
- `checkins`：保存后刷新状态图、滑块参考和回顾洞察；回顾页的单次状态记录可编辑发生时间、量表、备注和因素，更新不得改写 `createdAt`。
- `dailyRecords`：只刷新每日记录的当前类型历史与可视化；不得重绘“此刻”滑杆或清空其他表单。
- `chat`、`review`、`books`、`keepsakes`、`quotes`：各自独立刷新。

输入框、当前视图、滚动位置和无关区域不应因一次保存而重置。
思考引子异步返回前核对输入、表单重置、日期和当前账户；期间发生变化就保留用户当前输入。小物上传、编辑加载及分割图片解码使用请求序号校验，关闭或切换对象后，旧结果不得覆盖新画布。
账户切换时先锁定并清空旧账户的页面状态、表单、弹窗和媒体引用，只有新账户的 `/api/state` 与设置都成功渲染后才解除遮罩。退出动作先在本地锁屏，再请求服务端注销；旧会话中的在途前端请求随会话控制器中止。
API 公共入口在收到响应头、解码 JSON/图片和消费流式事件后均校验会话代次，即使底层传输未及时中止也拒绝旧响应。多个数据域的并发刷新只接收最新响应，同时合并所有待渲染数据域；原页面通过订阅执行局部渲染。

图片输入共用格式校验、文件选择、剪贴板、拖放、预览、Data URL 转换与附件落盘。书目和健康截图识别共用 Flash 图像调用链路，具体场景只替换识别提示词与 JSON Schema；小物主体分割走独立的阿里云接口。书目录入包含两个独立图片槽位：封面图只用于书架展示并在保存时上传，信息识别图只回填可编辑元数据，不能自动成为封面；已有书目的元数据和封面可继续编辑。书目识别、心率和用户选择的原图仅接受 PNG、JPEG、WebP，单张和单次合计限制 8 MB；睡眠接收 1～2 张并合并解析。小物透明轮廓由浏览器生成 PNG，可能大于原始 JPEG，持久上传接口单张允许 24 MB、请求体允许 36 MB，其他 JSON API 仍限制 12 MB。健康截图只回填可编辑表单，用户确认后才写入记录；截图缺少年份时，以用户当前所选日期推断最近年份，并在核验说明中显式标注。

书目保存独立的 `readingStartedOn` 与 `readingFinishedOn` 自然日字段：开始日期为新建必填项，结束日期允许为空且不得早于开始日期；旧书目兼容为空，不因增加字段升级存储版本。书籍详情页以笔记为主：轻微滚动后页面标题收拢至左上，随机精选笔记进入左侧，封面、标题、作者、简介及阅读日期缩为右侧摘要；该状态在当前书内保持稳定，返回书架后恢复展开标题。阅读时间线先于新增记录表单展示。

小物收集在 `keepsakes` 中同时保存原图路径 `originalPath`、透明轮廓图路径 `cutoutPath` 和标签 `tags`。自动分割唯一调用阿里云 `SegmentHDCommonImage`：服务端以 ECS RAM 角色提交本地图片流，把异步响应的 `requestId` 作为 `jobId`，通过 VIAPI `GetAsyncJobResult` 取得结果地址后及时下载临时透明 PNG，再向浏览器返回 Data URL；不调用 DeepSeek 锚点或 `RefineMask`。浏览器只从透明图读取 Alpha 蒙版，按 `edgeExpansion` 做小幅膨胀，随后允许用保留/擦除画笔修正；名称和类型由用户填写。透明 PNG 始终由原图与蒙版在独立画布生成，陈列与详情则把 15% 不透明度的原图放在底层、100% 不透明度的透明主体放在上层，不能把展示合成图覆盖为 `cutoutPath`。画廊使用 CSS columns 瀑布流，卡片进入页内详情后可在默认呈现与完整原图之间切换。服务端不常驻图像分割模型。

异步 DOM 事件在第一个 `await` 前保存表单、按钮等节点引用，不得在异步恢复后继续读取可能已被清空的 `event.currentTarget`。时间线按 `occurredAt` 排序、按派生的 `occurredOn` 分组：同一日期只在组首显示一次左侧日期。善言的来源及思绪的标签放在内容卡片外上方左侧，时间和该层级的轻量操作放在同一行右侧；元信息不得占用正文卡片空间。编辑发生时间不得改写 `createdAt`。

## 模型交互

模型配置分为 Lite、Mid、High、Ultra 四档；每档分别保存 `model` 与 `effort`。思考引子/草稿/回答、追问回答、长期对话、日记引子/结构/话题、日记回望、批注神鸡、认知复盘和书目识别分别保存所选档位，服务端按场景解析最终模型参数。旧的单模型设置首次启动时自动备份并迁移；书目图片因模型能力限制固定使用 Flash，但沿用该场景所选档位的思考强度。

“记下一条思考”的引子默认使用 Lite，且只在用户主动点击时调用。截止所选日期存在历史记录时，从近期捕念、日记、问题、长期对话、状态或每日健康记录中挑一个真实线索向前追问；完全没有历史时给一个轻巧、具体、允许不完整作答的问题。引子只回填可编辑的问题框，不自动创建或保存任何思绪。

主动查看的草稿、追问、日记回望等场景使用回答弹窗和 SSE 流，依次显示整理上下文、模型思考、生成回答、回答完成四个阶段。DeepSeek 明确返回的 `reasoning_content` 在思考区流式展示；首个回答片段到达时自动折叠思考区，并在回答区继续流式渲染 Markdown/LaTeX。思考区仅在用户仍贴近底部时自动跟随；用户向上滚动后不得抢回滚动位置。思绪根回答默认进入持久后台任务，不主动打开弹窗。

生成中的回答弹窗允许关闭。关闭只隐藏弹窗，不取消服务端请求；模型生成完成后仍须按原数据结构持久化、增量刷新对应区域并提示结果。`reasoning_content` 独立持久化为回答的 `reasoningContent`，仅供用户从回答旁的“思考”控件展开查看；不得混入最终回答正文，也不得进入完整追问链、长期个人语境、对话历史或认知复盘输入。

记录保存与自动回答在同一次 repository 原子写中建立记录和持久任务，接口立即返回任务 ID，前台随即清空并解锁录入表单。任务以 `targetId + inputVersion + clientRequestId` 绑定，服务重启后状态仍可查询；目标被修改或删除时结果标记为过期，不写入业务对象。通知中心承接排队、生成、完成、失败、跳转和重试，每个任务只影响自己的触发控件。

只有明确处于 `queued` 的任务在重启后自动继续；中断时仍为 `running` 的任务因无法证明供应商是否已经成功计费，会转为可见失败并等待用户重试。每个失败任务只能原子创建一个直接重试后继；重复点击返回同一后继任务，不重复调用供应商。并发 `/api/state` 读取只接纳最新响应，但待刷新的数据域会跨请求合并，避免通知轮询吞掉其他页面的最终渲染。
当前单实例内，直接流式草稿按“账户数据文件 + 场景 + `clientRequestId`”合并并发请求；根回答、追问回答和批注回答统一进入持久任务。相同请求只调用一次供应商，不同目标复用同一标识会被拒绝。

回收站永久清理先在同一次原子写中移除回收记录并登记 `attachmentCleanup`，再删除无有效引用的附件。附件删除失败不会让已永久删除的正文复活；清理项保留错误码与尝试次数，并在定时重试或服务重启后继续。每次删除前重新检查活跃数据和剩余回收记录的引用，避免删除共享附件。

所有流式请求显式开启 DeepSeek `stream_options.include_usage`，非流式请求读取响应顶层 `usage`。服务端按账户保存 v2 用量账本及开始/终态 AI 审计，失败与重试独立记账。无终止标记的断流、长度截断和内容过滤不保存为业务成功结果。完整 SP、UP、历史、参数、回答与推理不进入普通 stdout，也不由统计 API 返回。每个 HTTP 响应附带 `X-Request-Id`，系统、操作日志与 AI 账本/审计通过 `traceId / callGroupId / callId` 关联。完整字段、阿里云审计、保留与剩余边界见 `knowledge/observability.md`；计数与费用口径见 `knowledge/metrics.md`。

每次认知复盘均作为独立记录追加到 `store.analyses`，持久化 `id`、生成时间、触发方式、正文和模型思考，不覆盖历史结果。回顾页展示完整复盘历史及总数：最新记录默认展开，旧记录折叠但可随时回看。

主动认知复盘采用渐进式冷启动：存在任一状态、健康、捕念、日记或思绪记录即可运行。思绪不足 3 套时只输出 1～2 条明确标为“初步观察”的判断，并逐条说明证据与待补信息；达到常规样本后再输出 3～5 条强发现。每周自动复盘仍要求至少 5 套思绪，避免低样本阶段产生过密的后台结论。

空账户冷启动提供快速版 8 题与详细版 18 题。判断题全部必答；性别、地区、职业、专业、学校、兴趣、自我介绍、作品和导入材料均可跳过。服务端保存问卷原始选择并生成可编辑的初始认知，后续模型上下文同时保留原始选择与派生理解，且明确以后续真实记录和用户修正为更高优先级。完整策略见 `knowledge/onboarding-strategy.md`。

回顾页顶部不展示单纯的内容总量，而展示可解释的行为信号：

- 近 7 日记录覆盖：状态、健康、捕念、日记、思考问题、长期对话、善言或读书笔记出现过任一种记录的自然日数，分母固定为 7 天。
- 近 30 日身心同日：同一自然日同时存在“此刻状态”和每日健康记录的天数。
- 近 30 日思考留痕率：期间创建的问题中，存在初步想法、用户回答或编辑、评论/划线、追问、备注、编辑、保留/舍弃等主动痕迹的问题数除以问题总数；纯 AI 原样回答不进入分子，并在思绪时间线标记待留痕。完整边界以 `knowledge/metrics.md` 为准。
- 近 30 日主动校正：用户修改模型回答、追问、备注、批注及回复、主动触发日记回望或认知复盘的次数；自动生成内容不计入。
- 距上次认知复盘：最近一次复盘距今天的本地自然日天数，并同时显示累计复盘份数。

长期趋势在只有当前样本时直接展示当前均值与样本数，不等待完整的前后两组；延迟相关在因素首次出现时即展示单日观察，缺少次日或无因素基线时显式标注缺口。随着样本增加，状态依次升级为“初步线索”和“可观察”，任何阶段都不推断因果。延迟相关只展示按置信层级、可比样本量和相对基线差异排序后的前三条，其余不进入页面。计算流程不进入双栏正文，默认隐藏，只通过面板标题旁的信息按钮在浮层中按需查看，不能改变左右主面板高度。

日记原文必须先独立持久化，AI 不自动改写原文。编辑器可显式保存一份账户级草稿，只持久化标题、正文和编辑目标，不保存日记发生时间或标签；重新登录或跨设备打开后自动恢复，正式创建日记或保存对应日记修改时清除草稿。写作中的“引子 / 结构 / 话题”以当前编辑器全文和近期事件为输入，完成后只追加到当时编辑器的最新末尾，不覆盖用户文字；引子、结构、话题的每个非空行分别以 `🗃`、`🏷`、`💬` 标记，它们随日记保存后才进入持久化。用户可对已保存日记按需发起流式回望；每次回望作为带 `sourceUpdatedAt` 的独立版本保存在 `journals[].reflections`，日记后来被编辑时旧回望仍保留并明确标记为基于旧版本。回望的 `reasoningContent` 只供展开查看，不进入任何后续模型上下文。

捕念保存于独立的 `captures` 集合，不强制问题、答案或结构。当前“展开成思考”只把捕念正文带入思考表单的初步想法，由用户补充明确问题后再创建完整思考；不能静默改变原捕念或自动伪造问题。

每日健康记录保存于异构 `dailyRecords` 集合，类型为 `sleep / heartRate / weight / exercise`，四类均支持截图附件和结构化识别。体重/体成分与运动的字段、归一化、提示和摘要由 `src/modules/health/profile.mjs` 管理，四类记录载荷与 CRUD 由 `src/modules/health/records.mjs` 管理，HTTP 适配位于 `src/http/health-records.mjs`；附件和模型调用仍复用原装配链路。此刻状态记录同理由 `src/modules/checkins/records.mjs` 和 `src/http/checkins.mjs` 接管。识别结果只回填可编辑表单，保存后才写入业务记录。

体重有总重量时保留秤上原值、衣物类型、扣减均值、校正值和 95% 估计区间；无总重量时可仅保存体成分/描述，校正值与区间为空并排除出体重曲线。运动保留项目名、秒级时长、活动/总热量、平均/最大心率和可见心率区间，以及描述与核对说明。缺失不补零，旧版纯描述运动仍兼容；字段与单位见 `knowledge/metrics.md`。前端的编辑、取消、类型/日期/账户变化均使在途识别失效，保存后重置图片输入；原图链接供核对并沿用删除恢复语义。

善言记录保留原始换行并支持最多 8 个标签。时间线正文使用两端对齐，默认最多显示 5 行，确有溢出时才显示展开/收起控件。回顾气泡使用有边界的网格槽位，不能以绝对定位承载不定高正文；每个气泡随机采用 3–5 行正文上限，短内容自然收缩，超出部分通过真实滚动位置自动上下往返。所有气泡使用统一的四行气泡基准巡航速度和固定加速度，只在靠近两端时平滑减速；自动滚动时隐藏滚动条。用户用滚轮、拖动、触摸或键盘介入后可直接控制并显示滚动条，静止 5 秒后先继续向下，到底后反向向上；正文不能继续撑高整个模块。三个槽位采用不同的横纵基准偏移和错相位小椭圆运动，避免机械共线，但运动范围不得越出模块或互相重叠。每轮优先从不同标签各取一条，再用其他记录补足。气泡只在善言页可见、页面未隐藏且鼠标未停留时自动换组，也提供手动刷新。所有可批注正文的选区工具均可打开“善言”确认框，用户编辑内容、来源、标签与时间后才入库。

## 云端运行

云端是正式数据的唯一来源，代码与数据分离：Gitee 保存代码，`/srv/for-now/data` 保存认证、逐用户文本/结构化数据、用量和日志；私有 OSS 保存持久图片及一致性备份快照。不得用 Syncthing、网盘或 Git 双向同步运行中的数据目录。

设置 `INVITE_CODE_HASH` 后启用认证。密码至少 8 位并同时包含字母和数字，使用独立盐值的 scrypt 哈希；会话令牌只以 SHA-256 摘要持久化，浏览器使用 HttpOnly、SameSite=Lax Cookie。账户页允许按大小写不敏感的唯一性规则修改用户名；修改密码必须验证原密码，成功后撤销该账户除当前会话外的其他会话。首个邀请码注册账户自动接管迁移进根数据目录的既有记录；后续账户分别使用 `data/users/<user-id>/` 保存文本数据和模型设置，并使用 `for-now-attachments/<user-id>/` 保存图片。未登录请求不得读取 API 或附件。

云服务器由 systemd 托管 Node。Nginx 将 HTTP 和公网 IP HTTPS 请求重定向到 `https://77liu.top`，域名 HTTPS 保留现有根路径服务，并在 443 上为 `/now/` 关闭响应缓冲以支持 SSE。Let's Encrypt 域名证书保护正式入口，短期 IP 证书保证跳转前的连接可信；应用账户继续提供身份与数据隔离。`/apps/` 可作为多应用入口。

独立中台运行在同一 ECS 的 `for-now-platform.service`，公网路径为 HTTPS `/platform/`，进程仅监听 `127.0.0.1:4280`。中台不读取 `/srv/for-now/data`：主应用通过仅回环直连、Bearer 服务令牌保护的 `/api/admin/v1/snapshot` 输出实时脱敏聚合；Nginx 对该主应用路径固定返回 404。聚合只含账户标识、数量、状态、耗时、成本和脱敏事件，不含用户正文、模型 Prompt/回复、附件内容或凭据。中台与主应用分别保存服务令牌明文和 SHA-256 摘要，浏览器两者均不可见。

中台管理员认证独立于业务账户：生产模板只有 `shenji` 主账户，使用环境文件中的 scrypt 密码哈希、8 小时持久会话、Secure/HttpOnly/SameSite=Strict Cookie、CSRF 与同源校验和登录限速。只有 owner 角色拥有通配权限与 `access.manage`；授权、会话和审计在中台独立数据目录原子持久化。中台所有业务动作保持预演，不调用生产写 API。

本机默认使用隔离数据。`npm run start:local-test` 启用专属测试模式：设置页可切换“使用模拟”和“冷启测试”。使用模拟时，通过当前线上登录会话只读请求 `/api/auth/me`、`/api/state`、`/api/trash` 和 `/api/settings`，重建本地模拟副本；后续业务写入全部落到本地专用目录，远端附件只允许 GET/HEAD 回退。冷启测试每次切换都重建空 store 和默认模型设置。该模式拒绝线上注册、账户修改和所有业务写代理，禁止与 `NODE_ENV=production` 或 OSS 写入模式同时启用。旧的通用 `UPSTREAM_ORIGIN` 代理仅保留给未启用专属测试模式的兼容流程。

部署使用不可变发布目录和原子软链接切换，健康检查失败时恢复上一版本。备份短暂停止服务形成文本与元数据的一致性压缩快照，恢复服务后通过 ECS RAM 角色和北京内网 Endpoint 上传 OSS；附件对象保存在独立私有前缀并由恢复演练逐项验证可读，不保存长期 AccessKey。容量、限额、最小 RAM 权限、告警和恢复流程见 `knowledge/operations-capacity.md`。

## 安全与验证

密钥只在“设置”页面输入，不写入聊天或 README。内测码只通过环境变量保存 SHA-256 摘要，不保存或输出明文。没有密钥时应显示清楚的可恢复错误。代码变更至少执行 Node 语法检查、服务健康检查和相关 API 回归；认证变更还应运行 `scripts/auth-regression.mjs`；涉及位置型数据的修改还必须验证“前方增删后重定位”和“标记正文破坏后进入漂流箱”。真实模型响应只有配置密钥后才能端到端验证。
