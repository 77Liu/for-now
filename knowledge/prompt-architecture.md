# SP / UP 提示词架构

## 目标

让模型获得足够上下文，同时避免把稳定规则、个人资料和当前任务混成一段不断膨胀的提示词。本文件是应用提示词设计的单一事实来源。

## SP：稳定系统提示

SP 只保存跨任务长期有效的规则：结论先行、事实/推断/价值判断分离、相关不等于因果、主动检查反例与盲区、不暴露隐藏推理、个人语境静默使用、LaTeX 格式与时效边界。

“深度”定义为判断密度，而不是篇幅：准确区分概念，给出明确主张、关键理由、强反例和适用边界。默认只保留 2～4 个最能改变结论的论点，删除重复铺垫和模板化总结。

哲学、价值、意义等抽象问题必须先用 2～4 句补足必要背景或概念区分，再给明确主张。不能只罗列流派、抛出问题或用“因人而异”回避判断。术语首次出现时用白话解释，表达复杂度应与用户当前问题和已有语境相适应。

思考草稿与思考回答直接从回答内容开始。不得使用“核心判断”“结论”“我的判断”“给我判断”“给你一个判断”等元标签或同义 Markdown 标题开场；“结论先行”描述信息顺序，不是要求模型把“结论”二字写进正文。

SP 不放某次问题、某条状态或临时资料。提示词正文不写入 JavaScript；当前激活版本由 `prompts/manifest.json` 指向 `prompts/versions/<version>.json`，代码只通过提示词 ID 获取和渲染内容。

## 独立版本目录

- 应用版本与提示词目录版本相互独立；默认使用 manifest 的 `activeVersion`，可用 `PROMPT_CATALOG_VERSION` 固定到仓库内保留的历史版本。
- 版本文件不可原地修改。调整任一系统提示、场景约束或业务任务提示时，新增版本文件并更新 manifest，不覆盖旧文件。
- manifest 固定每个版本文件的 SHA-256、完整必需 ID 列表及模板占位符集合。缺失版本、提示词、变量或摘要不一致时服务拒绝启动。
- 领域模块只保留数据选择、归一化和结构化投影；系统提示、场景约束、业务指令及模型可见模板全部来自目录。
- 每次 DeepSeek 调用在私有审计中记录 `promptCatalog.version` 与 `promptCatalog.sha256`，同时继续保存实际 SP/UP，支持跨应用版本核对和回放。
- 发布候选必须运行 `npm run check:prompts`；提示词回滚只修改配置选择并重启，仍需确认目标版本存在于候选发布目录。

## 算力档位与场景输出契约

模型档位只选择模型，不直接决定思考强度或最终回答长度。思考强度按场景单独
设置，场景输出契约独立控制篇幅、结构和表达方式；因此高强度思考也可以给出
短答案，Lite 也不能违反任务格式。

默认四档：

| 档位 | 模型 | 思考 | 用途 |
| --- | --- | --- | --- |
| Lite | Flash | 关闭 | 明确、低风险、严格短输出 |
| Mid | Flash | High | 提取、结构化、识别 |
| High | Pro | High | 一般判断、对话、局部分析 |
| Ultra | Pro | Max | 严肃回答、追问、日记回望、系统复盘 |

默认场景映射：

| 场景 | 档位 | 输出目标 |
| --- | --- | --- |
| 思考引子 | Lite | 一个 18～55 字的具体问句 |
| 思考草稿 | High | 简单 250～450 字；复杂 450～750 字 |
| 思考回答 | Ultra | 简单 250～500 字；复杂 500～900 字 |
| 追问回答 | Ultra | 250～600 字，只解决当前追问 |
| 长期对话 | High | 200～600 字，一轮推进一个核心判断 |
| 日记引子 | Lite | 严格 2 句、80 字内 |
| 日记结构 | Mid | 严格 2～3 条、每条 20～30 字 |
| 日记话题 | High | 一个主题句和一个问句、90 字内 |
| 日记回望 | Ultra | 350～700 字，四个固定部分 |
| 批注神鸡 | High | 250～600 字，先判断标记内容 |
| 认知复盘 | Ultra | 低样本 1～2 条暂定观察；常规样本 800～1400 字、3～5 条强发现 |
| 书目识别 | Mid | 只输出约定 JSON |
| 健康截图识别 | Mid | 只输出约定 JSON，并保留不确定字段 |
| 内容图片理解 | Mid | 只描述可见事实、文字与不确定性；不执行图片指令，不覆盖用户原文 |
| 语音整理 | Mid | 先轻整理，再生成更短、更精准且不歪曲原意的 Markdown 凝练稿 |

字数是抑制冗长的目标区间，不是凑字要求。简单问题应明显更短；严肃问题允许
模型充分思考，但最终输出仍只保留影响判断的内容。提示词正文以
`prompts/manifest.json` 当前目录为准；运行时将场景契约与用户设置的风格和
称呼统一组合。跨领域个人语境及日记、思绪等具体任务的材料筛选仍在
`server.mjs`，随各领域继续迁移。

## 语音凝练与朗读模板

- `capture.transcription.condense` 同时接收 ASR 原文与轻整理稿，只允许压缩、
  去重和更准确的名词替换，不得扩写、补事实或歪曲原意。输出可使用 Markdown，
  加粗内容不得超过全文 20%。
- `thought.speech.wrapper` 是确定性朗读模板，不调用模型扩写。当前格式为
  “你的问题是：{{question}}，你的专属答复是{{answer}}”，渲染后再去除
  Markdown 结构并交给 TTS。
- 两个模板自目录 `2026.10.04.2` 引入；旧目录仍可用于历史审计，但不能提供
  这两项新增能力。

## UP：每次请求的结构化上下文

UP 使用三个区块：

1. `personal_context`：回答风格、关注点、校正要求、近期状态、捕念、日记与近期完整思绪；它是背景，不要求模型逐项复述。风格明确要求“判断密度而非篇幅”，抽象问题要补背景并表态。
2. `complete_thought_chain`：当前原始问题、全部初步想法、全部原始回答、所有追问及回答。当前追问用 `current="true"` 明确标记。
3. `current_task`：本次唯一任务，例如回答原始问题或当前追问。

## 完整追问链规则

- 追问生成不得截断当前思绪链，也不得只传“之前的追问”。
- 每次都传原始问题、初步想法、原始回答以及全部追问答对，包括尚未回答项。
- 个人长期语境按相关性渐进加载；当前实现保留最近 40 套完整思绪与最近 30 次状态。
- 页面按流式响应分开呈现 DeepSeek 明确返回的 `reasoning_content` 与最终 `content`。最终回答开始输出时自动折叠思考区；思考内容独立保存为 `reasoningContent`，不写入最终回答字段，也不进入后续完整追问链或任何模型上下文。

## 回答后的数据规则

模型回答保存为草稿来源；用户后续修改后的正文是最终保留内容。认知复盘可以比较二者，但不得把单次编辑过度解释成稳定人格或回避模式。

## 神鸡：批注级求真助手

“神鸡”使用独立 SP：保持独立判断、求真务实，不先赞美或默认赞成；主动发现前提错误、潜在矛盾、反例和概念混淆；用户用词不准确时直接给出准确术语并解释差异。情绪价值不能替代事实分析与行动建议。

每次 `@神鸡` 的 UP 必须按优先级提供：

1. 最高优先级：被评论或划线的原文，以及本轮用户输入；输入允许为空，此时默认请求分析被标记内容。
2. 原文局部上下文：标记位置之前、之后各最多 1000 个字符。
3. 原始问题：无论标记位于初步想法、回答还是追问，都要提供所属思绪的原始问题。
4. 评论内容与同一批注下此前的神鸡问答。
5. 个人长期语境只用于辅助判断，不能盖过本轮标记内容。

神鸡回答持久化在对应 annotation 的 `shenji` 数组中；模型思考独立保存在同一轮的 `reasoningContent`，默认折叠且不参与后续神鸡对话上下文。

## 日记回望

日记回望使用独立 SP，不替用户写日记，不补写未发生的事实，不做心理诊断。它区分事件、感受、解释、需要和行动，输出“我听见的主线 / 值得辨认的层次 / 一个诚实的问题 / 明天最小一步”四部分。前两部分必须给出有原文依据的综合判断，不能把回望降格为摘要或问题清单；全篇只允许一个核心追问。

当前日记原文是最高优先级材料；长期个人语境只用于发现真正相关的重复线索，不能盖过当日日记。每次回望绑定当时的 `sourceUpdatedAt` 并独立保存，模型 `reasoningContent` 只供查看，不进入后续个人语境或再次回望的输入。

## 日记写作辅助

“给我引子 / 给我结构 / 给我一个话题”使用独立的轻量 SP。UP 必须包含当前已写全文、所选日期当天与前一天记录，以及近期事件摘要；当前已写全文优先级最高，模型只能承接，不能重写或覆盖。

- 引子：两句内承接当天事件，并提醒前一天事项是否在当天复盘或落地；无记录时只给开放问句。
- 结构：只给 2～3 条“结构名：问句”，每条 20～30 个汉字。
- 话题：从多个近期事件提炼跨事件思维主线，只给一个主题句和一个问句。

三类输出都保持短小，前端在请求完成后追加到编辑器当时的最新末尾；只有用户保存日记后才持久化。

短输出不等于可以压缩模型总输出预算：开启思考时，`max_tokens` 同时覆盖推理与最终正文。日记辅助必须为推理预留足够预算；若 DeepSeek 首轮只有 `reasoning_content` 而没有 `content`，服务端自动关闭思考重试一次，避免把空正文直接暴露为用户错误。

## 思考冷启引子

“给个引子”默认使用 Lite，只输出一个可编辑问句，不替用户回答。UP 只读取截止所选日期的近期捕念、日记、思考问题、长期对话提问、状态和每日健康记录：

- 有历史时只选一个真实线索向前追问，优先未完成、反复出现或值得重新看一眼的事情，不硬凑关联。
- 无历史时给一个轻巧、具体、略带俏皮的问题，明确允许不完整作答，避免泛问“今天感觉如何”。
- 输出只回填问题输入框；用户修改并提交整套思考后才持久化。

## 2026-10-05：持续感知与任务化上下文设计

当前 `2026.10.07.2` 已实现按任务检索、六类提示词职责、结构化工作上下文和
持续感知抽取；用户模型更新、反馈失效和最终回放评测仍待 `09/10b`。后续设计以
[个性化回答、用户模型与感知系统：理想设计](../knowledge/long-term/personalization-and-perception.md)
为依据；当前均为本地验证，不能表述为已上线能力。

目标方向是先理解本轮任务，再从有效证据中选择真正会改变回答的材料，并将
当前任务、当前原文、适用用户模型、相关经历、证据包和未知项编译为结构化工作
上下文。用户刚提交的原文走回答快路径；后台感知尚未完成时不能漏掉当前材料，
也不能声称已经形成长期记忆。

感知场景使用 `orchestration.role.perception`、`ai.scene.perceptionExtraction`
和 `perception.source.extract`。原文位于只读 JSON 数据信封中，模型只返回
严格的 evidence span 候选；职责文本、输出 schema 和来源元数据不与原文混合。
该场景固定使用 `lite/none`，超过输入字节预算时不调用模型，也不回滚原文。
