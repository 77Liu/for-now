## 提交组织

- 一个提交表达一个可独立理解和验证的目的；只暂存本任务范围，保护其他未提交工作。
- 在获准范围内完成实现、自查、必要验证及接入审查后，形成可恢复的功能或任务提交。不为追求“小步”机械拆碎原子修改，也不无限堆积已可交付成果。
- 主题使用与实际内容一致的 `feat`、`fix`、`perf`、`refactor`、`test`、`docs` 或 `build` 类型；中文摘要说明结果，正文说明必要的原因、取舍与验证限制。
- 提交前核对实际 diff、分支、暂存内容和适用验证；声明通过必须对应被提交对象。
- 提交权限按已有 Owner 授权及其暂停、撤销、范围限制执行；不因门禁拒绝就推定需要新的人工授权，也不因测试通过就推定获得授权。

## 自动门禁与人工接入

低风险任务使用 `npm run commit:task -- --message "<类型>(范围): 摘要"`；`commit:feat` 仅为兼容入口。允许类型、路径分类、规模、固定暂存树核验和验证命令由 [commit-gate](../scripts/commit-gate.mjs) 维护，本文不复制数值。

门禁拒绝后先读原因。已授权但不适合自动路径的治理、共享契约等改动，由协调者核对实际差分、必要验证和授权后按普通 Git 路径提交。不得修改类型、隐藏失败、忽略分支职责或削弱门禁来制造通过。

治理规则及其拆分正文不能作为普通文档自动提交。规则拆分、移动或新增唯一正文时，必须同时核对门禁消费者及所有引用；门禁不能独立判断业务语义或替代主控审查。

本地提交不表示合入、发布或部署已完成。外部动作的许可、候选身份和执行顺序只见上表对应正文。
