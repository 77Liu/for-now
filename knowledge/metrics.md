# 指标与统计口径

## MVP 上线指标

MVP 先用少量、可解释的指标判断用户是否进入核心闭环和系统是否稳定。所有人数均按去重账户统计，测试账户和运维探测应排除；时间按应用本地自然日计算。

| 指标 | MVP 定义 | 分母与窗口 | 数据来源 |
| --- | --- | --- | --- |
| 激活用户数 | 注册成功且完成隐私确认的账户数 | 直接报人数；在邀请码发放事件尚未记录前不伪造“激活率” | 认证数据、隐私同意记录 |
| 激活率 | 激活用户数 / 已发放且仍有效的邀请码对应人数 | 累计及按周；当前缺少邀请码发放账本，暂记 N/A | 后续邀请码账本 |
| D1 留存 | 注册次一自然日存在至少一次成功登录的用户数 / 当日激活用户数 | 按激活日 cohort | 成功注册、登录操作日志 |
| D7 留存 | 注册后第 7 个自然日存在至少一次成功登录的用户数 / 当日激活用户数 | 按激活日 cohort | 成功注册、登录操作日志 |
| 记录→回答→校正闭环率 | 创建记录后 7 天内取得至少一次成功 AI 回答，并发生一次用户校正的记录数 / 取得成功 AI 回答的记录数 | 近 30 日滚动窗口；同一根记录只计一次 | 业务记录、AI 审计、操作日志 |
| AI 失败率 | DeepSeek 失败或超时尝试数 / DeepSeek 总尝试数 | 5 分钟、1 小时、1 天 | `ai-usage.json`、系统日志 |
| 图片分割失败率 | 阿里云分割业务失败数 / 分割业务请求数 | 5 分钟、1 小时、1 天；轮询和结果下载不能重复计业务请求 | AI 审计、系统日志 |
| AI 延迟 | 每次供应商请求耗时的 P50 / P95；另报端到端业务完成耗时 | 1 小时、1 天；成功和失败分开 | AI 审计、请求日志 |
| 每用户 AI 成本 | 账户当日 DeepSeek 估算费用总和及人均值 | 每日及近 30 日；阿里云分割费用单列，不混入 | `ai-usage.json`、供应商账单 |

“用户校正”包括编辑模型草稿或回答、追问、备注、评论/划线及回复、`@神鸡`、明确保留/舍弃，以及主动触发基于该内容的回望或复盘。单纯查看、展开模型思考或原样接受回答不计校正。记录、回答与校正必须通过根记录 ID 或 `traceId / callGroupId` 关联；无法关联的数据计入“未知”，不得猜测归属。

首轮看板允许从每日离线汇总开始，不要求实时数仓。至少同时展示样本人数、分子、分母和统计窗口；少样本时不只显示百分比。登录只代表留存，不代表有价值使用，因此留存与闭环率必须并列查看。

## 状态量表

所有状态统一使用 1–5，方向一致：1 最差，5 最好。压力指标表达“压力状态”：1 为快要撑不住，5 为身心松弛，避免综合分中再做反向换算。

滑块默认参考上一次有效值；近 30 次均值只作为辅助提示。每次提交前仍要求用户触碰并确认，避免默认值被误当作真实记录。

## 同日多次提交

原始提交全部保留。时间线、日级趋势、延迟相关与日级综合分先按本地自然日分组，再对每项取算术均值。界面同时展示记录日数和提交次数，不能把备注或思绪计作状态提交。

长期趋势比较最近 7 个有记录的自然日与之前 7 个记录日，各天权重相同；空缺日期不填 0，也不把“7 个记录日”写成连续 7 天。同日情绪为 1、5，次日为 5 时，两日趋势均值为 `(3 + 5) / 2 = 4`。

## 综合状态分

日级综合值：

\[
S = 0.30M + 0.30E + 0.25L + 0.15P
\]

其中 M 为情绪、E 为精力、L 为睡眠、P 为压力状态，均为 1–5。展示分数换算为 `(S - 1) × 25`，范围 0–100。自定义指标默认只展示，不自动进入总分。

## 延迟相关线索

同名因素按自然日比较“出现因素日”“未出现因素日”和“出现后的自然次日”。因素首次出现时标为“单日观察”，出现至少 2 天后标为“初步线索”；记录达到 30 天、两组各至少 10 天且次日样本至少 5 天，才标为“可观察”。页面最多展示 3 条：先按置信层级排序，再比较可比样本量（有因素日与无因素日的较小值，加次日样本数），然后比较相对无因素基线的最大绝对差异；仍相同时按因素名稳定排序。任何结果都只称相关线索，不称因果。

## 思考留痕率

近 30 日思考留痕率 = 期间创建且留有用户主动痕迹的问题数 / 期间创建的问题总数；没有问题时显示空值，不伪造 0%。

用户主动痕迹包括初步想法、手写回答、提交或后续编辑 AI 草稿、编辑问题、评论或划线（含漂流记录）、追问、备注以及明确保留或舍弃。只有原样 AI 回答、且不存在上述任一行为的问题不进入分子，并在思绪时间线显示 `📫没有你的痕迹⏳`；未回答的问题不显示该标识。来源不明确的历史回答按用户内容处理，避免把无法证实的旧记录误判为纯 AI 回答。

## 体重衣物校正

始终保留秤上原始体重。当前暂定衣物重量模型：不穿衣 `0 kg`；轻便衣物均值 `0.5 kg`、95% 估计范围 `0.1–0.9 kg`；厚重衣物均值 `1.5 kg`、95% 估计范围 `0.5–2.5 kg`。

校正值 = 秤上体重 − 衣物均值。穿衣记录的体重区间 = `[秤上体重 − 衣物重量上限, 秤上体重 − 衣物重量下限]`。趋势可视化和后续分析使用校正值，并保留该区间；这个区间只表达固定衣物假设的不确定性，不代表体脂秤误差或医学统计置信区间。模型参数后续应依据实际衣物称量校准。

总重量未显示时，`measuredWeight / adjustedWeight / lower95 / upper95` 均为空；允许仅保存体成分或描述，该记录计入日录数量，但不进入体重曲线。不能根据体成分重量、比例或其加总反推总重。衣物校正只作用于总重量，不改变报告中的体成分读数。

## 体重与运动截图字段

字段定义、归一化与模型提示的实现入口为 `src/modules/health/index.mjs`。两类截图各支持 1 张，复用健康识别场景和 8 MB 输入限制；识别只回填，用户保存后才创建日录。数值缺失保存 `null`，文本/报告时间缺失保存空字符串；明确显示为零才保存 `0`，界面空白不转换为零。

| 类型 | 固定字段与单位 |
| --- | --- |
| 体重 | `measuredWeight` kg、`bmi` |
| 体成分 | `bodyFatMass / bodyWaterMass / proteinMass / boneMineralMass / muscleMass / skeletalMuscleMass` kg |
| 体成分比例 | `bodyFatPercent / bodyWaterPercent / proteinPercent / boneMineralPercent / musclePercent` % |
| 其他报告指标 | `visceralFatLevel` 等级、`basalMetabolism` kcal/日、`waistHipRatio` 比值、`bodyAge` 岁 |
| 运动 | `exerciseType` 项目名（如力量训练）、`durationSeconds` 秒、`distanceKm` km |
| 热量与心率 | `activeCalories / totalCalories` kcal、`averageHeartRate / maximumHeartRate` bpm |
| 心率区间 | `warmUpSeconds / fatBurnSeconds / aerobicSeconds / anaerobicSeconds / extremeSeconds` 秒 |

运动时长以整数秒保存，以 `HH:mm:ss` 输入和展示。活动热量与总热量独立保存，不相加；顶部“千卡”与独立“总卡路里”同时出现时分别转录，语义不清则留空并在描述中保留原文。平均心率不得高于最大心率、活动热量不得高于总热量、可见区间时长合计不得超过运动时长；保存时提示用户核对。

报告的测量时间 `measuredAt`、运动开始时间 `startedAt` 只有可识别时才回填。它们与用户指定的日录 `occurredAt` 分开保存；日期完全缺失时不猜报告时间，也不改动用户当前记录时间。月日缺少年份时沿用现有参考日期补年规则并在核对说明中注明，手机状态栏时间不能作为事件时间。

`description` 为可编辑描述，记录原报告文字、增减箭头及图中可见的相对变化；原报告评价须明确归因，不产生医疗诊断，不从曲线估计精确采样点。`verification` 保留识别缺口与核对提示。原图通过 `attachmentPaths` 保存，删除、恢复沿用日录附件生命周期。旧版纯描述运动和仅体重记录仍可编辑。

## 全量记录统计

“我的 / 统计”中的记录数是当前仍存在的数据快照，不是历史创建次数；删除一条记录后对应计数同步减少。内容统计按产品模块归组：此刻含状态，共参含长期对话，每日含睡眠、心率、体重和运动，念起含捕念，书间含书目和读书记录，拾句含善言，小物含小物，思绪含思考主题，日记含日记，回顾含个人实验和认知复盘。

互动统计同样按所属模块归组：正文批注含划线、评论、评论回复和 `@神鸡` 问答，思绪含追问和备注，日记含回望。已因正文变化进入漂流箱的批注仍是有效留存，只在划线或评论中计一次；`@神鸡` 按保存的问答轮次计数。

## AI 用量与费用

AI 用量只统计 `data/ai-usage.json` 启用后完成落账的 DeepSeek 请求，不估算或回填旧调用。每次请求记一条，包括失败请求；自动关闭思考后的重试是另一笔实际调用，也独立计数。成功数、失败数和 usage 未知数分别统计；官方输入或输出 `usage` 缺失、为 null 时 Token 与费用保持 0，不做推算。阿里云分割为非 Token API，只记审计，其费用需查供应商账单，不纳入这里。

- 输入 Token = `prompt_tokens`。
- 缓存命中 Token = `prompt_cache_hit_tokens`；缓存未命中优先使用 `prompt_cache_miss_tokens`，缺失时用输入减命中。
- 推理 Token = `completion_tokens_details.reasoning_tokens`。
- 回答 Token = `completion_tokens - reasoning_tokens`。
- 总 Token = 输入 Token + 输出 Token；输出 Token 已包含推理与回答，不能再次叠加。

费用以请求发生时固化的 DeepSeek 官方单价估算：输入未命中、缓存命中分别按对应输入价计算，推理与回答均按输出价计算。供应商原币金额只保留在内部流水用于审计，页面、经营估算、限额和告警均按当期换算系数显示人民币，不提供多币种切换。峰值时段按官方 UTC 工作日时段判断；中国法定节假日无法由本地标准库自动识别，因此恰逢工作日峰值时段的节假日实际账单可能低于看板估算。历史流水保留当次单价快照，后续调价不得改写既有费用。

输入方式分为 `text`、`vision` 和旧流水的 `unknown`。未知状态不算成功，未知耗时不进入平均耗时分母，旧数据已有费用原样保留。图片理解调用额外汇总调用次数、图片张数、原始图片字节数、Token、费用和耗时；图片本身仍按供应商返回的输入 Token 计费，不另外估算“图片 Token”。进程中止、双写失败等完整性边界见 `knowledge/observability.md`。
