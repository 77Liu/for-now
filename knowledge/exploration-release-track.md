# P1-P3 本地探索发布轨道

## 目标

在非主线分支上依次形成 P1、P2、P3 三个可运行探索版本，后一版本继承前一版本。探索版用于验证信息架构、交互、数据契约和风险边界，不等同于生产功能完成。

## 分支与发布

| --- | --- | --- | --- | --- |
| 基线 | `explore/nightly-base-20260928` | 不打发布标签 | 不长期运行 | 已建立 |
| P1 | `explore/nightly-p1-20260928` | `explore-p1-20260928` | `4191` | 已验证 |
| P2 | `explore/nightly-p2-20260928` | `explore-p2-20260928` | `4192` | 已验证 |
| P3 | `explore/nightly-p3-20260928` | `explore-p3-20260928` | `4193` | 已验证 |

所有分支、标签、数据和服务只保存在本机，不 push、不部署生产。每个阶段使用独立临时数据目录，禁止读取或复制正式账户数据。

## 探索边界

- 新功能放入独立“探索实验室”，不改变主记录流程的默认行为。
- 展示内容使用明确标记的合成样例，只进入探索数据域，不进入记录统计、个人上下文或 AI 证据。
- 能在当前无框架 Node/原生 JavaScript 架构内真实实现的交互应可操作并持久化。
- PostgreSQL、worker、多实例、向量检索、分片和多区域只提供本地契约、迁移检查、任务/故障模拟与可视化，不宣称完成真实基础设施切换。
- 外部连接器、社区、支付和 Harness 不连接真实第三方；授权、预算、审批、撤销、审计和数据删除路径必须可演示。

## 阶段范围

### P1

- API 契约与迁移检查面板。
- 个人上下文 V1：来源、时间窗、置信度、确认/否定/删除。
- Worker 任务队列、重试、死信与运行指标模拟。
- 思绪/备注附件原型、Todo 行动对象、小物加载策略对比。
- 外部小圈验证台账。

### P2

- 显式授权的位置记录与地点回顾。
- 主题写作工作台：材料、观点版本、大纲、草稿和来源。
- 只读外部连接器及撤销/删除。
- 候选知识图谱、捕念收件箱和离线同步队列。

### P3

- 受控 Harness：只读工具、预算、审批、暂停、回滚和审计。
- 选择性分享沙箱与分享副本隔离。
- 内容订阅/用量包实验。
- 混合检索、分片与多区域故障演练可视化。

## 每阶段交付

1. 独立分支和本地标签。
2. 隔离预览服务与健康检查。
3. 自动化回归和桌面/移动截图。
4. 示例内容及其“探索样例”标识。
5. 面向试用的「重点关注功能清单」。

阶段报告位于 `reports/exploration/p1-focus.md`、`p2-focus.md` 和 `p3-focus.md`。表中“已验证”仅表示探索原型通过本地验收，不改变 `README-TODO.md` 中生产主线任务状态。
