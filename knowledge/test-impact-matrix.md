# 测试影响矩阵

版本：1.1；生效日期：2026-10-12。本文是“改了什么就验证什么”的唯一选择正文。它决定受影响行为、最小专项和何时补上层验证；具体命令实现、fixture 和证据格式仍见 [`system-testing.md`](system-testing.md) 与 `package.json`。

## 维护边界

协调者维护矩阵的行为域、触发条件和返回状态。模块负责人只能提交新增或修改建议，并提供对应证据；测试维护者维护命令和夹具；任何 Agent 不得在任务卡、候选报告或聊天中另写一套当前测试选择状态。矩阵描述选择规则，不保存某个候选的运行结果；候选结果只引用控制面和绑定候选的证据。

矩阵不要求每次改动跑完整系统。每项验证必须回答三个问题：改变了哪个用户行为或不变量，哪个最小测试能证明它，什么变化会让旧证据失效。

## 选择算法

1. 以候选完整 tree、配置、依赖和运行环境为输入，按改动路径和调用链映射到行为域。
2. 先执行每个行为域的“最小专项”；若改动跨公共契约、持久化、账户隔离、部署或恢复，再追加对应的横切专项。
3. 若多个行为域需要同一命令，只运行一次并在证据中关联多个行为 ID；不得为每个需求复制同一回归脚本。
4. 只有候选冻结、共享契约变更、依赖/环境变化或既有证据失效时，才追加里程碑门或发布门。
5. 测试失败返回开发/集成节点；环境不可用保留 `blocked` 或 `partial`，不以重跑次数改变结论。

## 证据有效性

测试记录必须绑定 `candidateId`、完整 SHA/tree 或可重建 manifest、命令、行为 ID、环境、夹具、时间、结果和证据路径。以下变化会使相关旧证据失效：业务代码、公共契约、依赖、配置、提示词、静态资源、测试代码/fixture、数据库/浏览器/系统工具或关键运行环境变化。只有纯文档变化可以保留行为证据，但需要做文档链接和规则一致性检查。

结果统一使用：

- `PASS`：该行为在绑定候选和环境中有直接证据。
- `FAIL`：断言失败或发现真实缺陷，必须保留原始失败。
- `PARTIAL`：范围、浏览器、移动端、真实 provider 或生产条件仍未验证，写明补验条件。
- `BLOCKED`：外部权限、环境或资源使验证无法执行，写明责任人和解除条件。
- `NOT_RUN`：按矩阵未选择，或尚未开始；不能在发布摘要中省略成“已通过”。

同一候选、相同命令和相同证据目的已有有效结果时直接引用。允许重跑的理由只有：候选或环境变化、证据失效、独立复现、观察抖动需要确认，或验收目的不同。重跑必须说明理由，不能靠重复次数把失败变成通过。

## 日压缩到回答上下文的本机闭环验收

压缩、历史回填或其上下文消费者变化时，在本机用生产状态切片导入隔离 PostgreSQL，调用现有调度入口并模拟到期时钟，不修改生产时钟或在生产触发测试。生产切片保留合法来源、权限、日期、状态与引用；测试新增输入另作合成数据，不能替换异常任务来制造通过。

核对实际任务登记、供应商请求/返回、摘要校验与持久化、重启后读取、预算与通知回执；随后通过新思绪的实际回答入口检查摘要/七天趋势进入上下文并能被引用。AI参考必须独立标注，不能转写为用户事实或核心用户模型。已无来源/无变化的日期不入队，旧失败记录保留；新回填任务与旧任务分别可追溯，直到配置规定的历史起点，耗尽合法预算则等待，不越预算墙。

本机真实调用使用[上线前付费验收持续授权](release-authorization-policy.md#上线前付费验收持续授权)，并与无付费的有状态全局启动门分别保留结论。只有本地端到端链路完成才有发布依据；上线或上线后立即验收的授权仍从当前控制面读取，不把规则文字当作已执行结果。

## 候选级最小门

| 候选阶段 | 最小要求 | 不默认执行 |
| --- | --- | --- |
| 功能切片 | 受影响行为的最小专项、类型/构建检查、失败恢复断言 | 全站系统、压测、真实第三方费用 |
| develop 集成 | feat/工作树合入后，在 develop 对实际集成结果运行局部及跨域影响验证，保留绑定集成对象的证据 | 每次合并重复全量历史矩阵 |
| develop → release | 下述有持久化状态及脱敏生产快照的全局测试通过，才冻结 release；保留适用专项及部署/回滚准备 | 未受影响的付费或原生专项 |
| 正式观察 | 运行 SHA/制品一致、关键路径样本、错误/费用/资源和回退条件 | 用少量样本冒充长期 SLO |

## develop → release 有状态全局测试门

本节是发布前有状态全局测试的唯一规则正文。自本版本生效起，重新发布的候选也须遵守；历史未执行记录保留，不追溯改写为通过。

固定顺序：

```text
feat 专项验证
→ 合入 develop
→ 固定候选并构建
→ 获取脱敏生产状态快照
→ 隔离本地 PostgreSQL
→ 实际启动、readyz、重启恢复、核心冒烟
→ 通过后冻结 release
→ 部署与观察
```

1. **集成验证保留**：每个 feat/工作树合入 develop 后，验证实际集成结果中受影响行为及共享消费者；在控制面保留候选身份、命令、结果和证据引用。分支专项通过不能替代合并后验证。
2. **固定验证对象**：准备 develop → release 时，固定 develop 候选完整 SHA/tree、依赖、Prompt、配置与实际构建制品。不创建 release 来替代未完成的 develop 验证。
3. **采集真实状态**：用生产只读一致性快照保存任务状态、主/子目标及来源关系、单例状态、持久化结构、schema 和必要非秘密配置；记录采集时间、实际运行版本及快照摘要。脱敏必须保持引用对应、状态与结构约束，不得删掉失败任务或补齐缺失实体来制造通过。用户正文、原始媒体和凭据不进入回归快照、Git 或聊天。
4. **隔离持久化环境**：将快照导入独立本机 PostgreSQL 和临时数据目录；数据库版本、schema 与相关配置差异明确记录。不得连接生产数据库，禁用真实 AI/provider、通知、定时付费及生产凭据；必要替身只用于禁止外部副作用，不跳过实际启动恢复或持久化映射。
5. **执行全局链路**：用实际候选运行完整服务启动入口，证明监听成功、readyz 通过、进程保持存活；停止并再次启动，验证历史任务/状态恢复及持久化一致性。执行核心无付费冒烟，覆盖登录/读取、保存往返、任务状态与通知等适用核心路径。必须走真实 PostgreSQL 持久化；纯 JSON、投影专项、mock-only 回归或构建成功不能代替本门。
6. **绑定并裁定**：结果绑定候选 tree/制品、快照摘要、采集时间、本地环境、实际命令及启动/重启/核心冒烟证据。启动、恢复或核心行为失败返回 feat/develop 修复；快照或隔离环境不可用记录 BLOCKED，未执行记录 NOT_RUN，均不得冻结 release 或部署。通过后才进入 release 冻结及发布 SOP。
7. **避免重复与失真**：本门验证完整系统的有状态启动、恢复和核心链路；功能专项仍按上方影响矩阵去重选择，不要求每次 merge 重跑全部历史测试或付费矩阵。只有同一候选制品、快照及相关环境均未变化才可复用本门证据；仅文档提交可复用未变代码证据并核对候选身份。快照变化或影响启动/持久化/恢复的候选变化必须重新执行对应全局链路。

当前执行状态和命令实现完成情况只登记在唯一控制面；写入本规则不等于工具已实现或候选已通过。本门通过也不等于生产设备、真实 provider、告警投递或全部功能验收完成。

发布动作和失败回流以 [`release-and-observation.md`](../SOP/release-and-observation.md) 为准；本矩阵不重复维护发布状态或授权。
