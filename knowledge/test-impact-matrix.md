# 测试影响矩阵

版本：1.0；生效日期：2026-10-11。本文是“改了什么就验证什么”的唯一选择正文。它决定受影响行为、最小专项和何时补上层验证；具体命令实现、fixture 和证据格式仍见 [`system-testing.md`](system-testing.md) 与 `package.json`。

## 维护边界

协调者维护矩阵的行为域、触发条件和返回状态。模块负责人只能提交新增或修改建议，并提供对应证据；测试维护者维护命令和夹具；任何 Agent 不得在任务卡、候选报告或聊天中另写一套当前测试选择状态。矩阵描述选择规则，不保存某个候选的运行结果；候选结果只引用控制面和绑定候选的证据。

矩阵不要求每次改动跑完整系统。每项验证必须回答三个问题：改变了哪个用户行为或不变量，哪个最小测试能证明它，什么变化会让旧证据失效。

## 选择算法

1. 以候选完整 tree、配置、依赖和运行环境为输入，按改动路径和调用链映射到行为域。
2. 先执行每个行为域的“最小专项”；若改动跨公共契约、持久化、账户隔离、部署或恢复，再追加对应的横切专项。
3. 若多个行为域需要同一命令，只运行一次并在证据中关联多个行为 ID；不得为每个需求复制同一回归脚本。
4. 只有候选冻结、共享契约变更、依赖/环境变化或既有证据失效时，才追加里程碑门或发布门。
5. 测试失败返回开发/集成节点；环境不可用保留 `blocked` 或 `partial`，不以重跑次数改变结论。

| --- | --- | --- | --- | --- | --- |
| 前端页面、交互和生命周期 | `src/app`、视图注册、状态切换、事件处理、前端构建入口 | `check:modules`、前端类型检查/构建、受影响旅程 smoke | 跨页面状态、浏览器持久化或真实视觉变化时补 `test:frontend` / 浏览器评审 | 未改变的 API、fixture 和构建环境下的同候选行为证据 | `feat` 修复；契约变化回集成 |
| 后端 API 与公共契约 | 路由、schema、OpenAPI、错误包络、幂等头、游标 | 对应 API/契约专项 | 消费者、账户隔离、恢复或 OpenAPI 组合变化时追加相应集成测试 | 只改内部实现且响应、schema、错误和环境不变的行为证据 | `feat` 或集成；新候选身份 |

| 媒体、附件和前端加载性能 | 上传、派生、媒体 URL、图片/音频加载、重复拉取、闪烁 | 对应媒体事务/交互专项 | OSS/本地回退、清理补偿、性能或移动端变化时补专项 | 仅 UI 文案或非媒体路径文档变化 | `feat` 媒体切片；生产数据风险阻断 |
| 异步任务、时间意图和通知 | 队列、延迟执行、重试、定时、通知状态、关闭/重开 | 对应任务/通知专项 | 账户切换、幂等、失败恢复、重启或跨进程变化时补恢复验证 | 不改变任务标识、状态机、重试策略的同候选证据 | `feat`；共享状态变化回集成 |
| AI、第三方和费用 | provider、提示词、预算、账本、外部凭据、模型输出 | 本地替身/plan-only 和对应 provider 断言 | 获准 live、成本、审计、失败释放或生产身份变化时分别补测 | 仅内部纯函数且 provider 契约/价格/预算不变的本地证据 | 先回本地；真实外部限制为 `blocked`/`partial`，不盲重试 |
| 构建、模块边界和工程规则 | 依赖、模块登记、TS、生成物、提交门禁、规则文件 | `check:modules`、类型检查、构建、commit gate | 依赖/配置/生成物变化时补候选身份和集成验证 | 纯说明文档可复用行为证据，只补链接/格式检查 | `feat` 或 `docs`；规则冲突回协调者 |
| 部署、观测和回滚 | 部署脚本、环境变量、健康检查、监控、回滚开关 | deploy/monitor/rollback 专项 | 候选冻结后补预览、运行身份、回退条件和观察证据 | 同一制品、环境和回滚目标未变的运行证据 | 发布动作停止；按发布 SOP 返回 authorize/deploy/observe |

## 证据有效性

测试记录必须绑定 `candidateId`、完整 SHA/tree 或可重建 manifest、命令、行为 ID、环境、夹具、时间、结果和证据路径。以下变化会使相关旧证据失效：业务代码、公共契约、依赖、配置、提示词、静态资源、测试代码/fixture、数据库/浏览器/系统工具或关键运行环境变化。只有纯文档变化可以保留行为证据，但需要做文档链接和规则一致性检查。

结果统一使用：

- `PASS`：该行为在绑定候选和环境中有直接证据。
- `FAIL`：断言失败或发现真实缺陷，必须保留原始失败。
- `PARTIAL`：范围、浏览器、移动端、真实 provider 或生产条件仍未验证，写明补验条件。
- `BLOCKED`：外部权限、环境或资源使验证无法执行，写明责任人和解除条件。
- `NOT_RUN`：按矩阵未选择，或尚未开始；不能在发布摘要中省略成“已通过”。

同一候选、相同命令和相同证据目的已有有效结果时直接引用。允许重跑的理由只有：候选或环境变化、证据失效、独立复现、观察抖动需要确认，或验收目的不同。重跑必须说明理由，不能靠重复次数把失败变成通过。

## 候选级最小门

| 候选阶段 | 最小要求 | 不默认执行 |
| --- | --- | --- |
| 功能切片 | 受影响行为的最小专项、类型/构建检查、失败恢复断言 | 全站系统、压测、真实第三方费用 |
| develop 集成 | 共享契约和跨域影响矩阵专项、冲突审查、候选身份固定 | 与改动无关的历史矩阵 |
| release 候选 | 候选身份冻结、矩阵中所有发布相关域、部署/回滚/观察准备 | 未受影响的付费或原生专项 |
| 正式观察 | 运行 SHA/制品一致、关键路径样本、错误/费用/资源和回退条件 | 用少量样本冒充长期 SLO |

发布动作和失败回流以 [`release-and-observation.md`](../SOP/release-and-observation.md) 为准；本矩阵不重复维护发布状态或授权。
