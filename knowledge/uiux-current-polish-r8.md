## 3. 页面职责与布局

### 首页

保持现有一级“今日 / 所见 / 所思 / 我的”和“此刻 / 共参 / 每日”的层级关系。本轮只改此刻、思绪与详情；其它栏目在原型标 ↗ 并打开线上现有页面，不假装已完成改版。

桌面：侧栏156px，主区左右56px，栏目54px。题名和日期同一行，记录按钮与换组同行。工作区主列＋右栏（最小230px，列距48px）；主列是思绪＋两个辅片段。曲线在右栏顶部，小物在其下；行动与习惯位于主内容底部并默认折叠。高度≤700px缩短栏目与段距。保留既有三段内容，不添加大段口号。

手机：左右20px，题名与日期一行，主按钮44px；思绪占整行、书笔记与拾句并排；小物在后、曲线紧接；底部导航固定并留安全区。整段片段是可打开区域，右上↗提供提示，不再为每条预览额外占一行按钮。链接的可访问名称包含“查看原文”。

高度断点以 CSS 像素视口为准：≤740px 预览收短（主标题最多2行、主正文1行、辅正文2行），小物故事进详情；≤620px 主标题1行，小物与曲线同行、小物日期进详情。没有隐藏三段内容或状态功能。正常手机主正文16px、紧凑15px、极短14px；不继续递减字号去适配任意窗口。

首页“不滚动”指默认、未展开、正常字体的预览态，不要求全文同屏。长内容由 line-clamp 截断，原内容不删改，点击进入原文。行动展开、编辑、详情、字体放大以及小于已观察的视口允许正常滚动；禁止用 document overflow:hidden 掩盖溢出。浏览器工具栏、safe-area 和第三方容器挤压应在实施阶段用实际设备校准。空内容减少展示，不制造占位假记录。

不添加“随机回看 / 最近状态”等模块名。来源、日期、量表名称不是装饰标题，保留以便判断内容来处。首页三条内容继续使用已有 `createHomeMemoryPool / selectHomeMemories`：只取用户可访问、未删除、未舍弃的内容；AI 派生内容不冒充用户表达；先保证思绪/书笔记/拾句来源覆盖，数量不足则少展示，不重复凑数。原型的换组为确定性虚构示例轮换，生产继续复用现有随机逻辑。

### 时间线

保留日期轴、按月分组、发生时间/提交时间排序与标签筛选。首屏不是新 AI 总结或画像。

每条：日期＋时间 → 问题题名 → 一条有类型身份的预览 → 标签和打开。桌面典型行高125–155px，手机约145–175px；基于1440×900和390×844，当前种子内容分别约4–5条、3条完整记录。换行、辅助导航、字体放大时允许数量下降，不能通过缩小正文硬凑条数。标题通常1–2行；默认预览1行，全文进详情阅读。

预览优先级：最新有效、无追问父节点的**用户回答** → 该主题明确关联的初步想法 → 仅问题。把用户回答在视图中称作“我的结论”；不将 AI answer 当成结论，不因类型字段同名而误判。选中最新结论依据发生时间，提交时间作同值的稳定排序；模型回应与追问回答不参加。修改旧结论不能仅因提交时间变化抢占主结论。生产无可靠初步想法锚点时保留已有初始关联；不得把删掉初步想法后的一条新想法自动晋升为初步想法。

“当前结论”是阅读视图的派生关系，本轮不增加用户画像或新的持久化 currentId 字段。原型的 currentId 只是本机示例辅助字段。

### 详情

单一页面标题就是用户的问题。发生时间和标签在上，编辑问题在标题旁；右上 ⓘ 与回收站属于辅助操作。正文按发生时间正序，理解同一问题如何展开；主列表维持倒序方便浏览。

正文统一宋体18px/1.85，手机17px/1.8；不通过更换正文字体区分身份。初步想法/想法＝叶形＋浅绿描边；经历＝记录形＋灰玉小标；我的结论＝勾形＋实心叶绿，当前结论带淡绿局部底；AI应答＝星形＋晨光浅底与边标。身份不仅依赖颜色，保留明确中文名称。

每条显示自己的发生时间；编辑在固定位置；修改历史、批注与可恢复删除在 ⋯。不常驻“用户原文”“版本1”；用户修订 AI 内容仍保留 AI 来源，不自动变成自己的结论。模型依据与置信信息在生产既有来源面板内保留，不能因为原型未模拟就删去。

主要动作：补充（默认想法，可选经历/我的结论）、追问、给我回答/重新回答。手机固定在底部主导航上方，打开编辑时隐藏该操作栏，使用编辑器自己的保存/收起。AI 应答内只保留追问这次应答，避免重复放一个同义重新回答。追问保留与原问题/具体应答的关联，自己回答与模型回答明确分开。

## 4. 类型重叠与现有数据映射

| 用户选项 | 要写的内容 | 现有对象 | 说明 |
|---|---|---|---|
| 经历 | 事实、行动与结果 | 用户 `record` 子项 | 更直观的视图名称，不新增“经历系统” |
| 想法 / 初步想法 | 感受、解释、猜测 | 用户 `idea` 子项 | 初步想法是主题最初关联的想法；后续统一叫想法 |
| 我的结论 | 此刻对主题的回答 | 非 AI `answer` 子项 | 新证据可推翻；不是系统确认的用户永久事实 |
| 追问 | 一个需要继续回答的问题 | 根对象 `followUps` | 独立动作，保留自己回答与AI应答 |
| 批注 / 备注 | 对特定片段或主题的补充说明 | 既有 annotations / remarks | 不混入“经历”的分类入口；主题更多中有独立备注入口，原备注保留“备注”身份 |
| AI 应答 | 模型生成或模型来源的修订 | AI `answer` | 不进入用户结论优先级 |

三种补充存在语义上的自然相邻，但录入时按“发生了什么 / 我怎么理解 / 我的答案”区分；不能迫使用户先做复杂分类。默认想法，一次选一种，保存后可修改。备注不能因为精简菜单被自动迁移成经历；主题备注应在主题更多中保留原有入口，片段批注保持原定位关系。生产划线、标记、评论与漂流批注沿用原协议，本机原型只模拟整段批注，不宣称实现文本锚点。

## 5. 状态与交互契约

| 操作 | 正常反馈 | 中断/恢复 |
|---|---|---|
| 按钮展开记录 | 问题必填、初步想法可选、发生时间、标签可选；保存后进详情 | 关闭保留本机草稿；空问题内联提示；保存失败不清草稿 |
| 列表进入/返回 | 点标题或打开进入；返回原首页或原时间线 | 同一次使用保留列表搜索、标签、排序和滚动；返回来源在本机会话保留 |
| 修改内容 | 保留文本、类型、时间与图片；保存局部刷新 | 先写入成功再显示完成；空间不足明确未保存 |
| 修改历史 | ⋯→修改记录；查看旧文本并恢复为新修订 | 不暴露版本数字，不覆盖历史 |
| 删除 | 菜单确认后移入回收站，提供撤销 | 原型不永久删除；生产保留已有保留期与权限 |
| 舍弃 | 从默认列表和首页候选池隐藏 | 可重新保留；生产回收站负责删除，舍弃应回到既有取舍/筛选视图 |
| 追问 | 问题与关联节点一并保存；自己回答可随后补 | 保留关联，不把每次追问变成孤立主题 |
| 请求回答 | 新回答追加，旧回答可继续读；允许取消/失败后重试 | 原型固定本地模拟，不发送记录，不调用模型；生产保留任务、来源、冲突与同步状态 |
| 状态记录 | 现有情绪/精力/压力/睡眠四项，逐项确认才保存 | 默认滑块不算已确认；关闭保留草稿；因素与时间保留 |
| 情绪曲线 | 同日均值，固定1–5量表；低值不标红，不做评价 | 缺失日断开，不补零；详情提供数值与样本数 |
| 小物打开 | 图与名字进入同一详情；浏览不同示例、编辑名字/日期/故事 | 固定展示区，切换不随机改变位置；图像失败保留文字入口 |

按钮最小触控区44px；窄设备部分文字按钮视觉高度小于44px时通过透明扩展区补足。聚焦有叶绿轮廓，原生dialog承担焦点约束，Esc关闭；返回焦点到入口。默认不自动滚动随机内容、不抢输入焦点。`prefers-reduced-motion`关闭平滑滚动。长标题不水平溢出，表单顺序自上而下，颜色状态有文字替代。

生产未确认写入时使用已有待同步/正在同步/冲突状态，不把本机保存提示误当成服务端确认。此原型没有网络同步、认证、真正模型生成、Markdown公式渲染、精准文字批注或完整其它栏目。

## 7. 小物摆放：本轮尺寸覆盖

沿用 `reports/ui-ux-v0.5-review-r2/小物摆放规范.md` 的有效边界、视觉锚点与安全区原则；该旧版展示区尺寸在本轮首页被以下紧凑尺寸覆盖。只改变呈现，不增加用户缩放/旋转编辑器。

| 小物安全展示区 | 桌面 | 常规手机 | 紧凑手机≤740高 | 极短手机≤620高 |
|---|---:|---:|---:|---:|
| 区域 | 80×121 | 68×85 | 58×71 | 43×62 |
| 内部安全边距 | 5 | 4 | 3 | 2 |
| 细高物体可见最大尺寸 | 69×114 | 56×80 | 48×67 | 40×59 |
| 质心补偿上限 | ±4 | ±3 | ±2 | ±2 |
| 文本 | 名字+日期+2行故事 | 名字+日期+1行故事 | 名字+日期，故事进详情 | 名字，日期/故事进详情 |

以上为不同材质对象的布局安全槽，不是把所有图片固定拉成细高形。扁平纸张、圆润物体均在槽内等比 contain。桌面纸片75×75，鸟形75×85；常规手机纸片66×61、鸟形62×70。紧凑与极短断点同样使用可见安全界限夹取，保持原比例，不因旧的纸片尺寸覆盖新槽而越界。原型仅为三件示例预设摆放，生产需实现下述有效边界规则。

透明抠图计算有效边界 B；用 `s=min(maxW/Bw,maxH/Bh)` 等比缩放，实物底部锚定基线，纸片/悬挂物视觉中心锚定区域中心。横向质心补偿受安全区夹取约束。极细长物体保持真实比例，不拉粗。低清不超源图有效分辨率，原片提供放大查看。多连通物体不裁掉细链或小零件。

源图不透明或边界失败：保留照片整体、`object-fit:contain`、视觉中心摆放；不得假装已抠图。图片失败显示名称与查看原件，区域预留尺寸。已有阴影不重复添加；新阴影透明度≤8%，仅地面实物使用。自动旋转默认0°；原型手写纸片-5°是候选人工布置，不是生产自动规则，未确认前按0°实施。

本轮原型用三张历史演示素材，按预先确认的尺寸/偏移展示；没有实时跑全对象边界算法。前端实施应复用已有 `displayPath / cutoutPath / previewPath` 的优先级；边界缓存与源版本绑定，可以作为展示缓存而非新的用户数据。图片渲染到安全区，再排名字与按钮，任何物体都不能盖住文字。

## 8. V0.5.6 实施顺序

1. **基础与首页**：统一Token、导航/焦点、记录按钮展开；接现有内容池、原文路由、小物与真实情绪数据。交付双端首屏，不增加阶段判断。
2. **思绪列表**：压缩标题区，迁移日期轴/筛选/时间排序；可靠区分用户回答与AI，生成带身份的一条预览。旧数据未知来源应保守展示，不编造结论。
3. **详情与编辑**：单一主题标题、统一正文/身份、逐条时间与编辑、主要操作收敛；接回现有备注/批注、历史、取舍、删除恢复、模型异步与同步冲突。手机写作状态隐藏浮动操作。

不提前指定下一小版本号；线上已是v0.5.5，应由实际开发分支版本与需求池确定。生产验收发生在用户批准候选之后，不用设计截图当作实施成功。

### 后续设计验收清单（未执行测试）
- 当前真实菜单功能都有映射或明确保留入口；没有丢失备注、取舍、批注、AI来源或任务恢复。
- 一眼可指出页面标题、用户问题、当前显示的内容类型；“初步想法”和“我的结论”不用辨颜色也分得出。
- 桌面4–6、手机3–4为典型默认记录密度目标；长标题/字体放大不会溢出或隐藏必要动作。
- 首页三条内容和一件小物的路由准确；换组不打断输入，不伪造来源。
- 编辑内容/时间后历史可查；删除恢复保持关联；同步与冲突不能假装成功。

## 9. 交付与原型边界
