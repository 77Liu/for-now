# 日志与审计

本文档是系统日志、用户操作审计和 AI 调用审计现状与字段约定的单一事实来源。

## 当前结论

| 类别 | 当前状态 | 问题追溯能力 |
| --- | --- | --- |
| 系统日志 | 已建立 v1 | API 完成、异常、持久化失败、AI 与外部依赖、后台任务均写入结构化事件，可按请求关联 |
| 用户操作日志 | 已建立 v1 | 关键写请求及 store、settings、auth 的资源变化记录操作者、结果与字段摘要 |
| AI 用量账本 | 已建立 v2 | 可按账户统计每次实际请求、失败、重试、图片输入、Token、费用和耗时 |
| AI 调用审计 | 已建立 v1 | 可用 `traceId / callGroupId / callId` 还原一次业务请求中的每次模型尝试，并查看实际 SP、UP、历史、参数、响应和错误 |

以上能力已随生产技术基线 `908004b50d3f` 部署并验证。常规请求可跨系统日志、操作审计与 AI 调用追踪；最低运行告警已完成飞书真实投递，但尚不具备事务级审计保证或集中式指标平台。

## 系统日志与操作审计

- 系统日志：根数据目录 `logs/system-YYYY-MM-DD.ndjson`，包含所有账户的诊断元数据，只有服务进程和运维人员可读取。
- 操作审计：本机 `logs/operation-YYYY-MM-DD.ndjson`；账户模式位于 `users/<user-id>/logs/`。未认证的失败请求记入根目录。
- 公共字段：UTC 时间、结构版本、运行版本、事件与模块、`traceId`、操作者 ID、方法、路径；请求完成时附级别、应用状态、HTTP 状态、耗时、结果、错误码、变更数。
- `data.changed` 在数据提交后记录集合、资源 ID、创建/修改/删除、变化字段名及脱敏后的前后 SHA-256。正文、密码哈希、会话令牌及密钥本身不在操作日志中保存；密钥变更只记录是否已配置。
- 写请求无论成功、校验失败、越权、未找到或模型失败都会记录完成结果；SSE 的应用失败与 HTTP 200 分开记录。关闭回答弹窗仍继续生成，不能据此将调用计作取消。
- 系统异常只记录错误类型、机器码和栈位置，不序列化整个 Error 对象或它附带的模型输出；普通 stdout 不保存正文。
- JSON 读取只在文件不存在时使用默认值。解析或 I/O 失败保留原文件并返回受控错误；数据写入使用 `0600` UUID 临时文件加原子重命名。
- 根数据目录、账户目录、附件目录和日志目录固定为 `0700`；JSON、迁移备份、附件与日志文件固定为 `0600`。启动和本地到云端迁移都会修正已有文件权限，不依赖 umask。
- 公网中台只消费主应用生成的脱敏聚合，不读取上述正文日志。聚合日志最多返回最近 100 条请求状态或错误事件，只含路由、状态码、耗时和 Trace ID；不返回错误正文、请求体、模型输入输出或附件。中台自己的登录、退出、角色分配与会话记录保存在 `/srv/for-now-platform/data/access-control.json`，与业务审计分开。

## AI 用量账本

位置：

- 本机模式：`data/ai-usage.json`
- 账户模式：`data/users/<user-id>/ai-usage.json`

v2 每条记录包含：

- 身份与关联：`id`、`callId`、`callGroupId`、`traceId`。
- 时间与结果：`createdAt`、`completedAt`、`durationMs`、`status`、`httpStatus`、`errorCategory`、`errorCode`。
- 模型信息：`provider`、请求模型、供应商返回模型、供应商请求 ID、场景、档位、思考强度。
- 尝试信息：当前尝试、最大尝试次数、重试原因、是否流式、响应格式、`maxTokens`、结束原因。
- 输入形态：`text / vision / unknown`、图片数量、总字节数、MIME 类型、宽高；账本不保存图片正文或 Base64。
- 容量摘要：历史消息数、请求字符数、回答字符数、推理字符数。
- 计费信息：是否取得官方 usage、原始 usage、标准化 Token、峰谷时段、单价快照和费用拆分。

每一次已完成落账的 DeepSeek 请求计一条，包括失败请求和自动重试。`calls` 因而不是业务操作次数；成功数、失败数和 usage 未知数分别统计。官方输入或输出用量缺失、为 null 时，Token 和费用均保持 0，标记 `usageKnown=false`，数值型原始字段仍保留备查。旧版本升级先备份；旧流水原有费用保留，未知输入形态、状态和耗时不伪造。

## AI 调用审计

位置：

- 本机模式：`data/logs/ai-audit-YYYY-MM-DD.ndjson`
- 账户模式：`data/users/<user-id>/logs/ai-audit-YYYY-MM-DD.ndjson`

三类日志文件均为 `0600`、目录为 `0700`。默认保留 30 天，可通过 `AI_AUDIT_RETENTION_DAYS` 设置为 1–3650 天；初始化和每小时后台任务清理过期日文件，保留 UTC 截止边界整日。用量账本不随审计日文件清理。

每个尝试先写 `status=started`，结束后以同一 `callId` 写终态；终态记录包含：

- 版本、类型、调用 ID、调用组 ID、请求追踪 ID和账户 ID。
- 供应商、场景、档位、尝试序号、重试原因、起止时间、耗时和状态。
- 实际生效的 SP、UP、历史消息与模型参数。
- 图片 MIME、字节、宽高和 SHA-256；不重复保存图片二进制或 Base64。
- HTTP 状态、供应商请求 ID、返回模型、结束原因、回答、`reasoning_content`、原始 usage 和费用快照。
- 失败类别、错误码和受限长度的错误响应。

API Key、Cookie、会话令牌、邀请码和密码不进入 AI 审计。单个文本字段默认最多 100 万字符，超过部分显式标记截断；可用 `AI_AUDIT_TEXT_LIMIT` 在 1 万至 500 万字符间调整。

完整 AI 审计含高度敏感的个人正文，不通过统计 API 返回，也不写入普通 stdout。备份、导出和删除时应把它视作与 `store.json` 同等级的用户数据。

阿里云 `SegmentHDCommonImage`、同类目 `GetAsyncJobResult` 轮询和结果 PNG 下载通过同一私有审计存储记录独立调用 ID、共同调用组、图片摘要、实际参数、供应商请求 ID及响应摘要；SDK 自动重试关闭。分割是非 Token API，SP/UP、推理和 Token 为 N/A，费用需查阿里云账单，不进入 DeepSeek 统计。SDK 内部上传授权与传输包含在分割尝试内，未拆分为传输级流水。测试分割明确标记 `mocked`，不代表真实服务验证。

空正文、内容过滤、长度截断、无终止标记的 EOF、格式错误、HTTP 失败和超时有不同错误码。长度截断的部分回答只进入审计，不保存为业务成功结果；日记辅助等允许降级的场景，只有空正文才关闭思考重试一次。

## 关联规则

- 每个 HTTP 响应返回 `X-Request-Id`；合法的上游 `X-Request-Id` 会沿用，否则服务端生成 UUID。
- 同一 HTTP/后台业务链使用 `traceId`，一次模型任务内的重试共用 `callGroupId`。
- 每次实际供应商请求有独立 `callId`；重试不会覆盖首轮失败记录。
- 正常落盘时，一条 DeepSeek 用量记录对应同 `callId` 的开始和终态审计；阿里云调用只进入审计。

## 访问、备份与删除

- HTTP 对外使用 HTTPS；当前文件未做应用层静态加密，ECS 磁盘与 OSS 加密配置仍需在供应商控制台持续核实。
- 云端持久图片位于私有 OSS 附件前缀，通过登录后的应用代理读取；结构化记录与日志仍在实例数据目录。生产迁移和桶策略的状态见 `knowledge/operations-capacity.md`。
- 页面没有原始审计读取或下载接口。运维按账户授权导出该账户目录，禁止交付根系统日志或其他用户目录。
- 审计随一致性数据快照一起备份；本机备份保留 7 天，OSS 历史副本由桶生命周期控制，需单独核实。
- 删除业务记录不会立即删除对应审计，在线审计在保留期届满时清理；账户导出/整体删除目前需运维操作，同时处理其备份副本，不能只删除 `store.json`。

## 告警

`for-now-monitor.timer` 每 5 分钟检查主应用与公网中台的 systemd/`readyz`、磁盘 70%/85%、备份超过 26 小时、连续 5 次 AI 失败和当日总 AI 费用达到 ¥36.00。状态变化、持续异常和恢复通过飞书自定义机器人发送，费用统一展示人民币，消息不含用户正文、密钥或 webhook。详细阈值、去重和真实投递测试见 `knowledge/operations-capacity.md`。

## 已知边界与发布观察

- 进程被强制停止时，可能只留下 `started`；没有终态的调用用量/费用未知，不能由开始记录推算。请求中途日志盘故障可能导致开始记录也丢失。
- 业务写入、用量账本与 NDJSON 不是同一事务。任一日志失败会记录 `logging.failed / ai.log_failed`，不覆盖已经提交的数据，也不让已完成的模型回答自动重试；尚无自动补写和对账。
- 在线日志按时间清理但未设单日容量上限，JSON 账本会增长并在统计时全量读取。当前单进程队列不支持多实例共同写文件。
- 最低告警依赖服务器配置的飞书 webhook；当前已完成测试消息、受控服务停止严重告警和恢复通知的真实投递。每次发布后仍需观察 30 分钟：检查新 `storage.*_failed / logging.failed / ai.log_failed`，检查无终态调用、AI 失败与重试量、响应耗时和磁盘增长；任一持久化故障或账户串写立即停止发布并恢复上一版本。
- 本地可复核命令：`npm run test:observability`、`npm run test:auth`、`npm run test:monitor` 和 `npm test`。当前生产验证、发布结论与未关闭项见 `reports/mvp-operations-validation-2026-09-27.md`。
