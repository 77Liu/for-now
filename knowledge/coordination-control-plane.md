# 唯一协调控制面与版本事件协议

版本：2.5；生效：2026-10-16。本文是当前状态、事件记录、更新入口与归档的唯一正文，覆盖旧的内嵌历史和逐次状态提交约定。

## 三个记录对象

| 对象 | 路径 | 用途与写入方式 |
| --- | --- | --- |
| 当前控制面 | `coordination/current.json` | 覆盖更新，仅保留当前有效范围、活动任务、候选、授权、阻碍、下一动作、运行事实与证据引用 |
| 版本事件 | `coordination/versions/<版本>/events.jsonl` | 按发生顺序追加本小版本的有意义事件；已有事件不得覆盖，纠错追加事件 |
| 收口快照 | `coordination/versions/<版本>/terminal.json` | 小版本完成或明确取消时保存完整收口控制面及结果，归档后只读 |

当前控制面是当前状态唯一正文，由 `canonical_path` 指定位置；该字段必须保存项目根目录相对路径 `coordination/current.json`，项目根目录只在 `PROJECT_RULES.md` 的“所在根目录”维护。只有 Owner 指定的协调者维护。其他工作树、README、需求池、看板、版本记录和聊天只能引用，不得维护第二份当前状态或直接修改当前 JSON。

当前控制面仅保留当前有效结论，禁止嵌入历史事件、旧任务过程、已被替代的结论、已解决缺口、旧阶段结论、已结束候选和旧发布尝试。仍影响行动的决定与限制只保留当前值，形成过程通过事件引用追溯；有效验证只保留适用对象、当前结论、仍有效限制与回执引用，验证细节及源码哈希留在对应回执，不在控制面重复保存。尚未解决、尚未验证或仍影响当前行动的失败，必须作为阻碍、待验证项或限制保留，并引用原证据；只有已被有效验证关闭，或已有明确去向且不再影响当前范围时才移出，不得仅因时间过去或出现新结果而移除。历史失败不得改写为通过。历史归档不能作为当前状态或新任务基线。协调者通过唯一入口清理，不由 monitor 直接改写。

精简逐项判断：已被替代的过程回到原事件/回执；可复用证据只留适用对象、结论及引用；未解决问题、有效限制、授权及下一动作留在当前正文。重复限制仅在适用对象和含义一致时合并，并保留对应证据关系；不确定是否失效的限制先保留并标待核对。临时引用失效时查找持久原件，无法取得等价证据就标无法复核，不能以删除引用代替解决。运行观测必须保留时间，不把历史健康当实时状态。通过唯一入口记录移出内容的原位置与去向并核对回放，不另建常驻历史摘要或第二份 current，也不为精简设比例目标。

不得手工维护与结构化字段重复的展示摘要；入口删除此类摘要，展示需要时从当前结构化字段生成。迁移前记录仍通过原 Git 和事件引用追溯，不改写原失败或制造新验收。

## 事件标准

**改变后续行动，或证明关键动作已发生的决定与结果，必须记录为事件。**

| 必须记录 | 不单独记录 |
| --- | --- |
| 需求选择、范围、验收标准变更 | 排版、措辞、字段顺序调整 |
| 基线变更、候选冻结或替换 | 同一状态的重复描述 |
| 任务派发、负责人或写集变更 | 同一任务的重复提醒 |
| 授权、暂停、恢复、撤销 | 无变化轮询 |
| 实现接入、关键验收结论 | 不改变结论的逐条输出、重复测试 |
| 缺陷确认、返工、延期、阻碍解除 | 未改变判断的调查过程 |
| 推送、发布、部署、回滚实际结果 | 聊天进度复述 |
| 影响行动的状态纠正、版本收口 | 普通文字纠错 |

事件必须有唯一 ID、版本、事件类型、发生及记录时间、原因、变化字段及必要前后值、证据引用，并区分计划／决定／实际结果。普通事件不复制完整控制面；不存在的字段与空值必须可区分。完整状态仅在必要恢复检查点和版本收口保存。补录标明补录及原来源，不能把补录时间当发生时间，也不能凭计划补写动作成功。

记录改变行动的决定与关键实际结果，不记录每一步工作叙事。同一切片的普通补充说明合并表达，不为每条解释、提醒或调查过程生成事件；后续真正改变范围、授权、负责人、写集、候选或关键结果时及时落盘，不为合并记录延误必要决定。未改变契约的实现细节由 Git 追溯，验证细节由绑定候选的回执承载，事件只引用，不重复抄写。

## 项目记录的哈希与集合差量

本节是项目自行维护的控制面、事件、回执及其他记录的哈希约定唯一正文。机器保存和比较完整哈希，并注明对象类型、仓库或文件路径；六位简称仅供展示，不参与完整性校验、去重、幂等、候选绑定或授权核对。候选 `sha/tree` 分别保存完整提交/树对象标识；源码、快照、状态和请求摘要保留算法及完整值。展示的简称有歧义时延长或显示完整值，不能以相同前缀认定对象相同。

Git 对象标识、依赖锁校验值、签名及认证等协议字段保持完整。旧记录保持原样：已有完整值按原算法完整比较，不能退化为前缀比较；仅有六位值的记录只能提供有限历史核对，不能补造完整值或单独证明新候选身份。能从对应原对象独立核验完整身份时，在新回执中记录完整值及旧证据引用；不能核验时保留未知。新格式须在生成、回放、去重和引用消费者完成兼容验证后启用，不因规则预改就直接改写当前状态或旧事件。

证据、任务及其他具有稳定ID的数组集合，按稳定ID识别新增、删除与字段修改，禁止按位置重写后续内容。已有集合使用其 `id`；以 `key`、`requirement_id` 或 `iteration_id` 标识的集合沿用该身份，重复身份拒绝。无稳定ID的顺序值数组仍按其原顺序契约处理，不伪造身份。

集合顺序变化独立表达，不复制各项正文；具有业务意义的顺序必须可回放，不能通过忽略实际变化缩小日志。新增与删除记录对应项，修改只记录该ID下变化字段。格式3和格式4按此契约回放，格式2的位置差量保持原契约，不修改旧事件。

## 唯一更新入口

协调者通过 `npm run coordination:update -- <动作> --input <JSON请求文件>` 更新；入口以 `package.json` 为准，实现为 `scripts/control-plane-update.mts`，产物只在忽略的 `.build/`。请求文件不在参数中展开，不含凭据或用户正文。

请求包含 `actor`（当前协调者聊天 ID）、`expected_revision`、`iteration_id`、完整目标 `state`；有意义变更另含 `event` 的 `id/type/phase/reason/evidence`，`phase` 使用 `plan/decision/result`。`close` 另附 `closure.status/result/checks`，五类核对各有结论、原因、事件 ID 和证据引用。变化记录、修订和收口快照只能由入口生成，不接受事件输入注入；请求的完整目标 state 是更新输入，不等于事件保存完整状态。准备请求时从当前 JSON 程序化读取并修改本次必要字段，保留其他字段及 expected_revision 校验；不要求模型手工重新生成整份状态，也不另存第二份当前状态。

1. 读取当前 revision、模式与事实回执；请求注明协调者和预期 revision。
2. 范围、基线、负责人、写集、授权、候选、阻碍、下一动作或关键结果变化必须提供事件类型、原因、证据。普通措辞修改可不生成事件；结构化行动字段仍须事件，不能借“改措辞”绕过。
3. 校验后先追加事件并持久化，再原子替换当前控制面。事件保存失败，禁止推进依赖该变更的动作。
4. 同一事件 ID 重试不重复追加；同 ID 不同请求拒绝。事件已持久化而状态未更新时，从已验证旧全量事件或恢复检查点回放变化恢复，不重复外部副作用。新格式的变化与恢复结果按本节对象对应的完整哈希校验；旧格式沿用明确的历史兼容边界，跨版本引用、未收口恢复和审计使用同一回放契约。
5. 协调者单写；其他角色只产出回执，协调者独立核对后由入口更新，不能直接照抄回复推进状态。

`apply` 更新状态，`audit` 核对事件与当前状态持久化一致性，`handoff` 启动新版本，`restore-held` 恢复已有未收口版本，`close` 核对收口、保存快照并清理当前状态。交接请求含 `from_iteration_id`、目标 `iteration_id`、完整新状态及 `iteration_handoff` 事件。恢复请求含当前来源 `from_iteration_id`、目标 `iteration_id` 和 `held_iteration_restored` 决定事件；事件详情引用 `target_iteration_id`、`held_event_id`、`held_state_after_hash`，证据须包括 Owner 信号与当前授权依据。锁或持久化不一致先恢复现场，不盲删锁或继续派发。入口实现验证前，不宣称自动防漏或技术强制。

`handoff` 用于当前版本已验证并冻结、状态为 `READY_WAIT_OWNER` 且没有活动任务时启动下一版本；它不等于发布或收口，不把前版改记为完成或取消，也不创建 `terminal.json`。候选冻结依据[测试矩阵](test-impact-matrix.md#必需门的来源与独立核对)确定的 `required_gates`、规则版本与 `test_matrix_ref`；入口须核对适用必需门是否漏列、回执是否绑定候选和环境、结果是否均为 `PASS`，不能只检查候选自报子集。矩阵之外的 `PARTIAL`/`NOT_RUN` 项如实保留。现有入口从当前已登记 Git 规则基线读取机器策略，检查发布底线和实际差分触发门；未定义的语义影响仍由独立审查补充。首次启用须先按原流程接入含策略的规则基线；基线没有策略时拒绝放行，不退回自报清单。

协调者提供新版本完整目标状态和 `iteration_handoff` 决定事件。入口把事件追加到来源版本事件链，目标版本用 `started_by` 锚定该事件；目标状态的 `held_iterations` 保存未收口版本、其状态事件引用、完整状态摘要、候选 SHA 与授权摘要。候选、授权和未收口状态的完整内容由被引用事件及其可验证回放提供，不能在当前状态复制整份旧控制面。后续恢复和再次转移以不可变转移事件建立新的事件链段；递归审计只需核对到所引用的锚点事件，不要求该事件永远是来源日志末尾，也仍按对应事件格式校验状态和引用。

`restore-held` 用于明确的 Owner 信号要求恢复某个 `held_iterations` 中的版本。当前不得有活动实施任务；协调者通过 `held_iteration_restored` 决定事件记录 Owner 信号和当前授权依据。恢复取回原版本范围、候选、授权和任务状态，并保留当前控制面的规则基线、协调者身份及最新运行观测。它本身不授予发布权限、不等于发布或收口，也不覆盖已有事件或收口快照；原版恢复后可继续使用 `close` 正常收口，先前版本仍可再次恢复。历史授权若不再包含于当前授权，恢复拒绝重新启用它。恢复失败按相同事件 ID 与请求重试；转移、恢复和收口均使用事件锚点划分历史段，`audit` 核验每段与引用完整性。

## 门禁选择与执行入口

沿用 `npm run coordination:update -- gate-plan` 读取已登记规则版本的机器策略及实际候选差分，不执行测试。候选保存完整 `sha/tree/base_sha`，其中 `base_sha` 必须对应当前登记的 `scope.baseline.commit`；`gate_policy_commit` 绑定实际解析的完整规则提交。工作区修改矩阵不能改变已登记策略，也不能在同一次候选放行请求里换基线豁免检查。

`npm run coordination:update -- run-gate --input <请求.json>` 每次执行策略中的一项现有命令。请求只含 `gate` 与新的 `artifacts/local/` 输出路径 `output`；命令由策略提供。固定候选源码需干净，允许控制面/版本事件未提交；有状态门通过 `candidate.gate_inputs.snapshot` 传入现有脱敏快照，实际运行 default 与 v0516-combined 两种 profile，不用门的 self-test 代替真实启动。

执行器记录候选、规则版本、命令、实际 Node/平台/进程环境摘要、输入文件完整摘要、时间、退出码/信号及日志摘要。环境变量原文不落盘；`gate_environment` 只作声明的补充上下文，不冒充测量。将返回的路径/完整摘要登记到 `candidate.gate_receipts[门ID]`，环境摘要登记到 `gate_environment_sha256`，结果登记到 `quality_gate`。运行本身不自动修改控制面或授予放行权限；失败记录与日志保留，重跑使用新路径。

冻结、READY、handoff 及 completed 收口均核对策略清单、未关闭阻断、实际回执及日志；恢复带放行声明的旧版本时也重新核对；旧回执不足仍允许恢复现场，但撤销放行标记并增加待重验阻断，不把旧READY直接恢复为当前许可。缺项、NOT_RUN/PARTIAL/FAIL、短候选身份、输入/环境/日志不匹配均拒绝。原有历史事件仍可审计，不将旧自报 PASS 追溯改写成新的执行证明。回执摘要和生产者字段不是身份认证；文件可写者能伪造内容的权限问题仍由协调者和独立审查负责，不宣称工具证明全部业务正确或抵抗恶意本机写者。

## 各方边界

| 使用方 | 可以维护 | 禁止维护 |
| --- | --- | --- |
| 需求管理 | 原话、来源、问题、验收、反馈证据及未冻结建议 | 冻结范围、开发／发布／运行状态 |
| 开发与审查者 | 设计、实现、自查、验证与审查回执 | 全局队列、当前状态或另一份控制面 |
| 发布执行者／monitor | 指定动作外部回执、运行观测、告警 | 擅自改变候选、授权、当前状态或重放旧 heartbeat |
| README／地图／聊天 | 引用当前来源、revision及读取时间 | 自写完成结论、未读取却冒充实时状态 |
| 报告／事件／收口快照 | 绑定对象与时间的历史证据及限制 | 充当当前门禁、工作基线或覆盖当前决定 |

需求池状态只能从控制面单向投影，标注修订与同步时间；滞后如实显示，不反向覆盖。原始用户数据、附件与凭据不进入正式事件或 Git。

## 收口与提交

归档前由协调者逐项核对需求与范围决定、任务交接、候选变化、关键验收、发布动作是否有对应事件和证据。缺失先补录；无法证实保留未知、失败或 `partial`，不得补写通过。未执行的动作记未执行或不适用，不虚构发布。

收口请求提供上述五类核对的事件引用、证据、结论及未确认原因。完成或取消事件先落盘，再保存完整收口控制面和结果到 `terminal.json`，最后清空不再活动的范围、任务和候选。收口快照不得覆盖，纠错用追加事件追溯。

**唯一控制面文件必须进入 Git 并随相关提交保存。禁止仅因控制面、事件日志、交接中间信息或进度描述变化创建独立提交；不得夹带无意义代码或文档修改凑提交。** 事件与状态及时落盘，随相关代码、有效规则变更或正式版本收口保存；一起保存引用的正式事件，保证提交可独立追溯。正式版本收口是有长期价值的独立动作，可以集中提交 `events.jsonl`、`terminal.json` 和清理后的当前控制面。

材料是否进入 Git 取决于长期维护、正式验收、恢复或审计价值，不按扩展名或 reports 目录判定。有效规则、唯一控制面、正式关键事件和收口结果允许跟随相关提交；临时交接、轮询输出、重复摘要和采集中间材料不入 Git。正式事件和归档不得被 `.gitignore` 排除；原始快照、凭据与编译产物仍不入 Git。

## 格式迁移与验收

既有六位哈希及稳定ID差量以首条 `event_format=3` 事件为历史生效节点；兼容旧全量事件及 `event_format=2` 位置差量，旧事件、提交和归档保持原样，不追溯。新写入使用 `event_format=4` 保存完整 SHA-256，旧格式3保持六位兼容；格式4之后不允许降级写入。项目迁移通过 `control_path_migrated` 决定事件把当前状态的 `canonical_path` 改为根目录相对路径；旧事件及收口快照中的原绝对位置属于带哈希历史事实，不改写。历史格式3按原规范化过程读取并应用稳定ID差量，明确其六位核对能力有限；新格式直接保留完整哈希并应用稳定ID差量。生成、恢复、去重、跨版本引用与审计按各自格式契约处理，不把历史兼容的截断过程用于新记录。历史错误通过追加纠正事件处理，不为精简重写历史，不因记录方式调整删除分支、文件或恢复成果。恢复检查点须有具体恢复用途，不能把逐事件全量复制改名为检查点。

入口、恢复、去重、跨版本引用和审计一起调整；不得只删除 `state_after` 后留下失效消费者。沿用现有维护和验证入口，验收确认新记录保存完整对象身份且执行完整比较、同前缀不同完整值不会误判一致、普通事件按稳定ID差量且不复制整份状态、旧记录可读并在其已知限制内恢复、不产生纯过程提交。

## 能力声明
