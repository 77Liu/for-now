# 唯一协调控制面协议

版本：1.0；生效日期：2026-10-11。本文只定义运行事实的归属与读写协议，不另定义开发阶段、测试门或授权额度。

## 唯一入口与维护者

项目唯一运行控制面固定为共同仓库根目录的 `reports/requirement-coordination-current.json`，不使用各工作树中的同名副本。共同目录由 Git common-dir 定位，实际路径由协调者确认。JSON 是当前状态唯一正文，Markdown、README、需求池、候选报告和聊天均不是第二个状态源。

只有 Owner 指定的当前协调者可修改控制面。当前角色约定是主控负责协调、主开发负责开发执行；主开发或 subagent 不因名称或持有文件权限自动获得协调权。更换协调者须在控制面记录交接双方及修订号，旧维护者停止写入；Owner 的停止、撤权及范围变更由协调者立即落实。

任何运行脚本、监控或开发者只能产出证据/结果回执，由协调者核对后更新状态；自动运行的协调者仍是同一个逻辑写者。本协议是工作权限约定，不宣称现有文件 ACL、锁或发布工具已经实现了技术强制。

## 保存什么

一个控制面可以包含多轮迭代，但每个迭代、任务、候选和环境有稳定 ID，彼此通过 ID 关联。只保存决策和索引，不复制日志、私密正文或全部测试输出。

| 字段组 | 最小内容 |
| --- | --- |
| 身份与修订 | 项目、协调者、revision、更新时间、规则基线引用 |
| 工作模式 | 运行/暂停/待核验，以及适用范围；暂停立即阻止新的派发和变更动作 |
| 范围与任务 | 需求引用、已选范围、非目标、任务 ID、负责人、允许写集、依赖、基线与工作位置 |
| 当前状态 | 当前阶段、结论、原因、下一动作、责任人、解除条件；具体阶段语义引用生命周期规则 |
| 候选 | 候选 ID、分支、完整 commit/tree、制品摘要、依赖/配置标识；候选变化创建新修订 |
| 验证 | 验证计划引用、证据引用、审查结论、partial/未执行项与风险处置 |
| 授权 | Owner 决定的策略 ID/修订、风险等级、覆盖的动作/环境/数据/预算/有效范围、撤销或暂停状态；不存凭据 |
| 发布尝试 | attempt ID、候选 ID、目标环境、操作及外部回执、未决动作、恢复点 |
| 运行与观察 | 实际观测 SHA/制品、观测时间、部署结果、观察结论；未知和陈旧读数明确标注 |
| 历史与证据 | 修订事件的原因和证据链接；事实变更保留旧值，不篡改历史失败 |

控制面没有初始化、缺字段或证据矛盾时，相关状态为未知，不能用旧报告自动补成通过。协调者先对照 Git、现有任务和现场证据恢复受影响事实；其他已知、已授权工作可以继续。规则协议落地不代表已完成历史状态迁移或运行控制面的初始化。

## 各方读写边界

| 使用方 | 可以维护 | 禁止维护 |
| --- | --- | --- |
| 需求管理/需求池 | 原话、来源、问题、验收标准、反馈证据、未冻结建议 | 自行决定当前冻结版本、开发完成、可发布、已上线或运行状态 |
| 开发 Agent | 设计、实现、任务执行笔记、实际提交和验证回执 | 推进全局任务/迭代/候选/发布状态；另养实施队列 |
| 审查/测试者 | 绑定对象的发现、实际结果和结论建议 | 自行将候选签成最终可发布或已发布 |
| 发布执行者 | 指定 attempt 的外部回执、实际运行观测、恢复证据 | 自行写控制面或把调用成功当成全链完成 |
| monitor | 定时唤醒、差异观测和告警证据 | 把旧 heartbeat 的版本/状态当作新指令；暂停后启动任务 |
| README/状态地图 | 指向控制面和规则的稳定链接 | 手写当前版本、进度或完成结论 |
| 候选/发布报告 | 当时的 SHA、动作、结果、风险和时间快照；引用控制面 ID/revision | 持续维护另一份“当前状态”或覆盖后续控制面决定 |
| 聊天/看板 | 读取后展示并注明控制面 ID/revision/读取时间 | 自行计算或回写权威状态；没有新读取时冒充实时状态 |

需求池如必须展示状态，只允许协调者或其受控投影动作从控制面单向发布，标注来源修订与同步时间，并禁止其他角色手工修改投影字段。投影滞后时显示滞后，不反向覆盖控制面。用户产品验收反馈先作为原始证据提交，协调者据此推进验收状态。

## 更新和交接

1. 读取当前 revision、工作模式和相关对象，检查当前任务的授权。
2. 收集事实回执；每条回执绑定任务/候选/attempt、完整对象身份、环境、时间、结果、证据和未覆盖项。
3. 协调者核对证据及转换前提，只更新涉及字段；修订号变化时重读，禁止覆盖并发的新决定。
4. 保存前后 revision 与变更原因。操作实际已发生但回写失败时先恢复回执，不重新执行外部副作用。
5. 交接引用控制面路径、revision、对象 ID 和证据路径；不用聊天抄一份队列。执行者接受任务前读取这些引用，过期任务由协调者重排。

测试输出和生产现场是观测证据；控制面维护的是经过核对的当前决策。若两者冲突，暂停受影响的推进并核验，不能因为控制面写了成功而忽略真实故障。
