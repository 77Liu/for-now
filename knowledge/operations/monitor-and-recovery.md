# 监控、备份与恢复

返回[运维地图](../operations-capacity.md)。运行服务、timer、脚本和参数以 [deploy](../../deploy/) 中的实际候选及生产有效配置为准；权限遵循[授权策略](../release-authorization-policy.md)。

## 监控与告警

核对主应用及中台的进程、readyz、运行版本、磁盘、备份时效、AI 连续失败与费用。数据库读取失败必须报告未知/失败，不能回退成零费用或健康。

状态变化、持续异常及恢复通过配置的通知通道发送；费用区分已知、未知、预留和最终结算，不把“调度完成”当“摘要生成成功”。严重告警日志白名单及资源峰值采样边界的唯一正文见[日志审计](../observability.md#告警)。

飞书配置用 `FEISHU_ALERT_WEBHOOK` 和适用的 `FEISHU_ALERT_SECRET`，不在命令输出或日志泄露。配置核对、发送测试与接收端真实送达分别记录。测试发送是外部消息动作，必须在已有授权范围内；不能为核验主动制造未授权生产故障。

## 备份与恢复

按实际后端选择一致性备份方式。PostgreSQL 导出/恢复见[数据库协议](../postgres-migration.md)；归档、完整性校验、OSS 上传及成功标记分别核验，不能仅凭本地文件存在宣布远端备份成功。

恢复使用独立目录/数据库和隔离应用，核对账户、记录、状态/引用、附件字节及实际 HTTP 读取；新库恢复和旧 JSON 兼容读取是不同证据。校验文件按工具协议使用完整摘要，不截断校验算法。

恢复完成或失败都关闭本次进程、临时会话并清理本次测试资源；失败保留原备份与诊断，不改活动数据或清理别人的资源。既有备份保留期及 OSS 生命周期按生效配置核对，不能据旧文档推定仍有效。

发布回滚不能直接把已接收新写入的数据库切回过期 JSON。代码回退、数据前滚和恢复到新库分别评估兼容性；具体触发和结果遵循[发布 SOP](../../SOP/release-and-observation.md)。
