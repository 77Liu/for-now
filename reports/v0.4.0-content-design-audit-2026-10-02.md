## 2. 自动扫描基线

以下数字是用于定位风险的源码信号，不等同于缺陷数量：

| 信号 | `main@fa88f04` |
| --- | ---: |
| 注册视图 | 24 |
| 静态 `status` 节点 | 41 |
| runtime `empty(...)` 调用 | 24 |
| runtime `error.message` / `err.message` 引用 | 153 |
| 错误 toast 调用 | 65 |

结论：

1. 状态文字主要散落在单体 runtime，不能用一次全局替换证明完成。
2. 直接显示 `error.message` 的位置同时包含字段校验、对象错误、网络错误和管理员
   诊断，必须按对象逐项分类。
3. “我的”同时承载普通用户、Owner 和研发诊断内容；仅改措辞无法满足信息隔离。
4. 空状态此前只有单行字符串入口，难以稳定表达“现状、正常性、一个下一步”。

## 3. 统一词表

### 3.1 状态

| 状态 | 首层表达 | 必须说明 |
| --- | --- | --- |
| 编辑中 | 草稿已保存在本机 | 尚未完成服务端持久化 |
| 已保存 | 原文已保存 | 保存位置明确 |
| 同步中 | 已保存在本机，正在同步 | 可以离开或继续 |
| 处理中 | 原音已保存，正在转写 | 原始内容可访问 |
| 已完成 | 转写已完成 | 结果与来源可查看 |
| 需要处理 | 两端内容有差异，请选择保留版本 | 双方内容不丢失 |
| 失败 | 转写暂时失败。原音已保留，可以再次尝试。 | 失败步骤、安全内容、恢复动作 |

### 3.2 来源

| 推荐词 | 使用条件 | 禁止替代 |
| --- | --- | --- |
| 原文 | 用户文字与派生内容并列时 | 每张纯用户卡片固定贴“用户原文” |
| 录音 / 原音 | 音频对象或播放位置 | 语音原件 |
| 转写原文 | 录音转成的文字 | ASR 结果 |
| 图片识别 | 图片派生文字 | OCR 返回 |
| AI 整理 | 对原始内容的可编辑整理 | 自动真相、用户观点 |
| AI 应答 | 模型回答 | 用户结论 |
| 已确认 / 已修正 | 用户治理后的 claim | 系统已学习 |

### 3.3 首层禁用词

正常路径不直接显示 `API`、`ASR`、`OCR`、`Worker`、`Token`、幂等、供应商名、
模型档位、测试环境、实现限制和研发证明。确有价值时进入管理员页面、高级设置、
诊断详情或帮助文档。

## 7. 理解性验收脚本

P2/P3 真实招募仍暂缓，本轮先使用现有自动化与 Owner 人工验收，不伪造用户研究。

| 任务 | 提问 | 通过标准 |
| --- | --- | --- |
| 空账户进入念起 | “现在能做什么？” | 5 秒内指出唯一动作，知道文字/图片/录音任一即可 |
| 转写失败 | “什么丢了？下一步是什么？” | 明确原音仍在，只重试转写 |
| 寻迹读取失败 | “旧记录是否变化？” | 回答没有变化，并找到重新查找 |
| 同步冲突 | “系统会覆盖哪一版？” | 回答两版都保留，需要自己选择 |
| 个人概要为空 | “系统是否认为你没有这些特征？” | 回答未知，不是负面结论 |
| 管理页面隔离 | “哪里配置供应商和预算？” | 普通用户找不到；Owner 在受控入口找到 |

人工验收记录必须包含设备、视口、任务完成时间、误解点和原话，不只记录
“看起来清楚”。
