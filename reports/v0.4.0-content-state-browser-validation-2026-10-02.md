## 1. 目的与边界

本轮先在未提交候选上补充黑盒证据；首批实现进入 `8c7b52f` 后，Owner 实测发现
寻迹动作、原生显隐和移动触控缺口，最终以 `cf2946b` 修复并复验：

- 320×700、390×844、768×1024 和 1440×900 Web 状态；
- 反馈、导出、个人概要和通知的读取失败与重试；
- `role=alert`、toast、横向溢出和内部错误可见性；
- Tab 焦点顺序；
- 寻迹空态聚焦、分页显隐和通用 `[hidden]` 契约；
- 移动页头触控尺寸。

本轮不验证：

- 服务端 4xx/5xx 的每个错误 code；
- 08D-B 的 142 处动态 message；
- VoiceOver、200% 缩放、iOS 软键盘和物理设备；
- Owner capability、旧 URL 和页面职责；
- 生产账户、真实供应商、费用或部署。

网络失败使用浏览器请求拦截直接中止指定 GET。它能验证断网/请求失败的页面行为，
不能代替带结构化 `code/status/requestId` 的服务端错误矩阵。内部 sentinel
泄漏继续由既有自动化覆盖。

## 4. 状态内容与可访问性

### 4.1 反馈

失败：

```text
暂时无法读取反馈记录
已经提交的内容没有被删除。请检查网络后重试。
重新读取
```

恢复：

```text
还没有提交记录
问题或建议提交后会留在这里，方便继续核对。
写一条反馈
```

### 4.2 导出

失败：

```text
暂时无法读取导出范围
账户中的原始数据没有变化。请检查网络后重试。
重新读取
```

恢复后清单显示 3 个资源、0 个附件、0 个附件引用和 0 个待核对引用。失败状态
没有暗示导出操作修改了账户数据。

### 4.3 个人概要

失败：

```text
暂时无法核对个人概要
原始记录没有被修改。请检查网络后重试。
重新核对
```

恢复后显示“记录还不足以形成概要”和“还没有可用来源”。这两个状态都指向记录
入口，形成重复动作，记录为后续信息层级问题。

### 4.4 通知

失败：

```text
暂时无法读取通知
后台任务和已有结果没有被删除。请检查网络后重试。
重新读取
```

桌面与移动均满足：

- 状态容器为 `role=alert`；
- toast 为空；
- 页面不显示被中止请求的底层异常；
- 重试成功后 alert 消失；
- 恢复态不残留失败文字。

## 9. 判定

在本轮覆盖范围内，08D-A 的结构化读取失败满足：

- 说明当前对象和失败；
- 说明已有数据没有被删除或修改；
- 提供一个恢复动作；
- 使用持续页面状态而非 toast；
- 重试成功后清除失败；
- 四个 Web 视口无横向溢出；
- 无底层错误和控制台异常。

本轮不改变以下事实：

1. 08D-A 已以 `cf2946b` 修复初评缺口，但只完成首批范围。
2. G1 缺全视口/真机/辅助功能固定证据。
3. G2 页面职责和 capability 未冻结。
4. G4 全站权限、冲突、多账户和媒体中断路径未闭合。
5. 08D-B 动态错误与推理可见性尚未实现。

因此结论是“测试范围通过”，不是任务 04、08D、V0.4.0 或发布通过。

## 10. 真实 HTTP 复评反证

同日后续评审在 `http://127.0.0.1:4175/` 使用真实浏览器控件、真实本地 HTTP
状态数据和网络中止/恢复再次执行。完整记录见
[`v0.4.0-owner-review-2026-10-02.md`](v0.4.0-owner-review-2026-10-02.md)
的“真实 HTTP 复评追加”。

新增反证：

1. 寻迹无结果状态的“调整查找条件”引用不存在的 `discovery-query`，点击后焦点
   仍停在按钮；
2. `#discovery-more` 虽为 `hidden=true`，仍被 `.discovery-more{display:block}`
   显示，在无结果状态形成第二个无效动作；
3. 同类 `hidden` 样式冲突还影响治理中台入口和反馈上下文字段；
4. 普通思绪 DOM 实际包含 32 个内部推理块；普通“我的”仍可访问 Owner 信息。

处理标记：

- 寻迹动作和共享 `hidden` 契约：**接受修改**；
- 普通 DOM 推理：**接受修改**，归入 08D-B 严重阻断；
- Owner capability：**初步**，归入 G2/08D-C 严重阻断；
- 触控尺寸和个人概要重复动作：**优化**，按既有后续切片保留。

原报告关于失败文案、恢复、四视口无溢出和键盘无陷阱的证据继续有效，但在复评时
不再足以关闭 08D-A。当时结论改为“接受修改，修复后复验”。
