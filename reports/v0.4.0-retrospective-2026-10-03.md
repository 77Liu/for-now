## 3. 实际过程

### 3.1 开发与集成

1. 先建立迭代 SOP、任务边界和工作树隔离，再按首页、音频、小物、冷启动、
   用户模型、权限、路由和预算拆分提交。
2. 每个切片先做专项和 Journey Smoke，共享契约变化后运行前后端或
   PostgreSQL 系统门。
3. Owner 在发布前补齐预算、角色、缓存保留和真机时段决策；这些变化导致
   预算、路由、权限和持久化线在候选前串行集成。
4. 真机实测确认功能可用，但冷启动为 `4.437s`，未达到 `<3s`。Owner 接受
   延期到 V0.5.0，不将该项标记为通过。

### 3.2 候选与发布

1. 第一轮 Release 门在 `d9e7189` 全绿，总计 `210722 ms`；生产即时备份、
   AI 预算单例、最小权限角色和候选只读预检完成。
2. 第二轮独立审计在自动门全绿后仍发现 4 项 Major：离线五问覆盖远端更新、
   PWA 预缓存闭包缺失、并发转写预算复用、恢复演练漏验全站预算。
3. Owner 授权修复全部问题后直接发布。`9e258b4` 完成 4 项 Major 和 iOS
   指标缺失修复，独立 Release 门总计 `205984 ms`。
4. 发布整合提交 `8cb4d93` 再次从 detached 干净工作树验证，总计
   `204921 ms`，生产依赖漏洞为 0。
5. 部署前后两次即时备份均上传 OSS 并通过隔离恢复；生产按后端、新 API、
   网页、原生兼容顺序上线。
6. DeepSeek、火山语音/视觉、阿里分割与私有 OSS 合成冒烟 5/5 通过。
7. 2026-10-03 02:16:11–02:56:16 CST 完成 40 分钟观察，服务继续运行。

## 7. 复盘

### 7.1 保留

| 现象与证据 | 结论 | 后续做法 |
| --- | --- | --- |
| 第二轮在自动门全绿后仍发现 4 项 Major | 独立审计有效覆盖测试盲区 | 候选冻结后继续保留独立代码审计和最小复现 |
| 生产按后端先行验证后再检查网页/原生 | 避免客户端与旧 API 版本错配 | 把版本契约检查固定在每次发布顺序中 |
| 恢复门最终校验预算文件和导出哈希 | 新持久对象被纳入恢复边界 | 每次新增根级状态时同步扩展导出、恢复和清单 |
| 根脏现场与新集成工作树隔离 | 未覆盖用户未提交内容 | 新版本继续从已核对主线创建独立工作树 |

### 7.2 改变

| 现象 | 原因 | V0.5.0 行动与验收 |
| --- | --- | --- |
| 首屏 0.5 秒仍白屏、真机 4.437 秒 | 完整运行时、全量 DOM、水合和次级请求阻塞首屏 | P00：0.5 秒内有可见反馈，网页已登录首屏 P95 `<1s`，真机分段可解释 |
| AI 候选重入可再次付费并产生重复 claims | 幂等键绑定请求而非来源输入 | P00：按来源 revision/input hash 原子复用任务，模型调用与 claims 各一次 |
| 基础写入虽快，但等待反馈可超过 1 秒 | 用户反馈依赖完整刷新或后台结果 | P00：立即呈现本地提交态，服务确认 `<0.5s` 有明确反馈 |
| 追问成功后草稿和编辑态残留 | DOM 双副本和表单快照未按成功结果消费 | P0：成功后清空并关闭，失败保留，切页不复活 |
| 文本朗读 POST 200 但无稳定播放器 source | 使用脱离 DOM 的临时 Audio，自动播放受用户激活限制 | P0：绑定可见播放器，自动播放失败仍可手动继续 |
| RSS 观察期阶梯增长 | 缺 heap/external/handle 分段，根因未确认 | P00：先补低敏运行时采样，再做同规格长稳复现 |
| 备份成功标记早于服务 ready | 脚本只执行 `systemctl start` | P0：成功标记前有界等待 `/readyz`，失败恢复且不写成功标记 |
| Base 在发布后仍保留 V0.4 待开始状态 | 发布关闭未与需求池同步 | 每版观察结束后，同一关闭任务回写需求、交付和原计划 |
