## 4. 逐日开发过程

### 4.1 2026-10-05：规划、范围冻结与六条 P00

1. 归档个性化回答/感知设计、性能分析、私有媒体分发设计和 R9.4-F1 开屏
   资产；这些文档用于划清 V0.5.8 与后续版本边界。
2. V0.5.7 G7 于 14:45 左右获 Owner 验收；`309847b` 记录 V0.5.8
   开发放行。
3. 依次完成思绪路由、唯一内容层级、首页快捷语音和费用治理。每个产品切片
   都有专项、Journey Smoke 和独立复核，没有等到总集成才补用户路径。
4. 同步开屏经历 controller、HTML/runtime 集成、真实 paint 预算和失败锁存
   多轮收紧。曾发现双 `requestAnimationFrame` 仍可能早于真实 FCP，最终改为
   以 Paint Timing 和 `app.js` Resource Timing 约束。
5. `6730597` 冻结入口契约：入口不能通过 barrel、动态扫描或不可达 factory
   制造表面瘦身；同时固定三类入口策略、owned routes、迁移例外和页面
   lifecycle。

### 4.2 2026-10-05 至 10-06：服务端 B1-B7

服务端按依赖串行迁移：

```text
Store schema/normalization
-> 派生统计与公开投影
-> 账户和本地测试生命周期
-> AI runtime
-> 媒体 runtime
-> 内容 workflow
-> HTTP 编排
-> server runtime / lifecycle
```

结果：

- `server.mjs` 从 3,283 行降为 4 行；
- Store、账户恢复、本地测试、AI 预算/供应商、媒体、内容和 HTTP 都有
  显式应用模块或端口；
- `createServerRuntime` 和 `createHttpApplication` 成为组合边界；
- 每批先由叶子模块专项验证，再由集成负责人单写入口并运行影响门；
- PostgreSQL 16.14 在隔离签名 Node 下完成真实稳定门。

### 4.3 2026-10-05 至 10-07：浏览器 F1-F10

浏览器按页面耦合度迁移：

```text
application / router / ports
-> discovery / export / feedback
-> actions
-> notifications / annotations / background results
-> checkins / health
-> thoughts / shared audio / image drafts
-> captures / journals
-> library / quotes / review / statistics / keepsakes
-> basic / account / owner / trash
-> runtime composition
```

关键做法：

- `runtime.mjs`、`bootstrap.mjs`、registry、barrel、runner、Service Worker
  和 module boundaries 始终由集成负责人单写；
- 独立开发者交付 feature/controller 叶子，集成后删除旧入口实现，不保留
  长期双轨；
- 每个 feature 都定义 mount/unmount/reset、账户代际、迟到结果和失败恢复；
- 服务工作线程缓存闭包随模块迁移更新，避免在线成功、离线缺模块；
- F7-F9 的干净叶子工作树经 patch 等价核对后移除，分支 ref 保留。

最终：

- `runtime.mjs` 从 5,291 行降为 53 行；
- 25 个页面全部使用显式 descriptor/controller；
- API、DOM、event、timer、template、lines 六类 G6 例外全部归零；
- 108 个 active modules、237 条 owned routes。

### 4.4 2026-10-06：完整需求原子重排

## 5. 多 Agent 调度与协作

调度记录没有把“开了多少 Agent”作为完成证据，而是记录角色、基线、写集、
依赖、消息和关闭条件。主要角色包括：

| 角色组 | 责任 |
| --- | --- |
| `orchestrator` | 唯一 DAG、共享入口单写、串行集成、候选和发布状态 |
| backend workers/scouts | B1-B7 的 Store、账户、AI、媒体、内容和 HTTP 叶子 |
| frontend workers/scouts | F1-F9 的 feature/controller 叶子与边界侦察 |
| validators | PostgreSQL、生命周期、同步、PWA、性能和候选身份复核 |
| reviewers | 固定差分的 blocker/P0/P1 审查，不修改候选 |
| secretary/auditor | 角色知识账、资源、ready 未派发原因和治理回流 |

有效协作模式：

- 共享热点只有一个 writer；
- 叶子模块并行，入口接线串行；
- 变更、测试、review、资源释放后重算 DAG；
- Reviewer finding 必须进入修复和回归，不能只写在聊天里；
- 已集成且干净的工作树及时回收，分支 ref 保留可追溯性。
