## 问题与修复

- v0.2.0 以 JSON 写源部署后，新版备份成功生成包含附件清单的完整归档。
  恢复演练确认账户、附件、集合数量和小物 ID 均一致，但在小物内容摘要处
  停止。
- 根因是恢复验证器对备份中的私有小物对象计算摘要，而 `/api/state` 按
  设计通过 `publicKeepsake` 隐藏 `originalPath` 并补齐兼容派生字段；两侧
  不是同一公开投影视图，因此内容哈希必然不同。
- 修复后，验证器仅在生成 API 期望摘要时对小物应用同一公开投影；原始备份
  和附件清单仍按完整私有数据逐文件校验。失败诊断只输出集合名、数量和
  SHA-256，不输出正文、路径内容或凭据。

### Bug 修复

#### 小物恢复摘要误报｜Bug 修复

**Bug 描述：** 完整备份中的小物数量、ID 和附件均一致时，恢复演练仍会在
API 内容摘要检查处误报失败。

**原因：** 验证器直接比较包含私有原图路径的备份对象与隐藏该路径、补齐
兼容字段的公开 API 对象，两个视图的哈希口径不一致。

**解决方案：** API 期望摘要改用与线上接口相同的 `publicKeepsake` 投影，
同时继续对原始备份和附件实物执行完整校验，并在失败时输出无正文的集合级
差异证据。
