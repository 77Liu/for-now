## Bug 修复

### 恢复校验误报与漏验

**Bug 描述：** 上一生产 Store 中的捕念私有语音缓存和旧转写默认字段会导致
公开 API 摘要误报；关系导出清单中的 Store 与账户文档哈希又未被实际核对。

**原因：** 恢复脚本混用了持久层内部对象与公开响应对象，并且只校验关系导出
哈希的格式，没有读取恢复后的文件做内容比对。

**解决方案：** 复用候选捕念公开投影，按当前转写字段规范化后比较 API；同时
验证每个账户的 `store.json`、设置、用量和费用方案文档哈希，并加入私有字段、
旧默认字段、文件篡改、非字符串账户 ID 和缺失集合的负向回归。

## 架构调整

- 首页与思绪 R8 样式从已超预算的全站阻塞 CSS 中拆为单独资源；浏览器预加载，
  启动入口在显示页面前等待，1.5 秒后可降级到基础样式，避免样式请求阻塞启动。
- 山水与竹影保留 PNG 回退，并提供带内容 SHA 前缀的 AVIF/WebP；派生格式单文件
  不超过 32 KiB，由 Service Worker 延迟缓存。
- 首页内容继续使用既有 memory pool；新增对已舍弃子记录的过滤。
- 思绪列表和详情只增加前端派生关系，不写入新的 `currentId` 或来源字段。

## 功能、UX 与 UI 优化

### 首页默认单屏

此前手机端只显示两类回看内容，短屏下行动入口可能落到首屏外；本次将第一条
主内容与两条辅内容排成稳定网格，小物和情绪按高度断点压缩，六个目标视口均
保留完整入口。

### 全页山水环境

此前背景只属于首页局部图层；本次使用同一横竖山水环境覆盖应用底层，首页、
思绪列表和详情分别使用 0.68、0.35、0.24 的内容浓度，竹影只出现在桌面边缘。

### 思绪列表

此前列表会把最新回答直接当预览，AI 回答可能获得接近用户结论的视觉权重；
本次优先显示最新有效用户回答为“我的结论”，其次显示最初想法，AI 回答不进入
该预览。列表增加月份分组、单条身份预览和清楚的打开入口。

### 思绪详情

此前详情复用展开卡片，问题、内容身份与操作层级分散；本次使用单一问题标题，
内容按发生时间正序，想法、经历、我的结论和 AI 应答通过图形、名称与材料共同
区分。手机端补充、追问与回答入口固定在主导航上方，编辑时自动让位。
