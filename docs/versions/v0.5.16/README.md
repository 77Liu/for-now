1. 先核对最新实现、复现和方案待决参数，冻结认证、账户隔离、队列终结及阅读状态共享契约；不凭旧优先级断言当前线上根因。
2. 服务可靠性切片统一处理 F1/F2/F5，交付记录 `reczz28NmYM0vJSR`；关注坏账户清理与预算账本之间的边界。
3. 同步窄读切片只做 F3 阶段 A，交付记录 `reczz28NmYM0rrKt`；不能把大规模数据库演进作为其他七项前置。
4. 阅读与批注切片统一处理 F4 和三项追加需求，交付记录 `reczz28NmYM0s39S`；复用原批注、选区和分页入口，不建立三套局部状态。
5. 每片先自查完整生产者—持久化—消费者契约，主控独立审查后按影响验证并合入 `develop`；最后执行有状态全局发布门。

## 验收与范围上限

- 认证与恢复：错误登录压力下健康账户仍可认证和读写；故障账户的拦截、清理、重试与恢复可区分。
- 同步窄读：相同切片下结果与原消费者契约一致；无变化同步不重建完整业务数据，变化域和回执读取有行数/耗时对比，保留原写入语义。
- 队列：未发送即取消/到期不调用供应商、不重复扣费；已发送的结果归属和恢复不被未调用路径误清理。
- 阅读批注：完整历史可达，计数真实、折叠和阅读位置保留；验证跨页、重绘、失败、账户切换及移动选区。模拟器与真机证据分别记录。
- 全局门：固定候选构建后，使用脱敏生产切片与隔离 PostgreSQL 完成启动、readyz、重启恢复和核心读写；按[测试影响矩阵](../../../knowledge/test-impact-matrix.md)选择其余必要验证。
- 本版不扩展富媒体编辑器重写、全站 Markdown 改造、联网搜索、录音新生命周期、多实例或全量存储重构。预计收益通过实测给出，不编造工期和性能改善比例。

本轮资产整理及范围选择不包含业务实施、push、tag、Release、部署或付费调用。已发布技术修复与用户验收分开；历史未定位的普通思绪空答、账号停机根因和真实设备性能缺口未因去重或新版本规划而关闭。
