## 实施切片与顺序

唯一顺序为：`AI 原子行审计 → 新 F1 → F2 → F5 → 新 F3 → 新 F4 → F7 → F6 → F8 → AI 推理可见性 → 新 F9`。任何时刻最多一个需求处于实现、验证或返修状态；当前项完成独立测试、共享组件契约、受影响回归、开发回填和主控出口审查后，下一项才可开始。

八类共用组件、每项唯一前驱、进入条件、交付物和出口门见[版本级方案 3.2.2](../../technical-proposals/V0516-跨需求共用底座与串行开发-技术方案.md#322-有效需求复用组件与唯一串行位置)。实施时必须重新确认最新 `develop`、需求事实源与控制面；本页不承诺日期，不允许按不同文件或端别解释为可并行开发。

## 验收与范围上限

- AI 审计与可见性：审计 begin 失败时供应商调用为零；每次尝试、usage 与终态可核对；产品只读取领域业务结果，不读取私有审计，未知 scene 和历史记录默认隐藏。
- 认证与恢复：错误登录压力下健康账户仍可认证和读写；精准查询不全表扫描；故障账户的拦截、清理、重试与恢复可区分。
- 记录级数据：普通局部命令不全账户读取或覆盖写；业务结果、幂等回执和 ChangeSet 原子提交；数据库分页和 rebase 均有界。
- 队列：未发送即取消/到期不调用供应商、不重复扣费；已发送的结果归属和恢复不被未调用路径误清理。
- 阅读批注：完整历史可达，计数真实、折叠、阅读位置、焦点和选区保留；验证跨页、重绘、失败、账户切换及移动选区。模拟器与真机证据分别记录。
- 记录级同步：所有启用实体 producer coverage 完整；断线按 cursor 补发，失效时只按当前 scope rebase；不得用整账户快照兜底。
- 全局门：固定候选构建后，使用脱敏生产切片与隔离 PostgreSQL 完成启动、readyz、重启恢复和核心读写；按[测试影响矩阵](../../../knowledge/test-impact-matrix.md)选择其余必要验证。
- 本版不扩展富媒体编辑器重写、全站 Markdown 改造、联网搜索、录音新生命周期、多实例或无边界全量存储重构。预计收益通过实测给出，不编造工期和性能改善比例。

资产整理及重基线本身不构成开发或发布授权；六条新规需求当前 Base 状态和计划版本关联保持不变，只有 Owner 明确决定后才更新。已发布技术修复与用户验收分开；当前 F9 P75 未达标、首页夹具待调查和真实设备性能缺口未因方案重写而关闭。
