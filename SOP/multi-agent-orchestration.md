# 多 Agent 调度 SOP

本 SOP 用于把一个已获准执行的工程任务拆给调度者、思考秘书、侦察员、
并行开发者、验证者和 reviewer，在不放宽工程门禁、文件所有权、授权边界和
事实记录要求的前提下缩短交付时间。

本 SOP 不替代迭代计划、工程规则、系统测试或发布流程。范围和优先级以
`README-TODO.md` 与当前迭代计划为准；工程、测试和发布约束分别以
`knowledge/engineering-rules.md`、`knowledge/system-testing.md` 和
`knowledge/pre-launch-confirmation.md` 为准。

## 1. 适用与禁用

适用于：

- 存在至少两个互不重叠、可独立产出证据的任务。
- 大任务需要并行完成代码、测试、审查、文档或事实侦察。
- 共享入口或公共契约必须由单一集成者串行接入，但叶子模块可以并行准备。

不应启动并行：

- 任务少于三个明确操作，单人可直接完成。
- 多个任务必须同时修改同一共享文件、schema、公共契约或依赖锁。
- 范围、验收或授权尚未冻结。
- 当前门禁处活跃工作树已经达到 6 个，且没有可安全退出的已结束工作树。

## 2. 角色

| 角色 | 职责 | 默认写权限 |
| --- | --- | --- |
| 调度者 | 冻结目标、建立任务图、分配所有权、串行集成、决定门禁和最终状态 | 集成树与共享文件 |
| 思考秘书 | 维护角色知识账、依赖、决策、通信摘要、NO-GO 和下一步 | 调度记录；默认只读 |
| 侦察员 | 回答具体代码问题，定位契约、消费者、风险和测试入口 | 只读 |
| 并行开发者 | 在指定文件或模块内实现单一切片并运行最窄验证 | 明确所有权范围 |
| 验证者 | 运行独立测试、复现失败、检查环境与证据有效性 | 测试产物；默认只读代码 |
| Reviewer | 从冻结差分审查正确性、回归、安全和缺失测试，按严重度给出结论 | 只读 |

同一 Agent 可以在不同时间承担不同角色，但同一交付不能由同一上下文同时作为
唯一开发者和唯一 reviewer。调度者不能把 Agent 的完成声明直接当作集成结论。

## 3. 角色知识账

每个活动角色必须在本轮调度记录中维护以下字段：

| 字段 | 内容 |
| --- | --- |
| `roleId` | 稳定、可引用的角色标识 |
| `specialty` | 该角色本轮专精的问题或模块 |
| `activeContext` | 基线 SHA、任务目标、验收条件和已知反例 |
| `ownership` | 允许修改的文件、目录、端口、数据目录或数据库 |
| `dependencies` | 输入依赖、等待对象和输出消费者 |
| `communications` | 关键发现、决策、移交、冲突和接收方 |
| `evidence` | 修改文件、命令、结果、失败样本和剩余风险 |
| `status` | `queued / active / blocked / review / integrated / closed` |
| `next` | 唯一下一动作或关闭理由 |

知识账写入 `reports/multi-agent-coordination-<scope>-<date>.md`。短时消息可先在
Agent 通信中传递，但改变范围、契约、所有权、风险或验收结论的内容必须回写
调度记录，不能只留在聊天上下文。

## 4. Step 0：保护现场与工作树门

开始调度前执行：

```bash
git status --short --branch
git worktree list --porcelain
git log -10 --oneline --decorate
```

逐个工作树登记分支、HEAD、脏文件、进程、未合入提交、价值和处置：

- 未完善或无法判断归属：保留现场，计入活跃数。
- 已结束且仍有长期追溯价值：先形成可恢复归档分支，再移除工作树。
- 已结束且提交已集成、无额外价值：确认干净后移除工作树。
- 不得强制删除脏工作树，不得用 reset 或 checkout 覆盖用户改动。

每个计划、集成、候选和发布门禁处，`git worktree list` 中的活跃工作树总数
必须不超过 6 个。超过 6 个时：

1. 停止创建新工作树和派发新的写任务。
2. 先关闭已结束任务，按“归档或删除”规则处理。
3. 无法降到 6 个以内时记录 NO-GO，并由 Owner 决定保留优先级。

Reviewer 在确认改动可合并后，负责提醒或触发“串行合入 -> 合入后测试 ->
工作树处置”的闭环；不得在未合入前删除实现现场。

## 5. Step 1：冻结任务图

调度者把目标拆成有向任务图，每个节点必须包含：

- 单一目标和明确非目标。
- 输入基线与前置节点。
- 文件或模块所有权。
- 成功、失败和恢复验收。
- 最窄测试、影响测试和需要升级的里程碑测试。
- 输出消费者和串行接入顺序。
- 外部服务、费用、生产、隐私和发布授权边界。

只有没有写集冲突、没有隐含共享状态且能独立验证的节点才并行。公共契约、
schema、模块登记、根入口、全局样式、依赖锁和发布文件默认由调度者单写。

## 6. Step 2：分配 Agent 与资源

每个派发消息必须写明：

1. 角色和任务。
2. 工作目录与基线。
3. 唯一文件/模块所有权。
4. 禁止修改项。
5. 必须读取的事实来源。
6. 必须运行的验证。
7. 是否允许写代码或只能研究。
8. 是否允许提交；默认不允许 push、tag、Release、部署或生产写入。
9. 交付格式：变更、证据、风险、下一交接。

优先复用仍掌握相关上下文的 Agent。相同问题已有活动 Agent 时不得重复派发。
任务结束、被替代或长期等待时及时关闭 Agent，避免旧上下文继续产生冲突结论。

并行写任务默认使用独立 branch/worktree/端口/数据目录。仅在同一切片、文件
所有权完全不重叠、调度者保持单写集成且不会分别提交时，才允许共享集成树；
一旦出现共享文件需求，立即暂停支线并交还调度者串行修改。

## 7. Step 3：通信协议

跨角色通信只传递可执行事实，最小格式为：

```text
[发送方 -> 接收方] [任务] [状态]
事实/证据：
决定或请求：
涉及文件：
测试结果：
阻塞与风险：
下一交接：
```

必须主动通信的情况：

- 发现现有实现与冻结契约冲突。
- 需要修改所有权外文件。
- 测试证明其他支线的假设失效。
- 新增安全、数据完整性、费用或发布风险。
- 任务无法独立完成，或已有 Agent 在做同一工作。

调度者处理冲突时，以用户最新要求、可复核代码/测试事实和单一事实来源为准，
不按 Agent 数量表决。

## 8. Step 4：开发、验证与审查

开发者：

1. 先建立失败断言或复现证据。
2. 只修改所有权范围。
3. 运行最窄专项并记录实际命令。
4. 报告未覆盖边界，不自行扩大授权。

验证者：

1. 从冻结 SHA 或固定差分独立运行。
2. 同时保留失败与通过样本，不用后续通过覆盖历史失败。
3. 环境失败与产品失败分开记录。

Reviewer：

1. 先列 blocker、P0、P1，再列低优先级建议。
2. 检查行为、回归、错误恢复、资源清理和测试是否会假绿。
3. 给出文件与行号。
4. 未运行测试时明确说明，不能签成“已验证”。

有 blocker/P0/P1 时返回开发环；修复后必须由独立 reviewer 复核受影响差分。

## 9. Step 5：串行集成

调度者按依赖顺序逐项接入：

1. 核对支线 diff、所有权和基线漂移。
2. 处理共享文件，不让支线各自演化公共契约。
3. 合入一个任务后立即运行其影响测试。
4. 更新角色知识账、提交和证据。
5. 再接入下一个任务。

若多个 Agent 共享同一集成树，只能由调度者暂存和提交；提交前逐文件确认没有
混入其他任务或用户改动。

## 10. Step 6：门禁与收口

每个切片进入下一阶段前检查：

- [ ] 任务图、所有权和依赖与实际一致。
- [ ] 活跃工作树不超过 6 个。
- [ ] 已结束工作树已决定归档或删除；未完善现场已登记保留。
- [ ] 所有 Agent 的状态、知识、通信和下一交接已更新。
- [ ] 没有重复运行的同类 Agent 或无人接收的完成结果。
- [ ] 开发者专项、影响测试和独立审查均有证据。
- [ ] blocker/P0/P1 已关闭或明确 NO-GO。
- [ ] 状态文档未把本地完成写成 Preview、发布或生产完成。
- [ ] 未越过 push、tag、Release、部署、费用和生产写入授权。

收口顺序：

```text
冻结差分
-> 独立审查
-> 修复并复审
-> 影响测试
-> 串行提交/合入
-> 合入后测试
-> 更新需求、交付与调度记录
-> 归档或删除已结束工作树
-> 关闭 Agent
```

完整系统、候选和发布门仍按项目分层测试与发布 SOP 执行，不能用并行 Agent
数量替代测试深度或 Owner 授权。

## 11. 异常处理

| 情况 | 处理 |
| --- | --- |
| 两个 Agent 修改同一文件 | 立即暂停后到任务；调度者确定唯一 owner 并串行重放 |
| Agent 结果与代码事实冲突 | 保留结果，重新读取固定差分或运行最小验证 |
| Agent 长时间无产出 | 获取状态；有明确进展则等待，否则关闭并重新切小任务 |
| 测试环境抖动 | 保存失败样本，区分环境/产品原因，独立重跑但不覆盖失败 |
| 公共契约需要变化 | 暂停所有消费者，调度者串行修订、测试并重新冻结 |
| 工作树达到 6 个 | 不再新建；先集成、归档或删除已结束工作树 |
| 需要外部授权 | 停在本地可验证边界，记录具体授权对象和恢复入口 |

## 12. 最小调度记录模板

```text
# <范围> 多 Agent 调度记录

基线 / 当前 HEAD / 工作树数量 / 授权边界

## 任务图
节点、依赖、所有权、验收、接入顺序

## 角色知识账
roleId、specialty、activeContext、ownership、dependencies、
communications、evidence、status、next

## 决策与通信
时间、发送方、接收方、事实、决定、影响

## 验证与审查
命令、结果、失败样本、review findings、关闭提交

## NO-GO 与下一步
未关闭风险、外部授权、唯一下一动作
```
