# UI 实施与验收

归属：[UI/UX SOP](../ui-ux-optimization.md)。只在原切片交接和回执内保存必要证据，不另建设计状态表。

## 交接

按影响提供需求与设计依据、页面／组件映射、文案、状态与恢复、响应式／动效／辅助功能、API 与数据来源、验收操作及非目标。已有有效规格直接引用，不重复制作。

UI 重构不得暗改原文、时间、来源、版本或权限语义；加载与交互状态见[设计契约](../../knowledge/design-contracts.md)。旧组件迁移明确消费者和删除条件，不保留永久平行实现。

依赖共享 token／组件时先串行完成公共契约，再按完整用户路径交付；不要同时改完所有页面后才验证。

## 实施审查与偏差

先核对实现、真实调用方及批准规格，检查是否误用组件、复制样式、缺失状态或破坏历史行为，再按[HTTP 评审](../http-browser-review.md)操作确认。

偏差区分实现错误、设计遗漏和实际技术限制。实现问题回原切片修复；需改契约时更新唯一设计来源、受影响页面和基线，再做必要复验。不能以进度为由接受核心路径失败。

共享组件／token 变化核对全部消费者，更新对应样例及视觉基线；局部文案变化不无依据重跑全站测试。

## 验收与交付

适用证据包含正常／空／长内容／加载／成功／失败状态，菜单、键盘、大字体、减少动态，以及手机、平板、桌面。截图同时核对 DOM、真实业务结果及刷新恢复，像素接近不代表行为正确。

未测的 iOS、真机、读屏或某状态明确保留未验，不把桌面仿真等同真机。部分验收按[授权策略](../../knowledge/release-authorization-policy.md#partial-的授权边界)及当前限制判定影响，不一律豁免或阻断整版。

交付最小字段：需求／设计引用、实现候选、环境与身份、操作结果、证据、偏差、限制及后续责任。当前结论由协调者更新控制面；范围改变进入既有事件，新需求回需求池，不悄悄加入视觉稿。
