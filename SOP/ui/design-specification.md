# UI 任务与设计规格

归属：[UI/UX SOP](../ui-ux-optimization.md)。本页维护设计方法；产品命名、文化和数据语义仍由各自正文维护。

## 任务与信息架构

每个页面明确“用户来到这里为了什么”，列默认内容、按需内容、不应展示内容及主要操作。任务描述包含入口、操作、业务结果和失败恢复，不只列点击动作。

导航一级表示稳定场景、二级表示类型／任务、对象详情承接局部操作，不以第四层常驻标签解决职责混乱。移动与桌面使用相同概念；深链、返回和刷新遵循[URL 契约](../../knowledge/url-history-contract-v0.4.0.md)。

普通用户、高级用户、Owner／管理员及开发能力分开；管理、密钥、供应商和调试能力不能只靠 CSS 隐藏。旧页面只提供事实，不是必须照抄的设计。

## 内容与状态

文案逐项判断职责：位置、任务、操作、状态、边界或来源；无职责的重复标题、标语和开发证明式说明删除或后移。来源可能混淆时区分用户原文与 AI 派生，不每条机械加标签。

错误说明发生了什么、数据是否安全和下一步；不能只写失败、直接暴露内部异常、用供应商名代替用户结果或同时呈现成功与失败。失败应有持续可见的恢复入口，不仅依赖短暂 toast。

分别定义编辑、本地保存、服务端同步、后台处理和完成；不得用“已保存”代替 AI 成功。必要状态表记录用户看见什么、可以做什么、数据在哪里、下一状态及恢复方式。

覆盖适用的空／超长输入、重复点击、慢网／断网、过期登录、权限拒绝、上传中断、AI 失败、版本冲突、切页、刷新、前后台、关闭重开、多标签及账户切换。失败不丢原始内容，不重复创建对象或费用；原文保存不依赖 AI 完成。

## 层级与组件

先以手机主要视口设计，再核对窄屏、平板和桌面；考虑安全区、键盘、单手触达、长文及返回。灰阶线框应能区分任务、用户内容、元信息、次要操作和状态，不能只靠颜色表达。

对渐进披露明确发现入口、展开／收起、状态保留及键盘／读屏行为。五秒内能否理解页面、主操作、返回和保存状态可作可用性诊断，不充当性能硬门。

先复用语义 token 和组件。新增变体说明职责、槽位、状态、尺寸、键盘、可访问名称、响应式和使用页面；禁止复制组件后各改一套样式。视觉组件不直接调用业务 API。

同类组件在同断点保持一致结构和几何；选中态不改变外框，loading／徽标／错误预留槽位，媒体加载前固定比例。模板共享锚点按批准几何基线检查；内容自然增高与控件无故漂移分别判断。

色彩、字体、留白及容器风格见[设计语言](../../knowledge/design-language.md)。具体像素以当前批准设计和源码 token 为准，不能从旧版本草稿推导新的全局硬限制。

## 原型与冷启动

必要原型覆盖真实长度、段落、媒体比例、长标题、空数据、错误及恢复；占位数据必须保持内容形状，不用等高假数据证明布局。

无提示观察能否开始、完成、确认保存、恢复及返回，记录犹豫、误触和回退。原型不能代替真实页面验收。

冷启动沿当前批准的[冷启动策略](../../knowledge/onboarding-strategy.md)核对题目、跳过／退出、保存、整理和首页入口，不在本 SOP 复制题数或强制过场页。未填写不推断态度；用户填写与模型派生分开，不能把 AI 整理失败变成无出口的阻塞页。
