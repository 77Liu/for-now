# 工作树生命周期

分支和角色见 [协作协议](multi-agent-orchestration.md)。工作树尽量少、存活尽量短；不以 Agent 数分配工作树，也不把固定数量上限作为所有阶段硬门。

## 建立

1. 核对 `git worktree list --porcelain`、活跃任务和所有权；优先复用适用现场。
2. 有明确并行写需求或发布候选隔离需求才建立；先完成任务卡。
3. 功能工作树从明确的 develop commit 切出，不从 feat 继续派生。release/hotfix 按协作协议的发布例外执行。
4. 写任务使用独立分支；端口、测试数据等只在真实占用时隔离。规则从共同根目录读取，任务卡记录规则版本。

## 接入

协调者验收并串行接入；不能只凭分支名称、ahead/behind 或 Git 可自动合并判断业务成果已吸收。按实际差分、契约和验证证据作出接入/暂缓/放弃决定。

## 归档

1. 确认没有运行中的写者，记录分支、HEAD、已接入情况及未提交内容。
2. Codex 支持时使用其工作树归档；归档应保留提交、未推送历史及未跟踪文件。忽略文件中有价值的数据另行保存。
3. 工具因其他聊天所有权不可用时，可做 Git 恢复 ref + 完整本地目录归档，含暂存/未暂存状态；归档放在受保护的非发布目录，核对内容哈希后才移除原 checkout。
4. 原分支和恢复 ref 不随工作树移除而删除。脏现场可以归档，不能未备份就清理；恢复记录说明位置、恢复步骤和未验收成果。
5. 已完成、被替代和长期无任务的工作树归档；不会因成果尚未合入就无限保留活动目录。存档只用于追溯/提取代码，需要续做时从新 develop 开任务并审核搬入差分。

Git 命令行归档不能同步 Codex 旧聊天的附件元数据；旧聊天恢复前先读协调记录，不继续使用失效目录。
