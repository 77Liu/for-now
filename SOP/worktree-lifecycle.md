# 工作树生命周期

分支和角色见 [协作协议](multi-agent-orchestration.md)。工作树尽量少、存活尽量短；不以 Agent 数分配工作树，也不把固定数量上限作为所有阶段硬门。默认写入位置是当前唯一的 `develop` 工作树。

## 硬性默认规则

1. 没有**已确认的并行写入**、发布候选隔离或外部环境隔离时，禁止创建或保留工作树；“以后可能并行”“方便备份”“看起来更安全”都不是理由。单写者直接在唯一 `develop` 工作树完成任务。
2. 一个任务只能有一个活动写入位置。根目录和工作树不得同时修改同一共享文件集；一旦发现重复写入，立即停止第二个写者，由协调者选择唯一负责人并合并/放弃差分。
3. 工作树的隔离理由消失、任务完成、任务取消或候选已接入后，当前任务内立即完成交接、记录证据并归档移除；归档后的分支、恢复 ref 和目录只用于审计/恢复，禁止继续开发。
4. 需要续做时必须从最新 `develop` 新建任务，由协调者审查后选择性搬运归档差分；不得重新打开归档工作树作为开发基线。

## 建立

1. 核对 `git worktree list --porcelain`、活跃任务和所有权；优先复用适用现场。
2. 只有在建立当下已经存在明确并行写入、发布候选隔离或外部环境隔离时才建立；先完成任务卡并登记唯一写集、明确禁写集和共享文件负责人。单写任务不得预先开树等待并行。
3. 功能工作树从明确的 develop commit 切出，不从 feat 继续派生。release/hotfix 按协作协议的发布例外执行。
4. 写任务使用独立分支；端口、测试数据等只在真实占用时隔离。每棵工作树只能修改任务卡列出的写集，禁写集和共享文件不得越界；共享配置、构建入口、部署脚本、`.gitignore`、控制面等文件由协调者指定唯一串行写者。规则从共同根目录读取，任务卡记录规则版本。

## 接入

协调者验收并串行接入；不能只凭分支名称、ahead/behind 或 Git 可自动合并判断业务成果已吸收。按实际差分、契约和验证证据作出接入/暂缓/放弃决定。

## 归档

1. 确认没有运行中的写者，记录分支、HEAD、写集/禁写集、已接入情况及未提交内容。
2. Codex 支持时使用其工作树归档；归档应保留提交、未推送历史及未跟踪文件。忽略文件中有价值的数据另行保存。
3. 工具因其他聊天所有权不可用时，可做 Git 恢复 ref + 完整本地目录归档，含暂存/未暂存状态；归档放在受保护的非发布目录，核对内容哈希后才移除原 checkout。
4. 原分支和恢复 ref 不随工作树移除而删除。脏现场可以归档，不能未备份就清理；恢复记录说明位置、恢复步骤和未验收成果。
5. 已完成、被替代和长期无任务的工作树归档；不会因成果尚未合入就无限保留活动目录。存档只用于追溯/提取代码，需要续做时从新 develop 开任务并审核搬入差分。
6. 归档完成的验收条件是：写者停止、状态/差分/未跟踪文件已记录、提交或补丁及哈希已保存、分支/HEAD/验证/未验收项已登记、原 checkout 已移除。移除 checkout 不要求删除分支或恢复 ref；分支/ref 清理由协调者按明确授权另行裁定，完成或归档不触发自动删除。此条不要求无限期保留活动目录。

7. 合并前必须由主控核对规则基线、实际差分未超出写集，且没有与其他活动任务重叠的共享写入；越界或重叠视为流程失败，先停止写入、拆分/回退差分，再由主控串行合入 `develop`。工作树落后规则或 `develop` 时，不得自行 merge/rebase 解决后继续写，须等待主控裁定。

Git 命令行归档不能同步 Codex 旧聊天的附件元数据；旧聊天恢复前先读协调记录，不继续使用失效目录。
