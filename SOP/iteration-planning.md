# 迭代规划 SOP

修订：2026-10-17，Owner 已批准，接入 develop 后生效。负责把已确认需求变成可执行范围与切片，不维护第二份当前状态。生命周期见[开发生命周期](../knowledge/development-lifecycle.md)。

## 输入与唯一归属

1. 先读[当前控制面](../coordination/current.json)、Owner 当前约束及有关需求事实，再按缺口展开规则和证据；不默认全文读取全部历史。
2. 需求收集、去重和完整快照见[需求收集](requirement-intake.md)。核对分页完整性、采集时间、revision 和陈旧标记，避免只看某个视图遗漏高优问题。
3. 核对上一版实际交付、未解决故障、复盘行动、当前 develop、正式发布回流及未提交内容归属。已完成项需证据，不靠标题或版本号推定。
4. 费用、环境、生产与外部动作只读[授权正文](../knowledge/release-authorization-policy.md)和当前限制；计划不产生新授权。

需求池保存问题和验收事实，技术方案保存契约和依据，当前范围／任务／候选由协调者经[控制面入口](../knowledge/coordination-control-plane.md)维护。其他资产需要显示执行状态时，仅作带 revision 和同步时间的单向投影。

## 选择范围

- 明确一个连贯的主要用户结果、非目标、成功／失败／恢复及兼容验收；需求数与时间窗口服从本轮 Owner 决定，不写成通用固定数量。
- 核对全部已知 P00/P0，优先安排核心使用、数据与权限故障；不纳入时说明理由和去向，涉及改变已承诺范围由 Owner／既有授权裁定。不能因高优数量多就无限扩大版本。
- P1 按价值、依赖与容量选择；其他需求保留事实与后续建议，不删除历史或冒称完成。
- 冻结后新问题先判断是否阻断当前目标；必要插入改变范围时及时登记决定，其余回到需求池。
- `G1` 只表示范围与验收明确，不表示代码、方案或发布已通过。

## 选定基线

每个小版本启动前重新核对最新 develop 和正式发布回流，依[发布 SOP](release-and-observation.md#正式发布回流与下一版起点)锁定本轮基线，不提前用上轮预估节点代替。

分支起点和同功能返修见[Git 分支规则](../knowledge/remote-branch-policy.md)。核对工作区、stash、工作树与差分归属；规划不授权清理、重置或提交他人成果。

## 设计、拆片与排序

- 先沿真实实体、存储、API 和前端消费者审查可行性，再确定方案；遵循[设计契约](../knowledge/design-contracts.md)。
- Epic 表达完整用户能力；切片按状态／资源所有权和可独立验收的纵向结果划分，不机械拆前后端或按文件数拆原子迁移。
- 各切片明确目标、非目标、关联需求、负责人、起点、写集、禁写集、公共契约、依赖、验收及必要验证。具体任务卡复用[协作协议](multi-agent-orchestration.md#任务下达协议)。
- 依赖、并行与排期的制作方法见[切片与排期](planning/slices-and-scheduling.md)。该方法不另设 Agent、工作树上限或强制角色。
- 在现有版本技术方案／任务卡中保存设计，不为每个阶段创建报告；当前任务状态仍只由控制面维护。

## 验证规划与开发就绪

按[测试影响矩阵](../knowledge/test-impact-matrix.md)确定受影响旅程、专项、集成及发布前全局门。命令以 package.json 为准；真实第三方验证见[对应入口](../knowledge/third-party-live-testing.md)。

`G2` 开发就绪需确认：切片契约可执行、关键依赖有依据、共享所有权清晰、资源与授权覆盖、验收能判断结果。未决项只阻塞其实际依赖；不能把计划写完当作就绪。

审查重点：重复能力、循环依赖、并行写冲突、全量访问或隐式共享状态、无证据的 ETA、测试／恢复遗漏，以及暂未解决的问题是否被藏进“后续优化”。

## 维护与返回

| 新事实 | 处理位置 |
| --- | --- |
| 验收或范围改变 | 回到范围选择，协调者记录决定 |
| 共享契约／写集冲突 | 回到设计与排序，暂停相关写者 |
| 普通实现问题 | 原 feat 切片修复，不重新制作整套计划 |
| 某项授权或资源不可用 | 保留局部阻碍，选择其他已获准且无依赖的任务 |
| 当前版本正式发布 | 按发布 SOP 回流 develop，再确定下一版起点 |

设计依赖图只表示依赖和规划，不手工复制运行状态；若展示进度，从控制面生成。普通补充说明合并表达，有意义决定及时落盘。记录与提交见[控制面协议](../knowledge/coordination-control-plane.md)，不为过程变化独立 commit。

交付说明本轮目标、范围、切片契约、真实依赖、验证与剩余决策即可；通过后交给[功能开发](feature-development.md)，结束后按[复盘](iteration-retrospective.md)回流。
