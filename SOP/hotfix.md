# 生产异常与热修 SOP

- SOP 编号：`SOP-OPS-001`
- 版本：`1.0`
- 状态：生效
- 对应流程：生产异常旁路
- 退出路径：重新观察并进入 `G6`，随后完成 `G7`

热修只用于恢复服务、数据正确性、安全或关键用户路径。紧急程度可以压缩范围，
不能取消生产授权、最低验证、观察和事后补回归。主流程定义以
[`knowledge/development-lifecycle.md`](../knowledge/development-lifecycle.md)
为准。

## 1. 触发条件

命中任一项时启动：

- 核心用户路径不可用或持续错误；
- 数据丢失、错写、跨账户访问或不可解释变化；
- 认证、权限、隐私或安全边界失效；
- 外部依赖、队列、费用或资源失控；
- 部署后关键指标明显劣化；
- 发布观察触发已定义的停止或回滚阈值。

普通体验优化、非紧急重构和与事故无关的缺陷进入需求池，不混入热修。

## 2. 角色与纪律

| 角色 | 责任 |
| --- | --- |
| 事件负责人 | 统一判断影响、优先级、止损和状态 |
| 修复负责人 | 复现、最小修复、测试和交付证据 |
| 发布负责人 | 备份、回滚、部署、冒烟和观察 |
| Owner | 风险接受、生产操作和最终继续/回滚决定 |

事故期间保持单一指挥和时间线。未经事件负责人确认，不得由多条支线同时修改
生产候选或共享契约。

## 3. 标准流程

```text
H0 发现与分级
→ H1 控制影响
→ H2 最小修复
→ H3 针对性验证
→ H4 发布与重新观察
→ 补回归、复盘和规则回流
```

### H0：发现、保护证据与分级

立即记录：

```text
发现时间与来源：
生产运行 SHA / 标签：
受影响用户、账户、数据和功能：
症状、错误率和开始时间：
是否仍在扩大：
当前数据写入状态：
可用回滚点：
凭据/隐私处理：
事件负责人：
```

- 保留必要日志、追踪 ID、请求摘要和监控，不输出凭据或私人正文。
- 区分当前事故、历史噪声和观察盲区。
- 无法确认影响时采用保守等级，但明确写“初步”，不伪造结论。

### H1：控制影响

按预案选择最小止损动作：

- 回滚到已验证版本；
- 关闭受影响功能或外部调用；
- 停止写入、队列消费或发布；
- 限流、隔离账户或切换只读；
- 对数据风险先创建一致性备份。

生产写入、回滚、配置和流量切换仍需明确授权。动作后立即验证影响是否停止；
无效则重新评估，不连续叠加未经验证的变更。

### H2：定位并做最小修复

1. 在隔离环境复现，建立最小失败断言。
2. 找到直接根因和影响边界。
3. 只修改恢复所必需的代码、配置或数据步骤。
4. 不混入重构、体验优化或其他需求。
5. 数据修复必须可审计、可预演并有恢复点；代码回滚不自动等于数据恢复。
6. 公共契约变化需通知全部消费者并扩大验证。

### H3：针对性验证

最低覆盖：

- 原故障能在修复前失败、修复后通过；
- 相邻正常路径未被破坏；
- 数据、权限、账户隔离和重复执行安全；
- 回滚/恢复路径仍可执行；
- 构建、启动、健康和关键用户路径；
- 本次缩减或未执行的常规门禁。

时间允许时按正常 `G3/G4` 执行。确需压缩时，在发布记录中逐项列出跳过内容、
风险、补验责任和截止条件，不使用“紧急所以未测”笼统带过。

### H4：发布与重新观察

按 [`release-and-observation.md`](release-and-observation.md) 执行：

- 固定热修 SHA、标签、Release、生产基线和回滚点；
- 取得本次 push、tag、Release、部署和生产写入授权；
- 先验证备份/恢复条件，再部署指定候选；
- 对原故障和关键邻近路径做生产冒烟；
- 重新开始完整观察窗口。

观察仍异常时回到 H0/H1。稳定后才能进入 `G6`。

## 4. 热修关闭

热修稳定后必须：

- [ ] 记录影响窗口、用户/数据范围和最终运行版本；
- [ ] 确认止损、修复、部署与观察结果；
- [ ] 补齐被压缩的系统、旅程、恢复或安全测试；
- [ ] 增加能复现事故的自动回归；
- [ ] 将修复并回正常主线，避免只留在临时分支；
- [ ] 检查临时开关、限流、只读和诊断配置已处理；
- [ ] 回写需求池、发布记录和当前状态；
- [ ] 按 [`iteration-retrospective.md`](iteration-retrospective.md) 完成事实记录；
- [ ] 对可复发错误更新 `one-mistake-one-rule.md` 或自动门禁。

补验尚未完成时可以恢复服务，但热修状态必须写“运行稳定，待补验”，不能宣告
迭代已关闭。

```markdown

- 发现与影响：
- 运行版本与时间线：

- 止损动作与结果：
- 根因：

- 针对性验证：
- 未执行门禁与补验：
- 发布授权与生产动作：
- 观察指标与结论：
- 回归、复盘和规则回流：
```

## 6. 禁止事项

- 在没有影响判断时直接改生产；
- 把重启服务当作根因修复；
- 删除日志、错误分支或失败测试来获得“通过”；
- 热修中加入无关功能与重构；
- 复用模糊历史授权执行生产动作；
- 服务恢复后跳过回归、观察和复盘。
