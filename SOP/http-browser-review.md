# 真实 HTTP 浏览器交互评审 SOP

- SOP 编号：`SOP-UIUX-002`
- 版本：`1.1`
- 状态：生效
- 适用项目：此刻
- 适用范围：本地预览、测试环境、候选环境和生产候选的浏览器交互评审
- 上游流程：`SOP/ui-ux-optimization.md` 的 S9/G9
- 可支撑门禁：`G3`、`G4`、`G5`、`G6`

生命周期、状态和证据契约以
[`knowledge/development-lifecycle.md`](../knowledge/development-lifecycle.md)
为准。本 SOP 是门禁证据的一部分，不能单独授权发布。

## 1. 目的

本 SOP 用于在真实 HTTP 页面上复核实现，而不是只根据源码、自动化测试、设计稿
或静态截图给出结论。它重点发现以下问题：

- 页面能打开，但按钮没有产生预期结果；
- `hidden`、disabled、loading 等 DOM 状态与实际视觉状态不一致；
- 自动化断言通过，但用户仍看见重复、无效或越权入口；
- 错误文案没有泄漏内部信息，但缺少数据安全边界或恢复动作；
- 桌面正常，移动触控、键盘、缩放或读屏不成立；
- 模拟身份、缓存页面或请求拦截被误报为真实登录和完整端到端验证；
- 初步评审已经通过，但固定提交的真实操作出现反证。

本 SOP 不替代单元测试、系统测试、Journey 测试、真机验收或发布门。浏览器评审
发现反证时，旧的“通过”结论必须重新打开，不能因代码已提交而忽略。

## 2. 两组独立标记

每个发现同时记录“处理标记”和“评审结论”。两者不得混用。

### 2.1 处理标记

| 标记 | 含义 | 使用条件 | 后续动作 |
| --- | --- | --- | --- |
| **初步** | 已观察到现象，但证据或归属仍不足 | 尚未稳定复现、身份不完整、环境存在模拟、设计边界待 Owner 决定 | 补复现、源码定位和范围判断，不得据此关闭或发布 |
| **接受修改** | 问题已稳定复现并接受进入修改范围 | 当前行为违反已批准契约、验收标准或数据/权限边界 | 建任务、修复、补回归并在同一固定候选上复验 |
| **优化** | 改进方向成立，但不阻断当前已冻结范围 | 不破坏任务完成、数据安全或授权边界，且已有明确归属和退出条件 | 进入后续组件或页面切片，不得只写“以后优化” |

处理标记不是完成状态。“接受修改”不表示已经修复，“优化”也不表示可以永久
忽略。

### 2.2 评审结论

| 结论 | 含义 |
| --- | --- |
| **通过** | 当前范围、候选和证据均满足验收，可关闭对应评审项 |
| **修改** | 当前候选存在可定位缺陷，修复并复验后才能关闭 |
| **保留** | 本轮不修改，但已有明确后续任务、责任边界和启动条件 |
| **严重** | 涉及权限、隐私、数据完整性、不可恢复操作或核心任务失败，阻断相关发布或迁移 |

推荐组合：

- `初步 · 严重`：风险很高，但仍需补齐身份、范围或服务端证据；
- `接受修改 · 修改`：已复现的当前切片缺陷；
- `接受修改 · 严重`：已复现且必须立即阻断；
- `优化 · 保留`：已接受的非阻断改进，进入后续切片。

禁止使用“初步通过”“大致没问题”“先算通过”等不可执行表达。

## 3. 进入条件

开始前必须记录：

1. 目标 URL、完整提交 SHA 和工作树状态；
2. 服务监听进程、启动命令、端口和数据目录；
3. 浏览器引擎、版本、视口、DPR 和颜色模式；
4. 当前身份、角色、账户和认证方式；
5. 数据来源：空账户、合成数据、本地副本、只读线上快照或生产账户；
6. 允许的读写范围、费用和外部服务 NO-GO；
7. 本轮要验证和明确不验证的页面、状态及用户旅程。

服务启动后先用独立 HTTP 请求确认端口仍在监听。页面已打开但端口已经停止时，
浏览器可能只显示缓存或 Service Worker 内容，不能继续作为真实 HTTP 证据。

## 4. 认证与模拟边界

认证证据分为三层：

| 层级 | 可证明内容 | 不可声称 |
| --- | --- | --- |
| 真实登录 | 用户名/密码或既有合法会话完成服务端认证 | 不能自动证明角色授权正确 |
| 测试身份 | 测试服务签发的隔离账户会话 | 不能等同生产账户或线上权限 |
| 浏览器模拟身份 | 仅在浏览器中拦截 `/api/auth/me` 等请求 | 不能称为真实登录、完整端到端或受保护媒体通过 |

使用浏览器模拟身份时必须：

- 只用于验证页面、真实本地 HTTP 数据和交互行为；
- 在报告中列出被拦截的端点；
- 单列未覆盖的登录、会话、附件和服务端 capability；
- 不把模拟身份产生的 401、附件失败归因为产品缺陷；
- 不读取、记录或输出用户密码、Cookie、Session Token。

需要线上只读快照但没有有效登录会话时，停止线上拉取。可以复用已经存在的本地
快照，但必须标明快照时间、记录数和缺失范围。

## 5. 标准流程

### 5.1 固定基线

记录：

```text
URL:
HEAD:
实现提交:
数据目录:
数据模式:
身份层级:
浏览器:
视口:
明确不验证:
```

测试期间若 `HEAD` 或静态资源发生变化，旧页面必须完整刷新；若行为代码变化，
当前评审证据失效并重新开始。

### 5.2 首次进入与导航

验证：

- 首屏是否进入预期页面；
- 一级与组内导航是否同时标识当前位置；
- 页面切换后 URL、history 和返回行为是否符合契约；
- 刷新是否恢复当前页面、筛选、对象和滚动；
- 无权限或无效入口是否进入安全页面；
- 隐藏入口是否真的不在视觉、Tab 顺序和无障碍树中。

页面切换后 URL 和 `history.length` 都不变时，只能记录为内存路由，不能声称深链
或浏览器返回已实现。

### 5.3 核心任务

每条旅程至少操作一次真实控件：

```text
进入页面 → 输入或选择 → 提交/切换 → 看见业务结果
→ 刷新或重新进入 → 结果仍成立
```

只读取 DOM、直接调用内部函数或修改状态变量不能替代用户操作。为避免真实费用、
生产写入或不可逆修改，可以在提交前停止，但必须把未验证步骤列为缺口。

### 5.4 空、加载、失败与恢复

对每个目标页面分别验证：

- `loading` 与原数据是否可区分；
- `empty` 是否说明现状、正常性和一个下一步；
- `failure` 是否说明发生了什么、什么仍安全、下一步；
- 失败是否使用持续页面状态，而不是只用 toast；
- 重试成功后失败状态、toast 和旧错误是否清除；
- 按钮是否真正执行动作，不只存在文字；
- 页面整体是否只有一个主要承诺。

错误注入优先使用浏览器中止 GET 或隔离服务返回稳定错误码。不得在生产触发真实
故障。恢复测试必须解除拦截后点击页面提供的重试动作，不能直接刷新代替。

### 5.5 DOM 与视觉状态一致性

对当前可见页面执行：

- `[hidden]` 元素计算样式必须为 `display:none`；
- disabled 控件不得响应；
- 空态动作引用的 `id`、view 或 command 必须存在；
- 隐藏元素不得进入 Tab 顺序或无障碍树；
- 没有下一页时，“继续加载”不得可见；
- 未勾选的可选字段不得显示；
- 权限隐藏不能只依赖 CSS。

发现多个页面的 `hidden=true` 元素仍可见时，应归因为共享样式契约问题，优先修复
通用规则并执行跨页面回归，不逐页增加补丁。

### 5.6 内容、推理与权限边界

普通用户页面必须检查：

- 是否出现供应商、Token、模型档位、API 密钥或内部错误码；
- 是否渲染完整模型 reasoning、思考链或诊断数据；
- “用户原文”等来源标签是否只在可能混淆时出现；
- Owner/管理员入口是否由服务端 capability 控制；
- 直接 URL、刷新和账户切换能否绕过入口隐藏；
- 无权限响应是否清理旧页面中的敏感内容。

只隐藏导航入口不构成权限隔离。普通 DOM 中存在推理内容，即使默认折叠，也视为
可见，因为复制、查找、读屏和脚本仍可访问。

### 5.7 响应式与触控

最少覆盖：

| 视口 | 重点 |
| --- | --- |
| 320×700 | 最窄布局、长文换行、底部导航 |
| 390×844 | 手机主路径、触控、键盘 |
| 768×1024 | 导航形态切换、内容宽度 |
| 1440×900 | 桌面层级、长列表与空白比例 |

每个视口记录：

- `scrollWidth - clientWidth`；
- 关键容器宽高；
- 主操作是否完整可见；
- 触控目标是否至少 44×44px；
- 标题、状态、按钮和底栏是否遮挡；
- 动态内容是否引发布局跳动。

### 5.8 键盘与可访问性

至少验证：

- Tab、Shift+Tab、Enter、Space 和 Escape；
- 焦点顺序与关闭后的焦点恢复；
- `role=alert`、`role=status` 和 `aria-live`；
- 可访问名称与视觉文字一致；
- 页面没有焦点陷阱；
- 200% 缩放、减少动态和 VoiceOver。

未执行 VoiceOver、200% 缩放或真机时必须标记“初步”，不得写成可访问性通过。

### 5.9 控制台、网络与副作用

记录：

- 控制台 error；
- 4xx/5xx 和被主动中止的请求；
- 写请求数量和目标；
- 重试是否重复创建对象或费用；
- 页面切换是否重复请求；
- 失败后是否残留 busy、disabled 或旧结果。

预期中止请求和身份模拟产生的错误必须与产品自身异常分开。

### 5.10 清理

结束前：

1. 解除全部网络拦截；
2. 恢复临时测试控制文件；
3. 关闭专用浏览器会话；
4. 不关闭用户启动且仍需使用的开发服务；
5. 核对 Git 状态和测试数据目录；
6. 标记 `/tmp` 截图为临时证据；
7. 确认没有生产写入、真实费用或凭据残留。

## 6. 判定与状态迁移

标准迁移：

```text
初步
→ 稳定复现并定位
→ 接受修改 / 优化
→ 形成修复提交
→ 同一固定候选复验
→ 通过
```

以下情况必须把已关闭评审重新打开：

- 真实点击发现主动作无效；
- DOM 与 `hidden`、disabled 或权限状态不一致；
- 普通用户可访问内部推理、密钥、全局成本或管理能力；
- 重试重复对象、重复费用或破坏已有数据；
- 固定提交与评审页面不一致；
- 之前只验证了存在性，没有验证操作结果。

已经合入的提交不必自动回退。若修复范围清楚且没有数据风险，可保留提交，追加小型
修复并复验；文档状态必须从“通过”改为“接受修改，待复验”。
